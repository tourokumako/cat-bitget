## §5-12 ★時間切れの玉を、どう決済するか（🔴 消さない・E38 の最適化のときに読む・2026-08-16 記載）

**この節は、engine_tuner で E38 を回すときに まこさんが決めることの説明です。**前提から順に書きます。読む人が engine_tuner と E38 の中身を知らなくても分かるように書いています。

### （1）前提｜E38 の玉には、持てる時間の上限があります

E38 は、レンジ（横ばい）の相場で、小さく何度も売り買いする戦略です。
1つの玉（建てたポジション）には、**何本の5分足まで持ってよいか**が決めてあります。設定の名前は `tmax_bars` です。

### （2）前提｜上限まで来た玉は「時間切れ」になります

上限の本数まで来ても、利確にも損切りにも届かなかった玉があります。この玉が**時間切れ**です。
**時間切れの玉をどう決済するかのやり方が、実物には2通り書いてあります**（`e38_logic_parts.py` の 350-355行）。

| | やり方 | 手数料 | どのくらい待つか | 売買記録に出る決済の理由 |
|---|---|---|---|---|
| **A** | **その場で成行で決済する** | **0.042%**（成行＝taker） | 待たない | `TIME_EXIT` |
| **B** | **建値から 0.08% 有利な値段に指値を置いて、そこに届くのを待つ。届いたら決済する。届かなければ 24本（＝2時間）後に成行で決済する** | 届けば **0.014%**（指値＝maker）／届かなければ 0.042% | **最大 24本＝2時間** | 届けば `BE_EXIT`／届かなければ `TIME_EXIT` |

> **数字の出どころ（全部 実物）**＝0.08% は `SCALP_FLOOR`（手数料の床・`e38_logic_parts.py:23`）。24本 は `BE_TTL_BARS = 24`（同 :25）。手数料がどちらになるかは `score.py` の `MAKER_EXIT_REASONS`（44行・`BE_EXIT` が入っている）と `TAKER_EXIT_REASONS`（57行・`TIME_EXIT` が入っている）。

### （3）前提｜`be_wait` は、A と B のどちらを使うかの切り替えです

**数字ではありません。**`e38_logic_parts.py` の 297行 が `bool()`（真か偽か）として受け取ります。
**0 なら A ／ 1 なら B** です。

### （4）いまの状態＝A だけです

`e38_logics.json` の `search_space.common_exit.be_wait` が `0 〜 0` なので、**engine_tuner は何回 走らせても B を1回も試しません。**

**★2026-08-16 の A-5-5 で「範囲」の書き方にはしましたが、両端は直す前の一覧（`[0]`）の最小と最大なので、試せる値は1つも増えていません。**書き方が変わっただけです。

### （5）いま A に固定されている理由

`e38_logics.json` の説明文に書いてあります。**B は最大2時間 待ちます。E38 の役割はスキャル（数分で回す）なので、2時間 待つのは役割の枠の外だ**、という理由です。

### （6）B も試させると、何が変わるか

- **B が勝つ可能性**＝時間切れの玉の手数料が 0.042% → 0.014% に下がります。E38 は小さく何度も回すので、手数料の差が効きます。
- **B が負ける可能性**＝2時間 待っている間、その玉が予算 0.12 BTC を占め続けます。その間、新しい玉を建てられません。回転数が落ちます。
- **どちらが勝つかは、engine_tuner が両方を走らせて net で決めます。CC が先に決めません。**

### （7）★なぜ CC が勝手に広げないか

いまの固定は、「2時間 待つのはスキャルではない」という**役割の決めごと**から来ています。
CC が広げると、**まこさんが決めた役割の枠を、CC が勝手に緩めたことになります。**

### （8）広げるときの直し方（触るのは1か所だけ）

`scripts/priority_rebuild/e38_logics.json` の `search_space.common_exit.be_wait` の `"hi": 0` を `"hi": 1` に書き換えます。
**ほかに直す所はありません。**実行器も検証器も、0 と 1 の両方を受けます。
