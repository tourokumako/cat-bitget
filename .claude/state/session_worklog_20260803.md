## §5 設計（まこさんの OK 待ち）

**受け渡しの形＝新しい小さなファイル1本（tuner_findings.py）で json の欄を7つに固定する。**

| 欄 | 中身 |
|---|---|
| schema | 形式の版 |
| source | 作った道具の名前・実行した日・読んだ売買記録CSVの名前 |
| **window** | ★窓のタグ。名前と開始日と終了日。必須 |
| **intent** | ★「順番のヒント」か「空間を狭める」かのどちらか。必須 |
| reduce_exit_reasons | 減らしたい決済理由 |
| focus_materials | 注目する指標と時間足 |
| increase_scenes | 増やしたい場面 |

**自由記述の欄は作りません。** 知らない欄が1つでも在れば読み込みで止めます（fail-closed）。

**observe_diag が書く**＝`results/priority_rebuild/ratchet/diag_findings.json`（1本に固定・上書きの前に archive へ逃がす）。`window` は必ず採点窓になり、`intent` は必ず「順番のヒント」になります（この道具は採点窓でしか動かないため、「空間を狭める」を書けない）。

**engine_tuner と engine_tuner_gen が受け取る**＝新しい引数 `--findings <ファイル>`。起動時に窓のタグを見ます。

- 採点窓に重なるタグ ＋「空間を狭める」→ **止める**（歩6 の検収の線）
- 採点窓に重なるタグ ＋「順番のヒント」→ 通す
- 値決め窓のタグ ＋「空間を狭める」→ 通す（L-267 に反しないため）

**効き方は3種類とも違います。** engine_tuner の作りが違うためです。

| 渡すもの | 効き方 | なぜ |
|---|---|---|
| 減らしたい決済理由 | **目的そのものが変わる**（自動で効く） | 目的は引数1つで切り替わる。探す範囲は狭まらない＝全部の値の組は今まで通り試され、順位のつけ方が変わるだけ |
