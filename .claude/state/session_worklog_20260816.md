### 4.3 原因の特定（3段階）

**① 並び順の乱れが原因か**

`PYTHONHASHSEED` を固定して3回 走らせたら3回とも同じ、固定しないで3回 走らせたら3回とも別物でした。
（Python は既定で、走らせるたびに文字列の置き場所を変えます。）

**② どの引き当てから変わるか**

案を作るときの引き当て（`choice`・`integers`・`permutation`）を1つずつ記録し、並び順 0 と 1 で突き合わせました。
**最初の食い違いは 17,224行目**。

```
並び順0:  integers|124|71  →  integers|5|14
並び順1:  integers|124|71  →  integers|7|21
```

**候補124件から71番目を引くところまでは同じで、その次のパラメータの範囲（5〜／7〜）が違う。**
＝**候補の並びが違うので、同じ71番目が別の指標になっていた。**

**③ 並びを作っている場所**

`engine_tuner_gen.load_signal_table`（580行あたり）

```
roles[rname] = {"lineages": set(r["lineages"]), ...}
```

**`set` は中身の並びが決まっていません。**この `lineages` を `_make_cond` が `for k in rr["lineages"]` と上から順に見て、候補の並びを作っていました（671行）。

### 4.4 直したこと（1行）

`set(...)` → `tuple(sorted(...))`。

**ほかの使い方5か所は「入っているかどうか」を見るだけなので、この形でも同じ結果になります**（機械で全部 数えて確認）。
