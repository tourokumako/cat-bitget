## どういう形にするか

**設計書の上部に、2つを置きます。**

1. **要件定義の全文**（固定。正本から、プログラムが写す）。
2. **要件定義と、この工事の照らしの表**（工事ごとに中身が変わる）。

**照らしの表の形**

| 要件（正本から、プログラムが並べる） | この工事は関わるか | 合っているか | 根拠（設計書のどこ・実物のどこ） |
|---|---|---|---|
| 1. 目標（全月 net ≥ $1,900） | … | … | … |
| 2. engine_tuner の目的 | … | … | … |
| 3. 機能要件の6項目（1行ずつ） | … | … | … |
| 4. 探し方（最初は代表の固定値・最後に範囲・値を名前に入れない） | … | … | … |
| 6. 指標の使い方（指標一覧からだけ呼び出す・オン・オフが効く） | … | … | … |
| 7. 教科書と法則の扱い（1か所を直せば、全部に届く） | … | … | … |
| 8. 作ってはいけないもの（2件） | … | … | … |

- 左の列は、プログラムが正本から並べます。要件が増えたら、行も自動で増えます。
- 右の3列は、私が案に書き、まこさんの OK をもらった文を、プログラムが写します。
- 1行でも空なら、プログラムは設計書を作らずに止まります。

- 監査は、表の1行ずつを、設計書と実物で確かめます。
