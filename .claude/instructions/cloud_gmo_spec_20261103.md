# 依頼書｜GMOコインの取引の仕様を調べて1本の文書にする（クラウドのセッション用）

## この作業の目的

トレードBOT の取引所を、Bitget から GMOコインへ替えます（2026-11-03 の決定）。売買を試算するプログラムの費用と約定の前提を、GMOコインの実物に合わせるために、仕様を調べます。

- 銘柄は BTC_JPY です。API で注文できる取引所（レバレッジ取引）を相手にします。
- 暗号資産FX は API の対象外なので、相手にしません。
- 本番への切り替えは BOT の完成後です。この調べは、試算の前提を決めるために行います。

## やること

次の問いに、公式の資料で答えます。

| 番号 | 問い | 分かると何に使うか |
|---|---|---|
| Q1 | 1つの建玉に、利確の指値と損切りの逆指値を同時に置けるか。置けないなら、同じことをする公式の手段（ロスカットレートの指定など）は何か | 損切りを採点でどう数えるか |
| Q2 | closeOrder・closeBulkOrder・changeLosscutPrice の決まり（建玉の指定、部分決済、数量の上限、エラーの条件） | 部分利確と積み増しの扱い |
| Q3 | 逆指値（STOP）の約定の決まり（成行か指値か、手数料、滑り） | 損切りの費用 |
| Q4 | SOK（Post-only）が約定せずに取り消される条件。指値の有効期限の決まり | 指値の約定の前提 |
| Q5 | レバレッジ手数料 0.04%/日の掛かる時刻と計算、ロスカット手数料 0.5% が掛かる条件 | 保有の費用 |
| Q6 | 証拠金の計算、証拠金維持率 75% のロスカットの計算。合計 0.12 BTC を持つときに要る証拠金の式 | 必要な資金 |
| Q7 | メンテナンス（定期・緊急）の曜日と時間、その間の注文と建玉の扱い | 本番の止まる時間 |
| Q8 | デモや試しの環境の有無。API のレート制限（Tier） | 本番の確かめ方 |
| Q9 | 過去の約定データや KLine の取得の上限（Public API の制限、BTC_JPY の取得できる最初の日） | 5分足の取得 |

3. 実際の注文を出しません。API キーを使いません。Public API の読み取りだけにします。
