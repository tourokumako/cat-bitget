# 依頼書｜全指標の教科書を、見本の形で作る・第1回（クラウドのセッション用）

## この作業の目的

engine_tuner は、net を最大にする条件の組み合わせを探すプログラムです。指標・閾値・パラメータ・時間足を、法則に沿って組みます。そのための指標の情報は、`SDK/scripts/priority_rebuild/indicators/indicators.json`（指標データ）に集めます。`SDK` は `v3-bitget-api-sdk/bitget-python-sdk-api` の略です。

いま指標データには、閾値の範囲と、入る合図などの使い方が、ほとんど入っていません。この作業は、指標データへ入れる材料になる教科書を、決まった形でそろえます。

**この作業は、値を決めません。データもプログラムも直しません。** 候補を全部並べます。1つを選ぶのは、後の工事の設計書と監査です。

## 経緯

全指標306種の調べは、前の依頼で済んでいます。ただし、形が指標データと違うので、そのままでは入りません。例えば、値が文字で書いてあり、「書いてない」という語が値の欄に在ります。

そこで、RSI 1種の見本を作り、読み込みのテストを通しました。この作業は、その見本と同じ形で、残りの指標を作ります。

## 最初にプッシュできるかを確かめる

1. `git ls-remote origin research/textbook-format-1` でブランチが在るかを確かめます。
2. 在れば、そのブランチの続きから始めます。結果のファイルに在る指標を飛ばします。
3. 無ければ、ブランチ `refactor/e35-e36-split-strat-base` の最新の版から作り、そのままプッシュします。
4. **プッシュが失敗したら、調べを始めません。** 止まった文を報告して、作業を終えます。

始めた時刻と終えた時刻を `date -u` で測ります。この作業を頼んだ人は、質問に答えられません。確認の質問をせず、最後まで進めます。会話の記録が要約に置き換わったときは、この依頼書の「形の決まり」「守ること」「出す物」を読み直します。

## やること

1種ごとに、次の順で進めます。

1. 材料を読み、在る値を見本の形へ写します。文字で書いてある値は、逐語を読んで数に直します。
2. 全部の要素を照らし、空の要素を挙げます。
3. **空の要素は、Web で探します。必須です。** 時間を理由に省きません。開発者の原典、定番の教育サイト、ライブラリの説明書、短い足やスキャルの資料の順に探します。暗号資産の資料が在れば、それも探します。
4. ページは curl と Chromium の両方で開き、本文に逐語が在ることを照らします。開けないページと、404 と書かれたページは、web.archive.org も見ます。それでも開けないページは、確かめの強さを「未確認」にし、注に HTTP の番号を書きます。
5. 探しても無い要素は、空にして「見つからなかった」と書きます。使った検索の語と開いたページを、`探した記録` に残します。

**とくに必ず探す要素：** 閾値の値（スキャルとデイトレ）、閾値の範囲の文、パラメータの範囲の文、使い方の行（使い方の種類・場面・玉の向き・向き）です。使い方の種類は、7種の全部について探します。場面は、レンジ・上げ・下げ・スパイクの全部について探します。入る合図の文が在る指標は、その合図の弱点を見る「入ってはいけない場面を除く条件」の文も探します（`SDK/.claude/memory/indicator_combination_kb.md` の §3）。期間違いの2本の組（クロスほか）の文は、`合図の形のパラメータ` に、組の相手の名前と両方の期間を書きます（同 §10.2）。時間足は、文に書いてある足だけを書きます。足を探すための検索はしません（足は役目で決まる・同 §4 の4）。

### 検索の決まり（必ず守る）

Web で調べる依頼は、使える手段を全部使って調べ切る。「探していない」を「無い」と書かない（まこさん指示 2026-11-04・逐語「今後こんな手抜き検索しないでほしいんだが。」）。

やること

①候補が無い欄と見つからなかった欄は、WebSearch で探す。依頼書が「探してかまいません」と書いていても探す。

②ページは curl と Chromium の両方で開く。依頼書が WebFetch を挙げていれば、WebFetch でも開く。

③開けないページと、404 と書かれたページは、過去のページの保存（web.archive.org）も見る。

④見つからなかった物には、検索した語・開いたページ・無かったことを書く。探していない物は「探していない」と書き、その件数を報告の先頭に書く。

⑤時間の制限が無いのに、「時間の都合」を探さない理由にしない。

## 形の決まり

鍵の名前と並びは、見本のとおりです。選べる語は次のとおりで、ほかの語を書きません。

| 欄 | 選べる語 |
|---|---|
| 教科書の役割の区分 | 向き・強さ・勢い・行き過ぎ・値動きの幅・出来高・位置。複数の行で持てます |
| 閾値の形 | 値・分位・回数・倍率・前提つき |
| 値の単位 | 値段・%・0〜100・分位・ドル・手数料の床の倍数・ATR の倍数 |
| 使い方の種類 | 場面の判定・入る合図・入ってはいけない場面を除く条件・合図が本物かを確かめる条件・出口の水準を作る材料・出口の反転・前提崩れの印 |
| 場面 | レンジ・上げ・下げ・スパイク |
| 玉の向き | SHORT・LONG・両方 |
| 向き | 上側・下側・上へ抜ける・下へ抜ける |
| 時間足・文の時間足 | 1m・3m・5m・10m・15m・30m・1h・2h・4h・6h・1d |
| 前処理 | 絶対値・過去6か月の中の位置・2本の比・2本の差・決まった数との差 |
| 軸の意味 | 窓・倍率・割合・重み・本数・ずらす本数 |
| 使える条件の形 | level・band・band_exclude・slope・slope_avg・cross・streak・within_n・barssince・diff・touch・candle_dir・hysteresis |
| 確かめの強さ | ページの文で確かめた・ページの語の数だけ・見つからなかった・未確認 |

追加の決まりは次のとおりです。

0. **指標の名前は2つ書きます。** `名前` は指標データの名前のまま（プログラムが読む名前）です。`元の指標` は、英語の正式名と開発者です（例＝RSI（Relative Strength Index・Wilder））。前の調べの `元の指標` の欄と、資料の表の `元の指標` の欄から写します。無い指標は Web で探します。検索には `元の指標` の英語の名前を使います。
1. **値の欄に「書いてない」「持たない」を書きません。** 文が無ければ、`null` か空の並びにします。
2. **値は数で書きます。** 1つの候補の行に1つの値です。「7 to 9」のような文は、値 7 と値 9 の2行にします。
3. **候補を全部並べます。** 1つに選びません。代表の値の候補は、スキャル・デイトレ・既定に分けます。文の中の足と名指しで分け、どちらとも読めなければ `既定` に入れて注に書きます。
4. **範囲を作りません。** 文の値は `挙げた値` に書き、`範囲の形` を「文に両端が在る」「値を挙げただけ」で書きます。「入力できる範囲」「強さの区切り」も、その語で書きます。
5. **逐語は1文字も変えず、文を切らずに全部写します。** 前の調べで途中で切れている文は、ページを開いて全部写します。
6. **選べない足（週足・月足ほか）は、時間足の欄に書きません。** 候補の `文の時間足` を `null` にし、注に原文を書きます。
7. **閾値を持たない指標は、** `閾値の範囲の文` を空にして、`閾値の注` に理由と逐語を書きます。
8. **文の分類は、語の有無でなく意味で読みます。** 「true range」の range はレンジの話ではありません。「short-term」の short はショートの話ではありません。別の線の文（基準線の行に転換線の文ほか）を混ぜません。
9. 計算の式は `計算の式` に、式の文と URL を書きます。無ければ見本のとおりです。
10. 指標データや前の調べと食い違う値は、消さずに候補に並べ、注に書きます。どちらが正しいかは書きません。
11. **使い方の行の `型`（down・flat_up ほかの入口の型）と `時間足` は、文に書いてあるときだけ書きます。** 無ければ `型` は `null`、`時間足` は空の並びにします。足は法則と engine_tuner が決める物なので、推測で埋めません。
12. **線どうしのクロスは、** `合図の形のパラメータ` に `{"名前": "組の相手", "代表の値": "<指標データの名前>"}` を書きます。文に期間の組が在れば、`パラメータの代表の値` に軸ごとに書きます。
13. **向きを持つ指標を絶対値で使う文**（DI差の大きさほか）は、`前処理` に「絶対値」と書きます。
14. **閾値の文が無い指標**（ATR% ほか）は、閾値を空にして「見つからなかった」と書きます。数を作りません。倍率の文（ATR の2倍ほか）は、形「倍率」・単位「ATR の倍数」で書きます。

## 守ること

1. データ・プログラム・文書を直しません。作ってよいのは、下の「出す物」だけです。とくに `.claude/rules/` を直しません。
2. 値を決めません。おすすめを書きません。
3. 書いてないことを、推測で埋めません。検索結果の要約だけで書きません。要約の文しか得られないときは、「未確認」にします。
4. 乱数を使いません。
5. engine_tuner・G2・H2・材料の検査を走らせません。5分足のデータがこの環境に無いので、走らせても止まります。
6. hook に止められたら、回り込まず、止まった文を結果に書いて作業を終えます。
7. 短いスクリプトと途中の出力は、リポジトリの外の一時フォルダに置きます。

## 出す物

ブランチは `research/textbook-format-1` です。置き場は `.claude/state/indicator_review/research/` です。このフォルダは .gitignore の対象なので、コミットのときに `git add -f` を使います。master へは入れません。

**1. `out_t1_01.json`、`out_t1_02.json`、…** は、20種ごとの配列です。1件の形は見本のとおりで、次の2つの鍵を足します。

- `探した記録`：`[{"要素": "", "検索の語": [""], "開いたページ": [{"URL": "", "HTTP": 200, "読んだ日": "", "当たる文": "在る"}]}]`
- `閾値の注`：閾値を持たない指標だけ

**2. `out_t1_summary.md`** は、人が読むまとめです。結論を先に書きます。

1. 探していない物の件数（先頭に書きます）。
2. 相手の数と、作った数。
3. 要素ごとの、値が在る指標の数と、見つからなかった指標の数。
4. 確かめられなかった物と、その理由。
5. 始めた時刻と終えた時刻。

20種ごとにコミットとプッシュをします。コミットの前に、次の2つを確かめます。

```
jq 'length' out_t1_01.json
jq -r '.. | strings | select(. == "書いてない" or . == "持たない")' out_t1_01.json
```

2つ目の出力が1行でも在れば、直してからコミットします。
