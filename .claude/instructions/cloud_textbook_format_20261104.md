# 依頼書｜全指標の教科書を、見本の形で作る・第1回（クラウドのセッション用）

## この作業の目的

engine_tuner は、net を最大にする条件の組み合わせを探すプログラムです。指標・閾値・パラメータ・時間足を、法則に沿って組みます。そのための指標の情報は、`SDK/scripts/priority_rebuild/indicators/indicators.json`（指標データ）に集めます。`SDK` は `v3-bitget-api-sdk/bitget-python-sdk-api` の略です。

いま指標データには、閾値の範囲と、入る合図などの使い方が、ほとんど入っていません。この作業は、指標データへ入れる材料になる教科書を、決まった形でそろえます。

**この作業は、値を決めません。データもプログラムも直しません。** 候補を全部並べます。1つを選ぶのは、後の工事の設計書と監査です。

## 経緯

全指標306種の調べは、前の依頼で済んでいます。ただし、形が指標データと違うので、そのままでは入りません。例えば、値が文字で書いてあり、「書いてない」という語が値の欄に在ります。

そこで、RSI 1種の見本を作り、読み込みのテストを通しました。この作業は、その見本と同じ形で、残りの指標を作ります。

## やること

1種ごとに、次の順で進めます。

1. 材料を読み、在る値を見本の形へ写します。文字で書いてある値は、逐語を読んで数に直します。
2. 全部の要素を照らし、空の要素を挙げます。
3. **空の要素は、Web で探します。必須です。** 時間を理由に省きません。開発者の原典、定番の教育サイト、ライブラリの説明書、短い足やスキャルの資料の順に探します。暗号資産の資料が在れば、それも探します。
4. ページは curl と Chromium の両方で開き、本文に逐語が在ることを照らします。開けないページと、404 と書かれたページは、web.archive.org も見ます。それでも開けないページは、確かめの強さを「未確認」にし、注に HTTP の番号を書きます。
5. 探しても無い要素は、空にして「見つからなかった」と書きます。使った検索の語と開いたページを、`探した記録` に残します。

**とくに必ず探す要素：** パラメータの代表の値（スキャルとデイトレ）、パラメータの範囲の候補、閾値の代表の値（スキャルとデイトレ）、閾値の範囲の候補、使い方の行（使い方の種類・場面・玉の向き・向き）です。代表の値と範囲は、パラメータと閾値の両方について、スキャル・デイトレの文を探します（要件＝最初の段階は戦略ごとの代表の固定値、最後の段階は範囲）。使い方の種類は、7種の全部について探します。場面は、レンジ・上げ・下げ・スパイクの全部について探します。入る合図の文が在る指標は、その合図の弱点を見る「入ってはいけない場面を除く条件」の文も探します（`SDK/.claude/memory/indicator_combination_kb.md` の §3）。期間違いの2本の組（クロスほか）の文は、`合図の形のパラメータ` に、組の相手の名前と両方の期間を書きます（同 §10.2）。時間足は、文に書いてある足だけを書きます。足を探すための検索はしません（足は役目で決まる・同 §4 の4）。

### 検索の決まり（必ず守る）

Web で調べる依頼は、使える手段を全部使って調べ切る。「探していない」を「無い」と書かない（まこさん指示 2026-11-04・逐語「今後こんな手抜き検索しないでほしいんだが。」）。

やること

①候補が無い欄と見つからなかった欄は、WebSearch で探す。依頼書が「探してかまいません」と書いていても探す。

②ページは curl と Chromium の両方で開く。依頼書が WebFetch を挙げていれば、WebFetch でも開く。

③開けないページと、404 と書かれたページは、過去のページの保存（web.archive.org）も見る。

④見つからなかった物には、検索した語・開いたページ・無かったことを書く。探していない物は「探していない」と書き、その件数を報告の先頭に書く。

⑤時間の制限が無いのに、「時間の都合」を探さない理由にしない。

## 形の決まり

鍵の名前と並びは、見本のとおりです。選べる語は、上の自動の表「選べる語」のとおりで、ほかの語を書きません。役割の区分は複数の行で持てます。

追加の決まりは次のとおりです。

0. **指標の名前は2つ書きます。** `名前` は指標データの名前のまま（プログラムが読む名前）です。`照らしと出どころ` の中の `元の指標` は、英語の正式名と開発者です（例＝RSI（Relative Strength Index・Wilder））。前の調べの `元の指標` の欄と、資料の表の `元の指標` の欄から写します。無い指標は Web で探します。検索には `元の指標` の英語の名前を使います。
1. **値の欄に「書いてない」「持たない」を書きません。** 文が無ければ、`null` か空の並びにします。
2. **値は数で書きます。** 1つの候補の行に1つの値です。「7 to 9」のような文は、値 7 と値 9 の2行にします。
3. **候補を全部並べます。** 1つに選びません。代表の値の候補は、スキャル・デイトレ・既定に分けます。文の中の足と名指しで分け、どちらとも読めなければ `既定` に入れて注に書きます。
4. **範囲の候補は、必ず探します。** パラメータの `範囲の候補` と `閾値の範囲の候補` は、スキャル・デイトレの代表の値と並ぶ必須の要素です（要件＝最後の段階で範囲から探す・指標ごとに一つ）。文の値は `挙げた値` に書き、`範囲の形` を「文に両端が在る」「値を挙げただけ」で書きます。「入力できる範囲」「強さの区切り」も、その語で書きます。範囲の数そのものは作りません。取り込みが、候補の全部の値の最小から最大までを、その指標の一つの範囲にします。両端の文が無い指標は、代表の値の候補だけからでも範囲ができます。文が一つも無ければ空にして「見つからなかった」と書きます。
5. **逐語は1文字も変えず、文を切らずに全部写します。** 前の調べで途中で切れている文は、ページを開いて全部写します。
6. **選べない足（週足・月足ほか）は、時間足の欄に書きません。** 候補の `文の時間足` を `null` にし、注に原文を書きます。
7. **閾値を持たない指標は、** `閾値の範囲の候補` を空にして、`閾値を持たない理由` に理由と逐語を書きます。
8. **文の分類は、語の有無でなく意味で読みます。** 「true range」の range はレンジの話ではありません。「short-term」の short はショートの話ではありません。別の線の文（基準線の行に転換線の文ほか）を混ぜません。
9. 計算の式は `照らしと出どころ` の中の `教科書の計算の式` に、式の文と URL を書きます。無ければ見本のとおりです。
10. 指標データや前の調べと食い違う値は、消さずに候補に並べ、注に書きます。どちらが正しいかは書きません。
11. **使い方の行の `場面と型` の中の `型`（down・flat_up ほかの入口の型）と `時間足` は、文に書いてあるときだけ書きます。** 無ければ `型` は `null`、`時間足` は空の並びにします。足の組が文に在れば `時間足の組` に書きます。足は法則と engine_tuner が決める物なので、推測で埋めません。
12. **線どうしのクロスは、** `合図の形のパラメータ` に、名前「組の相手」の行を書き、`代表の値の候補` の `既定` の `候補の値` に指標データの名前を書きます（見本の DI差）。文に期間の組が在れば、`パラメータの代表の値の候補` に軸ごとに書きます。本数や幅の文が在れば、同じ形で名前「持続の本数」「何本以内か」などの行に書きます。数が文に無ければ、候補を空にして `注記` に書きます。
13. **向きを持つ指標を絶対値で使う文**（DI差の大きさほか）は、`前処理` に「絶対値」と書きます。
14. **閾値の文が無い指標**（ATR% ほか）は、閾値を空にして「見つからなかった」と書きます。数を作りません。倍率の文（ATR の2倍ほか）は、形「倍率」・単位「ATR の倍数」で書きます。
15. **使い方の行の `出どころ` の文に数が在れば、その行の閾値に必ず書きます。** 文に足の名指しが無ければ、`既定` に入れて注に書きます。閾値の範囲の候補に書いたから行に書かない、としません。
16. **文に売買の方向が無い行は、`玉の向き` の欄を書きません。** `null` にしません。プログラムは、欄が無ければ「両方」と読みます。文に方向が在るときだけ、選べる語で書きます。
17. **帯（band）の行は、文に在る数を書きます。** 両端が在れば、行を分けて両方書きます。中心の値だけなら、その値だけを書き、注に「中心の値だけが文に在る」と書きます。両端を作りません。
18. **`向き` は、level・slope・slope_avg・diff の行で必ず文から読みます。** 読めなければ `null` にして注に書きます。band・cross・touch ほかの行は、文に無ければ `null` のままです。
19. **クロス（cross）の行は、組の相手か閾値のどちらかを書きます。** 線どうしなら組の相手、水準を抜けるなら閾値です。どちらも文に無ければ空のままにして、注に書きます。
20. **選べる語に無い単位**（CMF の値の幅ほか）は、単位を `null` にして、`値域` の `有界` に文の両端の値を書きます。語を足しません。
21. **部品の記録に置く指標**は、一番上に `置く記録` を書きます（値＝部品の記録）。指標の記録に置く指標には書きません。
22. **閾値の単位に「値段」「ドル」を書きません**（要件 H6＝USD の絶対値の閾値を禁じる）。値段や USD で書かれた閾値の文は、`閾値の範囲の候補` に `単位` を `null` で写し、`注記` に「値段の絶対値の文」と書きます。使い方の行の `閾値` には入れません。`値の単位と値域` の単位には「値段」「ドル」を書けます（値域の説明のため）。
23. **傾き（slope・slope_avg）の行は、** 名前「傾きの本数」（何本前との差か）を `合図の形のパラメータ` に書きます。平均を取る文は、名前「平均の本数」も書きます。文に本数が無ければ候補を空にします（見本の ADX・RSI）。

## 守ること

1. データ・プログラム・文書を直しません。作ってよいのは、下の「出す物」だけです。とくに `.claude/rules/` を直しません。
2. 値を決めません。おすすめを書きません。
3. 書いてないことを、推測で埋めません。検索結果の要約だけで書きません。要約の文しか得られないときは、「未確認」にします。
4. 乱数を使いません。
5. engine_tuner・G2・H2・材料の検査を走らせません。5分足のデータがこの環境に無いので、走らせても止まります。
6. hook に止められたら、回り込まず、止まった文を結果に書いて作業を終えます。
7. 短いスクリプトと途中の出力は、リポジトリの外の一時フォルダに置きます。

## 出す物

ブランチは `research/textbook-format-2` です。置き場は `.claude/state/indicator_review/research/` です。このフォルダは .gitignore の対象なので、コミットのときに `git add -f` を使います。master へは入れません。

**1. `out_t1_01.json`、`out_t1_02.json`、…** は、20種ごとの配列です。1件の形は見本のとおりで、次の2つの鍵を足します。

- `探した記録`：`[{"要素": "", "検索の語": [""], "開いたページ": [{"URL": "", "HTTP": 200, "読んだ日": "", "当たる文": "在る"}]}]`
- `閾値を持たない理由`：閾値を持たない指標だけ

**調べ直しのファイル：** 頼んだ人が指標と要素を指定して調べ直しを頼んだときは、`out_t1_redo_01.json`、… に書きます。鍵は `名前` と、調べ直した要素だけです。テストの口へ元のファイルの後に渡すと、同じ指標の同じ要素だけが差し替わります。定義表に要素が増えたときも、同じ形で足した要素だけを書きます。前のファイルは書き替えません。

**2. `out_t1_summary.md`** は、人が読むまとめです。結論を先に書きます。

1. 探していない物の件数（先頭に書きます）。
2. 相手の数と、作った数。
3. 要素ごとの、値が在る指標の数と、見つからなかった指標の数。
4. 確かめられなかった物と、その理由。
5. 始めた時刻と終えた時刻。

20種ごとにコミットとプッシュをします。コミットの前に、次の2つを確かめます。

```
jq 'length' out_t1_01.json
jq -r '.. | strings | select(. == "書いてない" or . == "持たない")' out_t1_01.json
```

2つ目の出力が在れば、直してからコミットします。

コミットの前に、形のテストも走らせます。最後の行の「合計の違い」が無くなるまで直してから、コミットします。

```
python3 .claude/state/indicator_review/gen_indicators_draft.py --try-textbook-many out_t1_01.json
```

このテストは、「書き写し忘れの疑い」という行も出します。この行は、テストを止めません。意味は次のとおりです。

- 教科書の使い方の一行には、三つの物が入っています。逐語（調べたページから写した英文そのもの）と、閾値の欄（その英文が言っている「この値を超えたら」の値を書く欄）と、合図の形のパラメータの欄（「何本続いたら」「どれだけ上がったら」の本数や幅を書く欄）です。
- 抜けの例＝ADX の見本の一行では、逐語に「ADX が安値から四つ上がるまで待て」と書いてあったのに、二つの欄が両方 空でした。英文は写したのに、その中の値を欄に書き写していない状態です。engine_tuner は英文を読まないので、書き写さない値は使われません。
- テストは、英文の中に数字が在るのに二つの欄が両方 空の行を、「書き写し忘れの疑い」として出します。
- 英文の数字が、全部 値とは限りません。本の頁の番号や、「次の足」の足の番号も数字です。プログラムには見分けられないので、出た行をあなたが読み、値なら欄に書き写し、頁の番号などなら注記に「閾値ではない」と書いてください。

## 終わったときの報告

1. 探していない物の件数（先頭に書きます）。
2. ブランチの名前と、最後のコミットの番号。
3. 作った指標の数と、ファイルの数。
4. 要素ごとの、値が在る数と見つからなかった数。
5. かかった時間。
6. 確かめられなかった物と、その理由。
