# 依頼書｜閾値の範囲とパラメータの範囲を教科書で探す（クラウドのセッション用）

## この作業の目的

engine_tuner は、net を最大にする条件の組み合わせを探すプログラムです。探し方は2段階です。最初の段階では、パラメータと閾値を代表の値に固定し、組を絞ります。最後の段階で、残った組のパラメータと閾値を、範囲の中から探します。

範囲は、要件で次のように決まっています。

- 「最後の段階で、残った組のパラメータと閾値を、範囲から探す。」（`.claude/rules/core_requirements_full.md`:40）
- 「最後の段階で、パラメータと閾値を探す幅です。指標ごとに1つです。」（同 :60）
- 「範囲で探せるという上記要件は絶対」（同 :61）

この作業は、その範囲の出どころになる教科書の文を探します。

**この作業は、値を決めません。データもプログラムも直しません。** 範囲を作りません。ページに何と書いてあるかだけを書きます。

## 経緯

1. engine_tuner を、まず9種の指標で、レンジ・スキャル・ショートの1通りだけ通します。
2. 9種の値を指標データに入れる工事が、ToDo の222番です。
3. 前の調べ（ToDo の264番）で、代表の値の文は多く見つかりました。ただし、閾値の範囲を両端で書いた文は、ほぼ見つかりませんでした。
4. 264番では、新しいページを探していません。

そのため、見つからなかった範囲だけを、新しいページで探します。

## やること

8件のそれぞれについて、次のことを行います。**新しいページを探すことは必須です。** 時間の上限はありません。時間を理由に省きません。

1. 開発者の原典、定番の教育サイト、ライブラリの説明書の順に探します。短い足やスキャルの資料も探します。暗号資産の資料が在れば、それも探します。
2. **1件につき、少なくとも3つのページを開きます。** 開いたページと使った検索の語を、全部書きます。
3. ページは curl で開きます。本文から逐語を1文字も変えずに写し、本文に在ることを照らします。開けないページは、HTTP の番号を書きます。
4. 見つけた文を、下の「文の分け方」で分けます。
5. 文が見つからないときは、「見つからなかった」と書きます。探したページの一覧が無い「見つからなかった」は、認めません。

### 文の分け方

文の意味を読んで分けます。語が在るかどうかだけで決めません。たとえば「true range」の range はレンジの話ではありません。「short-term」の short はショートの話ではありません。

| 欄 | 書く語 |
|---|---|
| 範囲の形 | 「文に両端が在る」（例＝閾値を 70 から 80 の間で調整する）／「値を挙げただけ」／「入力できる範囲」（プログラムが受け付ける幅で、勧める幅ではない）／「強さの区切り」（例＝25〜50 は強いトレンド。探す幅とは書いていない） |
| 閾値の形 | 値・分位・回数・倍率・前提つきのどれか |
| 単位 | %・0〜100・分位・手数料の床の倍数・ATR の倍数のどれか。値段かドルの文は、そのまま載せ、注に「単位が値段かドル」と書く |
| 話の相手 | スキャル・5分足・短い足・レンジ・ショート・一般のうち、文が本当に指している物を全部 |
| 時間足 | 文に書いてある足をそのまま写す。無ければ「時間足は書いてない」 |

## 守ること

1. データ・プログラム・文書を直しません。作ってよいのは、下の「出す物」の2本だけです。
2. 範囲を作りません。いくつかの文の値を並べて、最小から最大までを範囲にしません。
3. 文から1つを選びません。おすすめを書きません。どちらが正しいかを書きません。
4. 上の「探さない物」を調べません。
5. 書いてないことは「書いてない」と書きます。推測で埋めません。検索結果の要約だけで書きません。
6. 乱数を使いません。
7. engine_tuner・G2・H2・材料の検査を走らせません。5分足のデータがこの環境に無いので、走らせても止まります。
8. hook に止められたら、回り込まず、止まった文を結果に書いて作業を終えます。
9. 短いスクリプトと途中の出力は、リポジトリの外の一時フォルダに置きます。

## 出す物

置き場は `.claude/state/indicator_review/research/` です。このフォルダは .gitignore の対象なので、コミットのときに `git add -f` を使います。

**1. `out_textbook_ranges_270.json`** は、次の形です。

```json
{
  "件": [
    {
      "番号": 1,
      "指標": "RSI",
      "探す物": "閾値の範囲（形＝値）",
      "結果": "",
      "使った検索の語": [""],
      "開いたページ": [{"URL": "", "HTTP": 200, "読んだ日": "", "当たる文": "在る"}],
      "文": [
        {"逐語": "", "URL": "", "範囲の形": "", "下の端": null, "上の端": null, "閾値の形": "", "単位": "", "話の相手": [""], "時間足": "", "出どころの質": "", "注": ""}
      ]

  ]

```

`結果` は、「両端の文が在る」「値を挙げた文だけ在る」「見つからなかった」のどれかです。どの形の文も `文` に残します。欄の名前を変えません。無いものは空の配列にします。

**2. `out_textbook_ranges_270.md`** は、人が読むまとめです。次の順に、結論を先に書きます。

1. 8件の結果の表（番号・指標・探す物・結果・文に両端が在る文の数）。
2. 8件ごとの文の一覧。
3. 開いたページの一覧。
4. 確かめられなかった物と、その理由。
5. 始めた時刻と終えた時刻。

コミットとプッシュは、1件ごとに行います。コミットの前に `jq` で JSON が読めることを確かめます。最後に、`件` が8件であることを確かめます。master へは入れません。
