# 依頼書｜法則を法則のデータの欄へ写す対応表を作る（クラウドのセッション用）

## この作業の目的

engine_tuner は、法則に沿って指標・閾値・パラメータ・時間足を組み合わせ、net を最大にするロジックを探します。法則は、1か所を直せば全部のロジックに届くように、1つのデータ laws.json に集めます。

売り方と決済の枝は、laws.json にもう入っています。相場の法則と組み合わせの法則は、まだ入っていません。これを入れる工事が ToDo の195番です。

この作業は、195番の材料として、「どの法則のどの欄を、laws.json のどの欄へ写すか」の対応表を作ります。

**この作業は、データもプログラムも直しません。** 写す案を出すところまでです。どう入れるかは、195番の設計書と監査で決めます。

## 確認の質問をしない

この作業を頼んだ人は、質問に答えられません。確認の質問をせず、最後まで進めます。

- 始めるときに、`git ls-remote origin research/laws-map-195` でブランチが在るかを確かめます。在れば、そのブランチの続きから始めます。
- 始めた時刻と終えた時刻を `date -u` で測ります。
- 会話の記録が要約に置き換わったときは、この依頼書の「守ること」と「出す物」を読み直します。

## 写す相手

パスは、リポジトリの根からの相対です。`SDK` は `v3-bitget-api-sdk/bitget-python-sdk-api` の略です。

| 相手 | ファイル | 範囲 |
|---|---|---|
| 相場の法則 | `SDK/.claude/ratchet/regime_laws.json` | 「法則」の全部の行 |
| クロス | `SDK/.claude/ratchet/condition_parts.json` | `classic_crosses` の全部の行 |
| 組み合わせの法則 | `SDK/.claude/memory/indicator_combination_kb.md` | §3 の表の全部の行と、§4 の全部の項目 |

件数は、あなたが実物から数えて、結果に書きます。ToDo の文には、相場の法則が51件、クロスが11件と書いてあります。違えば、実物の数を書き、違うことを注に書きます。

## 写す先

`SDK/scripts/priority_rebuild/laws/laws.json` の `要素の定義表` です。

- `要素` の各行の「番号」（⑤-1 など）と「要素の名前」が、写す先の欄です。
- 「写す元」の欄に、どの元の欄を写すかが書いてあります。「新しく足す」と書いてある欄は、元に無い欄です。
- `選べる値` に、欄ごとに選べる値が書いてあります。
- `法則の行` に、売り方と決済の枝の行が在ります。行の形の見本として読みます。
- 読むプログラムは `SDK/scripts/priority_rebuild/laws/laws.py` です。読むだけで、直しません。

## やること

相手の1件ごとに、次の4つを調べて、下の形で1行にします。

1. **元の欄の全部を、写す先の欄へ割り当てます。** 元の欄を1つも残しません。写す先が無い欄は、「写す先が無い」の一覧に書きます。
2. **元の中身を、1文字も変えずに写します。** 法則の文を、言い替えたり、まとめたり、新しく作ったりしません。
3. **選べる値に合うかを確かめます。** 元の値が選べる値に無いときは、「選べる値に無い」の一覧に書きます。
4. **指標を名前で指している所を挙げます。** 要素 ⑤-8 は、指標を名前で指さないと決めています。いまの判定には、指標の名前で指す法則が在ります（例＝R5 の family の一覧）。判定を書き替えず、その法則の番号と、指標の名前の全部を挙げます。役割で指す形にするのは別の工事です。

クロスと組み合わせの法則には、番号がありません。番号は作らず、「元の場所」の欄に、元のファイルと行番号を書きます。番号を付ける案は、195番の設計書で決めます。

「法則の種類」（⑤-2）の欄は、元に無い欄です。元の文から読み取れるときは、案を書き、注に「調べた人の読み」と書きます。読み取れないときは「決められない」と書きます。

## 守ること

1. データ・プログラム・文書を直しません。作ってよいのは、下の「出す物」の2本だけです。
2. 法則の文と数を、新しく作りません。元に無いものは「元に無い」と書きます。
3. どの欄へ写すかを1つに決められないときは、候補を全部書き、「決められない」と書きます。推測で1つに決めません。
4. 全部の行を1件ずつ実物で読みます。要約や、ほかの文書の説明から書きません。
5. 値が元どうしで違うときは、片方に決めず、両方を書きます。例＝regime_laws.json の文と regime_detection_kb.md の §11 の文が違うとき。
6. 乱数を使いません。
7. engine_tuner・G2・H2・材料の検査を走らせません。5分足のデータがこの環境に無いので、走らせても止まります。
8. hook に止められたら、回り込まず、止まった文を結果に書いて作業を終えます。
9. 短いスクリプトと途中の出力は、リポジトリの外の一時フォルダに置きます。

## 出す物

置き場は `.claude/state/indicator_review/research/` です。このフォルダは .gitignore の対象なので、コミットのときに `git add -f` を使います。

**1. `out_laws_map_195.json`** は、次の形です。

```json
{
  "件数": {"相場の法則": 0, "クロス": 0, "組み合わせの法則": 0},
  "行": [
    {
      "元の種類": "相場の法則",
      "元の場所": "SDK/.claude/ratchet/regime_laws.json:行番号",
      "番号": "R5",
      "欄": [
        {"写す先": "⑤-4 文", "元の欄": "一文", "中身": "元の文のまま", "注": ""}
      ],
      "写す先が無い欄": [{"元の欄": "", "中身": ""}],
      "選べる値に無い": [{"写す先": "", "元の値": ""}],
      "指標を名前で指す所": [""],
      "決められない": [{"元の欄": "", "候補": [""], "理由": ""}]
    }
  ]
}
```

欄の名前を変えません。無いものは空の配列にします。

**2. `out_laws_map_195.md`** は、人が読むまとめです。次の順に、結論を先に書きます。

1. 件数と、全部を写せたか。
2. 写す先が無い元の欄の一覧（195番の設計書で、欄を足すかを決める材料です）。
3. 選べる値に無い値の一覧。
4. 指標を名前で指す法則の一覧。
5. 決められなかった物の一覧。
6. 元どうしで食い違った物の一覧。
7. 始めた時刻と終えた時刻。

コミットとプッシュは、次の順に行います。

1. `jq` で JSON が読めることを確かめます。
2. `行` の数が「件数」の合計と同じことを確かめます。
3. 2本をコミットし、`research/laws-map-195` へプッシュします。プッシュが失敗したら、1回だけやり直します。master へは入れません。

## 終わったときの報告

次の5つを書きます。

1. ブランチの名前とコミットの番号。
2. 相手ごとの件数。
3. 写す先が無い欄の数、選べる値に無い値の数、指標を名前で指す法則の数、決められなかった物の数。
4. かかった時間。
5. 確かめられなかった物と、その理由。
