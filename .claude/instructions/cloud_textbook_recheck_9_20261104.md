# 依頼書｜9種の教科書の調べを確かめ直し、入れる値の候補の表を作る（クラウドのセッション用）

## この作業の目的

engine_tuner は、指標データの役割・パラメータ・閾値を使って条件を組みます。engine_tuner を、まず9種の指標で最後まで通します。9種の値を指標データに埋める工事が、ToDo の222番です。

前の作業（ToDo の258番）で、教科書の調べと指標データを照らしました。その結果、教科書の調べの中に、誤りと食い違いが見つかりました。例は次の3つです。

- 全指標の調べの基準線の行に、転換線の文が混ざっています。
- 時間足の欄が「書いてない」なのに、逐語には足が書いてある行があります。
- 同じページを、9種の文書は「404 で開けない」と書き、全指標の調べは逐語つきで「ページの文で確かめた」と書いています。

この作業は、222番の材料として、次の2つを作ります。

1. 誤りと食い違いを、ページを開いて確かめ直した結果
2. 9種の欄ごとの、入れる値の候補の表

**この作業は、値を決めません。データもプログラムも直しません。** 候補を並べるだけで、1つに選びません。値を決めるのは、222番の設計書と監査です。

## 確認の質問をしない

この作業を頼んだ人は、質問に答えられません。確認の質問をせず、最後まで進めます。

- 始めた時刻と終えた時刻を `date -u` で測ります。
- 会話の記録が要約に置き換わったときは、この依頼書の「守ること」と「出す物」を読み直します。

## 最初にプッシュできるかを確かめる

前の作業は、最後にプッシュが 403 で止まりました。同じことを避けるため、調べを始める前に確かめます。

1. `git ls-remote origin research/textbook-recheck-264` でブランチが在るかを確かめます。
2. 在れば、そのブランチの続きから始めます。`out_textbook_recheck_264.json` の中に在る指標を飛ばします。
3. 無ければ、ブランチ `refactor/e35-e36-split-strat-base` の最新の版から `research/textbook-recheck-264` を作り、そのままプッシュします。
4. **プッシュが失敗したら、調べを始めません。** 止まった文を報告して、作業を終えます。

## やること1｜確かめ直す

前の照らしの結果の、次の2つの一覧の全部の行について、ページを開いて確かめます。

- 「逐語と値が合わない」（27件）
- 「調べの結果どうしの違い」（5件）

行ごとに、次のことを書きます。

1. 逐語の文がページに在るかを、次の語で書きます。

| 結果 | 意味 |
|---|---|
| ページに在る | ページの本文に、同じ文が在る |
| ページに無い | ページは開けたが、同じ文が無い |
| 開けない | ページを開けない |

2. 開いた道具と結果を書きます。WebFetch で開けないときは、curl でも試します。HTTP の番号が分かれば書きます。同じ URL は、開いた本文を使い回してかまいません。
3. 文が足や指標について何と書いているかを、ページの本文から写します。転換線の文と基準線の文は、分けて書きます。
4. 同じページに、基準線そのものを書いた文が在れば、その逐語を足します。

調べの結果のファイルは直しません。誤りは、この作業の結果に書くだけです。

## やること2｜候補の表を作る

9種の次の欄ごとに、候補を並べます。

| 記録 | 欄 |
|---|---|
| 指標の記録 | ②-4 パラメータの軸（軸ごとの範囲とスキャルの代表の値）・②-5 値の単位と値域・②-6 値の読み方・②-7 教科書の役割・②-11 閾値の範囲 |
| 使い方の記録 | 使い方の種類ごとに、③-3 場面と型・③-4 向き・③-5 閾値（形と値）・③-6 パラメータの代表の値・③-7 時間足・③-9 合図の形のパラメータ |
| 部品の記録（帯pivot） | ④-4 パラメータの軸・④-5 閾値・④-10 値の単位と値域・④-11 値の読み方・④-12 教科書の役割 |

使い方の種類は、`要素の定義表` の `選べる値` の語で書きます。前の照らしの結果の「指標データに行が無い使い方」（16件）も、候補に入れます。

候補の1つごとに、次のことを書きます。

- **値**：逐語に書いてある値です。
- **逐語と URL**：ページの本文から、1文字も変えずに写します。
- **ページの確かめ**：候補に載せる逐語は、全部 ページを開いて確かめます。結果は、上の3つの語で書きます。「ページに在る」でない物も、消さずに載せます。
- **時間足**：逐語に書いてある足を、そのまま写します。足が書いてなければ「時間足は書いてない」と書きます。
- **名指し**：逐語が何を名指ししているかを、次の語で書きます。2つ以上当たるときは、全部書きます。
  - スキャル（scalp・scalping・scalpers の語が在る）
  - 5分足（5分足の語が在る）
  - 短い足（1分足・3分足・15分足など、1時間足より短い足の語が在る。5分足は上の語で書く）
  - レンジ（range・sideways・consolidation の語が在る）
  - ショート（short・bearish・sell の語が在る）
  - 一般（どれにも当たらない）
- **範囲の形**（範囲の欄だけ）：1つの文に両端が書いてあるときは「文に両端が在る」、いくつかの値を挙げただけのときは「値を挙げただけ」と書きます。いくつかの文から範囲を作りません。

候補が1つも無い欄だけ、新しいページを探してかまいません。開発者の原典と定番の教育サイトから探します。見つからなければ「見つからなかった」と書きます。候補がある欄で、新しいページを探しません。

基準線の候補には、転換線の文を入れません。

## 守ること

1. データ・プログラム・文書を直しません。作ってよいのは、下の「出す物」の2本だけです。
2. 候補から1つを選びません。おすすめを書きません。どちらが正しいかを書きません。候補の並びは、調べの結果に出てきた順のままにします。
3. 語の数を数えただけのものを、確かめたと書きません。検索結果の要約だけで書きません。
4. 逐語・URL・指標データの値を、1文字も変えずに写します。
5. 書いてないことは「書いてない」と書きます。推測で埋めません。
6. 全部の行を、1件ずつ実物で読みます。要約や、ほかの文書の説明から書きません。
7. 乱数を使いません。
8. engine_tuner・G2・H2・材料の検査を走らせません。5分足のデータがこの環境に無いので、走らせても止まります。
9. hook に止められたら、回り込まず、止まった文を結果に書いて作業を終えます。
10. 短いスクリプトと途中の出力は、リポジトリの外の一時フォルダに置きます。
