# experiment_result_procedure.md — 実験の結果が出た後の固定手順（まこさん承認 2026-07-17・毎回この順で行う）

作成の経緯: 実装のたびに CC が「net 合計だけ見て即・不採用」を繰り返し、まこさんが毎回同じ指摘（report/analyze を出せ・型別に見ろ・位置とタイミングを分析しろ・PDCA になっていない）をする状態になった。この手順を毎セッション自動読込のルールに固定し、hook（enforce_worklog_on_experiment）が物理で補強する。

## 固定手順（実験の本走の後、採否の話をする前に必ずこの順で）

1. **score.py で採点する。**
2. **report.py を前回比較つき（--vs）で出す。** C2 の入口型別（down / flat_up）を必ず見る。
3. **analyze.py を前回比較つき（--vs）で出す。** N0 の前後比較（件数・net・平均・勝率）を必ず見る。
4. **増えた玉・減った玉の「入った位置とタイミング」と建玉の動きを、型別に分析する。** 集計の合計値だけで止まらない。出血がどの少数の玉に集中しているか、勝った玉と何が違うかまで見る。
5. **この実験が何を検証したのか（狙い）を書き、その狙いに対応する部分指標で評価する。** net 合計の悪化だけで「不採用」と言わない。「不採用」は 1〜4 の分析を全部出した後にだけ言える。

## 大原則（PDCA）

- 一回の修正で目標に届くことはない。分析（Check）から次の調整（Act）を出して積み上げる。
- 器（計器・構造）とツマミ（値・条件）を区別する。器が狙い通り動いたなら、net が悪くても器は前進。次はツマミの調整。
- 「悪化した→スイッチオフで捨てて終わり」は PDCA ではない。捨てるのは分析して学びを記録した後の個別ツマミだけ。

## 物理強制（hook）

enforce_worklog_on_experiment.sh（Stop・fast-mode）が次を検査する。
- 実験や分析の後に worklog が未更新ならターン終了不可（従来）。
- 最新の採点 CSV に対応する report と analysis のファイルが無ければターン終了不可（2026-07-17 拡張）。
- worklog にその実験の記録（タグ_番号）と「型別」の分析が無ければターン終了不可（同）。
