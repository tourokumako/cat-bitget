## 決まり（5つ）

1. **一文を短くします。** 1つの文に1つのことだけ書きます。
2. **主語と述語と目的語を、1つずつ書きます。**
3. **単語が何を指すのかを書きます。** 新しい言葉かどうかに関係なく書きます。
4. **前提と経緯を省きません。**
5. **情報が3つ以上あるときは、箇条書きにします。**
6. **手順が複数ある動きを、1つの動詞に縮めません。**（2026-08-03 追加）

### A. いちばん大事な5つ（★まこさんが選びました・2026-08-18）

**★この5つは CC が考えたものではありません。外の指針から取り、まこさんが「これが重要」と選びました。**まこさんの逐語＝「文章の長さはそこまで厳密にせずともいい。それよりも以下が重要」。**言い回しを変えずに、そのまま載せます。**

4. **基本的な語順（「いつ」「どこで」「誰が」「何を」「どうした」）を踏まえる。**

## 決まり6 の使い方（追加 2026-08-03）

**見分け方です。** 自分が書いた動詞を見て、「どのファイルを開いて、何を探して、何をするのか」に書き下せるか試します。**書き下せるなら、書き下してください。** 1つの動詞に縮めると、読む人には何も伝わりません。

**縮めてはいけない動詞の例です。** 「取る」「引く」「拾う」「回す」「当てる」「効かせる」。ほかにもあります。**大事なのは語の一覧を覚えることではありません。「その一言の裏に手順が何段かあるか」を自分に聞くことです。**

## 使わない言い方の一覧（追加 2026-08-03・まこさん指示）

**この節に載っている言い方を、チャットで使いません。** 機械が生成する文書や、要件定義書のような正本ファイルの中に既に書かれている語は、そのファイルの中ではそのまま残します。**やめるのは、私がチャットで書くときだけです。**

| **多重検定の罰** | 統計の言葉です。まこさんが 2026-08-03 に「よくわからない」と指摘しました | **「試した回数が多いほど、合格の線を厳しくする仕組み」** と書きます。初めて出すときは、下の「言い換えの全文」を使います |
| **取る**（値や設定について） | 実際は「ファイルを開いて、その中の値を読む」という複数の手順です。一言に縮まっています | 「engine_tuner は、〜が書いてあるファイルを読みます」と書きます |
| **引く**（値や役割について） | 実際は「ファイルを開いて、行を探して、文字を読み取る」という複数の手順です | 「〜を開きます。その中の〜という行を探します。その右側の〜を読み取ります」と書きます |
| **判定表**（単独で使う） | 日本語だけだと用途が広く、何を指すのか定まりません。まこさんが 2026-08-05 に「判定表は用途が広いイメージで何を指してるのか定まらない」と指摘しました | **「tuner_judgement（判定表）」** と書きます。下の「道具の名前の書き方」を参照 |

| **合格・不合格の表** | 同上。CC が同じものに2つ目の言い換えを付けました（2026-08-05） | **「tuner_judgement（判定表）」** と書きます |
| **線**（2026-08-06 追加） | 「何ができたら完成したと言えるか」という条件を、引かれた線に**例えて**いました。例えなので、読む人には何の線か分かりません | **「完成の条件」** と書きます |
| **撒く／撒いた**（2026-08-06 追加） | engine_tuner が売買ルールの案を何本も作ることを、種まきに**例えて**いました | **「engine_tuner が売買ルールの案を作る」** と書きます |
| **器**（2026-08-06 追加） | engine_tuner 本体のことを、入れ物に**例えて**いました | **「engine_tuner」** と、そのまま実体の名前で書きます |

| **土台**（2026-08-06 追加） | いま採用している設定のことを、建物の基礎に**例えて**いました。memory の feedback_trade_terms_writing でも CC の造語として既に禁止されています | **「いま採用している設定」** と書きます |
| **十分性**（2026-08-07 追加） | 実装の英語のキー名 sufficiency を、そのまま漢字にしただけの直訳です。まこさんが 2026-08-07 に「『十分性』ってなに？ 英語の直訳みたいなのやめてほしい」と指摘しました | **「値動きの大きさ」** と書きます。指すもの＝値動きの幅が足りているかを確かめる条件（V9 P3 の実物＝ATR ≥ 250） |
| **環境認識**（2026-08-07 追加） | 同じく実装のキー名 env の直訳寄りの言い方です | **「相場の向き」** と書きます |
| **引き金**（2026-08-07 追加） | 同じく trigger の直訳です | **「建てる合図」** と書きます |
| **位置**（単独で使う・2026-08-07 追加） | location の直訳。何の位置か分かりません | **「レンジの中の位置」** と書きます |
| **点／点の一覧**（2026-08-09 追加） | 数直線の上の1つの値を、点に**例えて**いました。例えなので、読む人には何の点か分かりません。まこさんが 2026-08-09 に「点って何？」と聞き返しました | **「決まった数字だけが、あらかじめ並べてあって、その中からしか選べない」** と書きます。実物で言い換えると「engine_tuner が RSI の期間で試せるのは 7・9・14・21 の4つだけで、RSI12 は何回 試しても出てこない」です。対になる言い方＝**「範囲で探す」**＝「7 から 200 までの、どの整数でもよい」 |

## なぜ例えの語 5つを足したか（追加 2026-08-06・まこさん指示）

**経緯です。** 2026-08-06 に、CC がチャットで「線」と「撒いた」を使いました。まこさんが意味を聞き返しました。**まこさんの逐語です。**

> ニュアンスが伝わらない、CC用語みたいな単語使用はやめてほしい。
> そういう使用方するなら英語のままにしてほしい

### ★この5語には共通の作りがあります。全部「例え」です

| 語 | 何を何に例えたか |
|---|---|
| 線 | 完成の条件を、引かれた線に例えた |
| 撒く | 案をたくさん作ることを、種まきに例えた |
| 器 | 道具そのものを、入れ物に例えた |
| 空間 | 選べる範囲を、空間に例えた |
| 土台 | いま採用している設定を、建物の基礎に例えた |

### 見分け方（★語の一覧を覚えるのではありません）

**自分が書いた漢字1文字か2文字の名詞を見ます。** そして自分に聞きます。

> **これは例えか。それとも、そのものの名前か。**

**例えなら、例えるのをやめて、指すものをそのまま書きます。** 上の5語のほかにも、同じ作りの語はいくらでも作れます。**大事なのは5語を覚えることではなく、例えを使っていないかを毎回 自分に聞くことです。**

### なぜ例えが伝わらないか

**例えは、書いた本人の頭の中にある絵に頼っています。読む人は、その絵を見ていません。** ですから「線」と書かれても、何の線なのか分かりません。**書いた本人だけが分かっているつもりになります。** これは決まり3（単語が何を指すのかを書く）に反しています。

### まこさんの提案の意味（逐語＝「そういう使用方するなら英語のままにしてほしい」）

**意味はこうです。例えの日本語1語に縮めるくらいなら、英語の原語をそのまま書いた方が、まだ何を指すか分かります。**

**ただし一番よいのは、上の表の「代わりにどう書くか」の列のとおり、指すものを日本語でそのまま書くことです。**

### ★過去の文書を読むときの注意（後で自分が困らないため）

**この5語は、これまでに書いた文書の中に残っています。消しません。** 古い文書でこの語に出会ったときは、**上の表の「なぜ使わないか」の列を見て読み替えてください。** 例えば古い文書の「完成の線」は「完成の条件」、「撒いた構造」は「engine_tuner が作った売買ルールの案」という意味です。

## 道具の名前の書き方（追加 2026-08-05・まこさん指示・★絶対に忘れない）

> 判定表は用途が広いイメージで何を指してるのか定まらないので、これ以降は tuner_judgement（判定表）で統一して。この件は絶対に忘れないように、どこかに書いておいて

## なぜ5つになったか

2026-08-01 から 08-02 にかけて、まこさんが同じ日に6回、文章が分からないと指摘しました。逐語を残します。

- 「文章がよくわからない」
- 「まじで文章がよくわからない。なんだこれ」
- 「主語、述語、目的語、が明確じゃないせいなのか？英語の直訳みたいな変な日本語なんだよね」
- 「探索の伸びは止まりましたってどういう意味？」
- 「engine_tuner が見つけた値ってなんのこと？」
- 「『いまの規則ファイル』ってなんのこと？　まさにこういう文章が分かり辛い要因なんだよ」

**まこさんの診断（2026-08-02・逐語）**

> 新しく出す言葉に限らず、何を指す単語なのかがよくわからないケースが多いのかもしれない。
> 前提や経緯を省いた文章も分かりづらくなるケースがあるかも。
> あとは箇条書きにするとか。チャットGPTは文章が短く端的でわかりやすいんだよね。
> 君は一文が長く、主語、述語、目的語のつながりが曖昧で不明瞭に感じる

**★分かりにくさの原因ではないもの**

括弧とイコールと中黒は、原因ではありません。まこさん本人が 2026-08-02 に否定しました。逐語は「括弧とイコールと中黒が文章が分かり辛い要因ではない」です。CC はこれを原因だと決めつけて、記号を検査する仕組みを作りかけました。まこさんが止めました。**原因でないものを禁止しないでください。**

**★表と太字とリンクは使ってよい**

まこさんの記録 feedback_no_markdown_links に「リンク形式・太字・表は使ってよい」と書いてあります。禁止はバッククォートで囲んで背景がグレーになる書き方だけです。CC が 2026-08-02 に根拠なく「表を使いません」と断定して、まこさんに「どういう根拠を持って断定する？」と指摘されました。

**★崩れる場面**

情報が多いときに崩れます。雑談では崩れません。まこさんが 2026-08-02 に「ここでの会話文には違和感はないんだけど」と言いました。CC は、要素を落とさないようにしようとして、1つの文に情報を詰め込みます。**情報が多いときこそ、文を分けて箇条書きにしてください。**
