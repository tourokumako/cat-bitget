**＝1位でも、当てずっぽう（50%）に対して +9.5pt／+8.6pt しかありません。**この差で材料の順位を決めれば、順位は雑音で入れ替わります。

- **型**＝**起案 CC の案に不利な唯一の実測が、事実データから落ちた。**`false_positive_incident_policy.md` §2 の類型 G の隣＝**確かめずに「無い」と断じた**（違反の記録 #17 と同じ型）。
- **対策**＝依頼書に載せる「うちの実測の有無」は、**`ledger.md` の ARC の目印からプログラムで抜き出す**（`gen_improvement_arc.py` がもう ARC の目印を読んでいます）。抜き出す条件＝「内容」の欄に 判定・レジーム・range・帯 の語が在り、かつ「据え置き」「不変」の語が在る行。**CC が「1件も無い」と書ける道を無くします。**

### 【P-2】依頼書に「起案 CC に不利な事実」の節を必ず置く（Critical）

- **事案**＝札「強さ」の弱さ（正しく分けられた割合 58.6〜59.5%）と、別の札で ER・CHOP が1位群になる事実が、**どちらも依頼書に載っていません。**載っているのは「R5 の指標は上位4つに入っていない」という、いまの札を残す側の事実だけでした。
- **型**＝観点⑦。**「載せた事実が全部 正しい」ことと「不利な事実を載せた」ことは別です。**
- **対策**＝依頼書のひな型（`.claude/audits/inputs/_template.md`）に「**§不利な事実（起案 CC の案を否定する向きの実物・プログラムの出力）**」の節を必ず置く。**空欄で出せない**（監査の側が「空欄＝観点⑦ FAIL」と扱う）。

### 【P-3】「本文を開いた／開けなかった」を、根拠の欄に必ず書く（Major）

- **事案**＝本監査で、SSRN の全件・quantifiedstrategies の全件・NY Fed が開けませんでした。**開けなかったことを書かずに数字だけ引くと、【要約】が【本文】に格上げされます。**
- **対策**＝KB §11 の出どころの欄に「**取り方**」を1語 足す（`本文 取得済` ／ `要約のみ（一次ページ 403）` ／ `要約のみ（自動アクセスの遮断）`）。**印だけでは、後から見てどちらか分かりません。**

### 【P-4】プログラムが作らない「実測」の欄に、腐りを見張る仕組みを付ける（Minor）

- **事案**＝KB §11-2 の「engine_tuner で書けるか（2026-08-19 実測）」の R8 の欄が、実物と食い違っていました（Minor-1）。`materials.md` L680 の「M2-2 で足すもの」の行も同じでした（Minor-2）。
- **対策**＝`materials.md` と同じ形（プログラムが作る ＋ `--verify` で改変を検出）に寄せる。**手で書いた「実測」の欄が9日で腐った、という事実そのものが根拠です。**
