## 14-1 「見分ける範囲」を名前の形で決めることの落とし穴

**業界の扱い。**ファイル名の形（glob）で範囲を決めるとき、**広すぎる側と狭すぎる側は、同じ1つの選択の裏表**だと書かれています。

- **狭すぎる側**＝`*` は「1つの名前の中の文字」にしか当たらず、**フォルダの区切りを越えません**。下の階層に置かれたものを取りこぼします。越えるには `**`（Python では `rglob`）が要ります。
- **広すぎる側**＝`**/*.拡張子` は、どれだけ深く入れ子になっていても全部 当たります。**何が入るかを意識していないと、当てるつもりのないものまで当たります。**
- **もう1つの落とし穴**＝**大文字と小文字の扱いが、機械によって違います。**Windows は区別しないので `ABC` が `abc` に当たり、区別する機械では当たりません。

**業界が勧めるやり方は3つです。**①**入れる形と、外す形を組にして書く**（`AddInclude` と `AddExclude` は何回でも呼べる）②**当てたい末尾を、あいまいにせず はっきり書く**（前の部分だけの絞りにしない）③**下の階層を含めたくないときは `directory/*` と書き、含めたいときだけ `**` を使う。**

**この監査との照合。**
**この工事は、業界の答えの3つとも入れています。**
①**入れる形（`BTCUSDT-5m-*.csv`）と、外す形（名前に `bitget` を含むもの）を組にしました**＝広すぎる側（Major）の直し。
②**`glob` を `rglob` にしました**＝狭すぎる側（別枠 A）の直し。
③**大文字と小文字は `p.name.lower()` で揃えています**（`observe_diag.py`:1632）＝上の3つ目の落とし穴を踏んでいません。
**★ただし、外す形は名前の一部（`bitget`）で決めているので、別の名前で置かれた別の系列は見分けられません。**設計書 §7 の補4 が、その限界をそのまま書いています。

## 14-2 テストの中に、環境の値（期間・パスなど）を手で書くことの危険

**業界の扱い。**テストの中に値を直に書くこと（hard-coding／magic number・magic string）は、**名前の付いた失敗の型**として扱われています。

- **いちばん重い危険**＝**値は時間とともに変わるのに、テストがその変化についていかない。**業界の文の要点＝「決め打ちの値は時間とともに変わる。テストがその変化を反映していないので、**大きな不具合が長い間 見つからないままになる**」。
- **もう1つ**＝**直すたびに人が手で書き替えることになる**ので、変わる回数が多いほど手間が増え、抜けが出ます。
- **読む側の危険**＝説明の無い値は、読んだ人に「なぜこの値なのか」を考えさせ、テストの中身ではなく実装の細部へ目を向けさせます。

**業界が勧めるやり方**＝**決め打ちの値を定数へ出し、その定数を1か所（single source of truth）に置く。**

**この監査との照合。**
