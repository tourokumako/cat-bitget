## §1 現状の cc_ml_design_spec が定めている ML の使い方

### 何を ML にやらせているか

- **入力**: 各 5 分足 bar の特徴量 1,432 個（既存指標）
  - **指標の時間軸は MTF (マルチタイムフレーム)**: 5m / 15m / 30m / 1h / 4h / 1d の指標が含まれる
- **出力**: 16 個の数値を予測（K=12/24/48/96 × LONG/SHORT × MFE/MAE）
  - MFE = K本先までの最大有利値動き
  - MAE = K本先までの最大不利値動き
  - **K 窓 = 保有時間軸のバリエーション**: 1h / 2h / 4h / 8h の保有期間それぞれを予測
- **モデル**: LightGBM 回帰（決定木のアンサンブル）
- **使い方**: 予測した MFE÷MAE 比率が閾値以上なら Entry
- **エントリー bar の時間軸**: **5 分足固定**（1 分足や 1 時間足ではエントリー判定しない）

### MTF の現状を正確に整理（誤解しやすい点）

「ML は時間軸を組み合わせている？」という問いには **「部分的に Yes・部分的に No」** が正確な答え。

| 観点 | 現状 |
|---|---|
| 特徴量の時間軸（ML への入力指標） | ✅ MTF（5m〜1d 6軸） |
| 保有時間軸（ML が予測する保有期間） | ✅ MTF（K=12/24/48/96 = 1h/2h/4h/8h） |
| **エントリー bar の時間軸（実際に注文を出す bar）** | **❌ 5 分足固定** |

つまり「5 分足の bar で・複数時間軸の指標を見て・複数保有期間の予測を出す」までは出来ている。**でもエントリー判定そのものは 5 分足でしか出ない**。「1 分足でしか見えない瞬間的なチャンス」「日足の大局でしか分からない判断」は構造的に取れない。

### ML が**やっていない**こと

- どの Exit を使うかの判断（Phase 4-b で人間が決める手続き）
- Exit パラメータ（TP価格・トレーリング閾値）の決定
- ポジションサイズの決定（固定 or 動的配分は ML 外）
- いつ追加エントリーするか（ナンピン判断）
- 損切りタイミングの判断（Exit 方式が time_exit なら強制決済まで保有）
- 市場の状態（強い上昇トレンド / レンジ / 暴落寸前 等）の認識

### Phase 5 v3 で確認された現実

- 合計 NET: -$985 / 月次達成 0/12
- 19 combo 中 8 combo は採用 Exit で勝っている（最強 K12_SHORT_q90-q95 勝率72.6%・+$1,613）
- 19 combo 中 11 combo は採用 Exit で負けている
- 87% の発火が position_limit で no_trade
- 監査 audit#15 が「Exit 選定ロジックの構造的失敗」を疑うべきと指摘

つまり**現状の ML 設計には「予測モデル」としての機能はあるが、利益を上げる仕組み全体としては機能していない**。

## §2 現状の枠内でできる改善（spec を大きく変えない）

cc_ml_design_spec の「ML = 予測モデル / Exit = 別段階」の枠は維持する案。

### 案 W1: ハイパーパラメータ調整（spec §1.3 / Phase 3 で予定）

LightGBM の設定値(木の深さ・葉の数・学習率)を調整して予測精度を上げる。

- **何が変わるか**: 予測精度が数%上がる可能性
- **実装難度**: 低（既存 spec の Phase 3 で実装予定）
- **leak混入リスク**: 低
- **期待効果**: 小〜中。現状の数字を倍にできるかは不明
- **時間**: 数日

### 案 W2: 特徴量の絞り込み・追加

現状 1,432 指標全投入だが、特徴量重要度や permutation importance で絞り込んで再学習。または現状にない指標（オーダーブック由来・取引所別差分など）を追加。

- **何が変わるか**: ノイズ削減で予測精度が上がる、または新規シグナル発見
- **実装難度**: 中
- **leak混入リスク**: 中（追加指標で leak混入の歴史あり・フラクタル事案）
- **期待効果**: 小〜中
- **時間**: 数日〜数週間

### 案 W3: K 窓の見直し

現状 K=12/24/48/96 の4種類固定。K=6(30分)・K=144(12h)・K=288(24h)を追加 or K=24 を除外（K24 全 combo が test 2025 で負けた監査盲点1）。

- **何が変わるか**: 異なる保有期間の取引機会を捕捉
- **実装難度**: 低
- **leak混入リスク**: 低
- **期待効果**: 中
- **時間**: 数日

### 案 W4: Entry 閾値の動的化

現状 q90/q95/q99 の3閾値の固定組合せを、市場状況(ボラティリティなど)で動的に変える。

- **何が変わるか**: 高ボラ期 / 低ボラ期で発火タイミングを変える
- **実装難度**: 中
- **leak混入リスク**: 中（「市場状況」を t 時点で正しく取れるかが鍵）
- **期待効果**: 中
- **時間**: 1〜2週間

## §3 枠外の選択肢（spec の発想を広げる）

ML の管轄を広げる案。spec §3「Exit 設計」や §4「Position 設計」の人間手続き部分を ML に置き換える。

### 案 X1: Exit を予測対象に追加する

ML に「**この bar からエントリーするなら、何本後に・どの価格で決済するのが最適か**」を直接予測させる。

- **何が変わるか**: Exit 種別(TP / トレーリング / 時間)の選択を ML が自動判定。combo 別固定 Exit という制約が消える
- **実装難度**: 中（既存 LightGBM の枠組みで実装可能・学習データの作り方を変える必要）
- **leak混入リスク**: 中〜高（「最適 Exit」を train で計算する時に未来データを使う設計になりやすい・要慎重）
- **期待効果**: 大の可能性（監査が指摘した「Phase 4-b の選定失敗」を構造的に解消）
- **時間**: 数週間
- **専門用語**: 「マルチタスク学習」「multi-target regression」と呼ばれる

### 案 X2: 強化学習で一連の行動を最適化

ML に「エントリーから決済までの一連の行動」をまとまりとして学習させる。各 bar で「保持/利確/損切り/ナンピン」を都度判断させ、最終 PnL が最大化するように行動の選び方そのものを学習。

- **何が変わるか**: Entry/Exit/Position サイズ/ナンピン が全て ML の管轄に。spec の手続き部分が消える
- **実装難度**: **高**（強化学習は実装複雑・学習が不安定になりやすい・leak の出方も別パターン）
- **leak混入リスク**: 別の形で発生（reward 計算が未来を覗いていないかの verify が複雑）
- **期待効果**: 大の可能性。ただし実装失敗時のリスクも大
- **時間**: 数ヶ月
- **専門用語**: 「強化学習」「reinforcement learning」「DQN」「PPO」

### 案 X3: 時系列モデルへの切り替え

LightGBM は各 bar を独立に扱う（時系列の流れを直接モデル化しない）。これを LSTM / Transformer 等の時系列モデルに切り替えると「**3本前にこうなり、2本前にこうなり、いま**」という連続パターンを直接学習できる。

- **何が変わるか**: 時系列の文脈を活かした予測。連続的なシグナルパターンを捕捉
- **実装難度**: 高（実装は技術的に確立しているが、学習データ量・計算資源・leak混入チェックが複雑）
- **leak混入リスク**: 中（時系列モデルでは特有の leak パターンがある・要 verify）
- **期待効果**: 中〜大（時系列依存性が市場で強い場合に効く）
- **時間**: 数週間〜数ヶ月
- **専門用語**: 「LSTM」「Transformer」「N-BEATS」「TFT」

### 案 X4: ポジションサイズも ML が予測

ML が予測した「予測確信度」に応じて、ポジションサイズを動的に変える。確信度が高い時は大きく、低い時は小さく。

- **何が変わるか**: 同じ予測結果でも、確信度の強弱に応じてサイズを最適化
- **実装難度**: 中
- **leak混入リスク**: 中
- **期待効果**: 中（ケリー基準等で資金効率が上がる）
- **時間**: 1〜2週間
- **専門用語**: 「ケリー基準」「volatility scaling」

### 案 X5: 市場レジーム分類との統合

「今は強い上昇 / レンジ / 急落寸前」のような市場の状態（レジーム）を ML が分類し、レジームごとに別の予測モデル or 別の Exit ロジックを使う。

- **何が変わるか**: 市場状況に応じた戦略の切り替え。「常に同じ戦略」の弱点を補う
- **実装難度**: 中
- **leak混入リスク**: 中（過去の regime_research.md でも leak が発生した歴史あり）
- **期待効果**: 中〜大
- **時間**: 2〜4週間
- **専門用語**: 「regime detection」「HMM」「unsupervised clustering」

### 案 X6: マルチタイムフレーム統合（エントリー bar の多時間軸化）

**注: 現状の ML は「指標」「保有時間軸」では既に MTF を活用済み（§1 参照）。本案 X6 は『エントリー bar の時間軸そのものを複数化する』案。** 現状の「5 分足の bar でしかエントリー判定しない」制約を取り払う。

具体的には: 1 分足用 ML / 5 分足用 ML / 1 時間足用 ML / 日足用 ML を別々に作り、複数の予測を統合してエントリー判断。「1 分足の瞬間的な値動きシグナル」「日足の大局的トレンド転換」を、それぞれの時間軸で発火できるようにする。

- **何が変わるか**: 「日足の大局＋5 分足の精密＋1 分足の瞬間機会」の組合せ。エントリー機会の構造的拡張
- **実装難度**: 中〜高
- **leak混入リスク**: 中
- **期待効果**: 中
- **時間**: 数週間
- **専門用語**: 「multi-timeframe analysis」「hierarchical models」
- **現状との違い**: 現状は「5 分足の bar」で「複数時間軸の指標を見て」「複数保有期間の予測を出す」。X6 は「複数時間軸の bar で」エントリー判定を出す

### 案 X7: 別アルゴリズムへの切り替え

LightGBM 以外の機械学習アルゴリズム(XGBoost・CatBoost・Neural Network・古典 SVM 等)に切り替える。

- **何が変わるか**: 異なる学習方式で異なるパターンを捕捉する可能性
- **実装難度**: 低〜中（既存の特徴量とラベルがそのまま使える）
- **leak混入リスク**: 低
- **期待効果**: 小〜中（同じ予測対象で別アルゴリズムを試しても劇的改善は稀）
- **時間**: 数日〜2週間

### 案 X8: ML 自体を捨てる（ルールベース回帰）

ML をやめて、特徴量と PnL の関係を手動で分析し、ルールベース（条件分岐）の戦略を作る。

- **何が変わるか**: ML のブラックボックス性が消え、戦略が完全に説明可能になる
- **実装難度**: 中（人間の分析時間が大きい）
- **leak混入リスク**: 低
- **期待効果**: 小〜中（市場の複雑性をルールで捕捉できる範囲に限られる）
- **時間**: 数週間〜数ヶ月

## §5 私の所感（参考）

### 監査結果と現状数字から見て、有力候補と思うもの

**最有力: X1（Exit を予測対象に追加）**
- まこさんの「あらゆる Exit 方法を学習して最適化すればいい」発言と直結
- 監査 audit#15 が指摘した「Phase 4-b 選定ロジックの構造的失敗」を構造的に解消できる
- 既存 LightGBM の枠を活かせる（X2・X3 より移行コスト小）
- ただし leak混入リスクは中〜高（要慎重設計）

**次点: X4（ポジションサイズも ML）と W3（K窓見直し）の組合せ**
- X4 は監査盲点1（K24 全 combo 敗北）に対する補強にもなる
- W3 で K24 を除外 or K=6/K=144 を追加すれば取引機会の拡張

**慎重に検討すべき: X2（強化学習）**
- 期待効果は最大級だが実装難度・leak混入リスクも最大
- 期限なしのプロジェクトとして時間をかける価値はあるが、軽々しく着手すべきではない

### 有力でないと思うもの（参考）

- **W1（ハイパラ調整のみ）**: 既存 spec 通りで進める案だが、現状の数字（合計-$985）から見て、ハイパラ調整だけで月次$1,900達成は厳しい
- **X8（ML 自体を捨てる）**: ML の知見・1432指標・leak verify の経験が活きない。後退の意味合いが強い

## §6 私のバイアスへの自己警告

このドキュメントを書くにあたって、私に入りうるバイアスを正直に列挙する。

### バイアス1: 「現状路線を救う方向」の語彙偏向

audit#15 観点⑦で指摘された通り、私は過去「現状路線を否定する方向の語彙」に偏った。今回の所感では逆に「**現状路線を救う案を有力にしたい**」というバイアスが入った可能性がある。

具体的には：
- X1 を「最有力」とした判断に、「LightGBM の枠を活かせる＝今までの作業を無駄にしない」という保身が混じっていないか
- X2（強化学習）を「軽々しく着手すべきではない」と書いたのは、自分が強化学習の実装経験が乏しいことへの回避ではないか

### バイアス2: 「分かりやすい順序」への偏り

選択肢を W（枠内）→ X（枠外）の順で並べたのは「変更幅が小さい順」と意図したが、これは「**変更幅が小さい方が安全**」という暗黙の前提を含む。実際には、大きな変更の方が問題を構造的に解決する場合もある。

### バイアス3: 私が選定したリストの網羅性

W1〜W4 / X1〜X8 で網羅したつもりだが、**私が思いつかない選択肢が存在する可能性**は常にある。具体例：
- 「データを買う・取引所を変える」（私が思考から除外している）
- 「予測対象を MFE/MAE 以外にする」（例: 終値方向・分位点・分散）
- 「学習データを増やす・期間を変える」（半減期跨ぎ問題への対応）

これらは §3 にも入れていない。私の盲点として明示しておく。

### バイアス4: 専門用語の選び方

専門用語に「初出で補足」を付けたが、**用語の選び方自体に偏向**がある可能性。例：
- 「強化学習」を1単語で扱ったが、その下に多数の手法（DQN/PPO/A2C/SAC等）があり、選び方で実装難度が大きく変わる
- 「Transformer」も同様（GPT系・BERT系・時系列特化TFT等で全然違う）

深掘り段階（第2段）では、用語の中身まで踏み込む必要がある。

## まこさんへ：次のステップの選択

このドキュメントは「広く浅く」（案C第1段）。**深掘り（第2段）に進む対象を選んでください。**

選び方の例:

- **「X1 を深掘り」**: 私が最有力と判断した案。Exit を予測対象に追加する設計の詳細・leak混入回避策・実装ステップ・期待効果の数値見積もり
- **「X1 と X4 を組合せで深掘り」**: 私の所感の次点候補
- **「X2 を深掘り」**: 強化学習で根本変更する案
- **「複数案を比較深掘り」**: 例: X1 vs X2 vs X3 を同じ深さで比較
