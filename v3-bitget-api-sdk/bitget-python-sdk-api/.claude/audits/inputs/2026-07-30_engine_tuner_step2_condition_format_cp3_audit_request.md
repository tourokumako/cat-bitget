## 監査対象の事実データ

### 設計の骨子（詳細は設計書＝必読1）

- レシピ＝meta / pre_filter / entry（条件＋つなぎ木）/ exits（枝リスト・順番はデータ）/ position の5節。
- 条件1つ＝役割（env/trigger/sufficiency/location）・形（11種）・材料（family×param×tf の3軸・1本または2本）・側・値（閾値は分位のみ・生値は名前つき定数のみ）。
- 引き金ちょうど1本＝縁（エッジ）評価。他の役割は状態評価。
- つなぎ方3種＝all / any / if-then。深さ上限つき。
- 生成の物理制約 G1〜G6＝引き金1本・適合制約（検査5 の独立有効標本数≥N_MIN）・同系統制限・リスクリワード事前担保・役割と本数と深さの規則・未登録材料の拒否。拒否は理由別件数を機械出力。
- 出口の枝＝fire（ポジション状態列を材料に使える条件）・exec（X-k 10種・既定 maker）・scope（add区間×保有区間）・size_ratio。
- 玉＝avg / separate の2形・avg は平均建値基準で MFE を再定義・max_adds 探索対象・枠の占有を機械出力。
- 値の水準は全部まこさん判断待ち（設計書 §11 の7件）。

### 実装の現状（比較対象）

- engine_tuner が組める条件＝1本の列×閾値×上下の1種のみ・条件2個まで・材料9列（1.17%）。
- 出口4枝固定順・玉は別玉2つまで。

## 監査観点 (本監査固有・Q1-Q7)

### Q1 — 表現力の網羅

形11種×つなぎ方3種×役割4種は、材料C の「そこから出る要件」15行と v9_logic §4 の書き方14種を**全部**書けるか。書けないものがあれば名指しすること。逆に、軸カタログ（E-a〜E-j）の観点で「形式の段階で既に閉じている表現」（例＝マーケットメイク・グリッドの複数指値）が歩3/歩6 でどう扱われるべきかを確認すること。

### Q2 — 引き金＝縁評価の設計

「trigger は前バー不成立→今バー成立の縁で発火・他は状態評価」という規則は、(a) 発火しない組み合わせ（CP2 4-2）と (b) 毎バー発火し続ける組み合わせ、の両方を本当に塞ぐか。縁評価が壊す正当な使い方（例＝V9 P4 の「過去10本以内に押し目」を引き金にする形）が無いか。

### Q3 — 閾値＝分位のみ、の副作用

生値の閾値を持たず分位だけにする設計は、(a) 手打ち数字の混入（CP2 4-1・4-23 の型）を塞ぐ利点と、(b) 分布が動くと同じ分位でも実値が動く（値決め窓に依存する）欠点を持つ。教科書の固定水準（RSI 70/30 等）を名前つき定数で持つ折衷は十分か。業界の探索設計（グリッド/分位/連続値）と照合すること。

### Q4 — 適合制約と同系統制限の実効性

G2（独立有効標本数≥N_MIN）は CP2 4-4（122日に日足50本平均は独立2点）を正しく一般化しているか。系統マップを family から機械付与する設計（G3）で、分類が恣意的になる family（例＝MFI は出来高系かオシレーター系か）の扱いは壊れないか。

### Q5 — 出口の枝の一般形

「時間切れの含み損係数を専用フィールドでなく2本の枝で表す」等の一般化は、探索空間を不必要に広げないか（同じ挙動の別表現＝重複レシピが DSR の試行数を膨らませる懸念）。ポジション状態列（mfe_pct 等）の定義は avg/separate の2形で曖昧さなく決まるか（特に avg の積み増し時のピーク再定義）。

### Q6 — leak と因果性

形式のどこかに未来参照が入り込む余地は無いか（材料は当該バーまでの確定値・分位解決は値決め窓のみ・状態列は保有中の実績のみ）。縁評価・streak・within_n の実装で「シグナルバー自身の確定」の扱いが曖昧になっていないか（バー確定後に判定→次バーで執行、の既存慣例と整合するか）。

### Q7 — 実装可能性と検収

歩3 の恒等検収（現行 S2 をレシピで書き写して売買記録 md5 一致）は、この形式の情報だけで達成可能か。形式に不足しているフィールド（例＝エントリー指値のオフセット・TTL・レンジ判定の参照方法）が無いか。設計書 §8-1 の実例を実際に紙上で追跡して確認すること。
