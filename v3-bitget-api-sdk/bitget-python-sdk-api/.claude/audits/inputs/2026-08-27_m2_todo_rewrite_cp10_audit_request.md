### Q4 — いまの束が法則のどれを満たすか

事実データ5（起案 CC の数え＝○5・△4・✕6）を、実物（`engine_tuner_gen.py` `sample_regime_build` L2071-2108・`observe_diag.py` L363-371・L5439-5455）で確かめ、違う所を直す。**あわせて、事実データ8の具体例（RG-v6）が満たす法則との差を1件ずつ示す**（例＝R1 を、例は確定スイングの束ねで測り、いまの束は「いまの終値へのタッチ回数」で代用している、など）。★差を埋める提案は「例の定数を持ち込む」形でなく「何を測る決まりか・その値は engine_tuner が範囲から探す」の形で（#23）。

### Q5 — 材料で足りるか

事実データ6の材料（ta 43種 ＋ 法則の名指し）で、Q3 で「根拠あり」となった決まりを engine_tuner が条件として書けるか。書けない決まりは、どの部品が要るか（★一例の定数を持ち込む形でなく、「何を測る部品か」の形で）。

### Q6 — 作り直しの方向（§ 案 への答え）

§ 案（起案 CC の書き直し＝M2-12・M2-13・M2-11-0）は、Q1〜Q5 の答えに照らして、**効く判定を engine_tuner が見つける道になるか。名ばかりの行・欠けている行・順番の誤りを断言する。**
