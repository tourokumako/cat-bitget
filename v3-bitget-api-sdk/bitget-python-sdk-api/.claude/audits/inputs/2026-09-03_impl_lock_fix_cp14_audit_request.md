## 監査観点 (本監査固有・Q1〜Q7)

### Q1 — 14件は、主張どおりに直っているか

**1件ずつ、実物のコードを開いて確かめること。**主張と実物が食い違う件があれば、その件数と中身を挙げる。**「直っている」と書くなら、その根拠となる行番号と逐語を添えること。**

### Q2 — 抜け道は、実際に減ったか

cp13 は抜け道を **18件**（うち17件を実測で再現）挙げた。**同じ厳しさで数え直し、いま何件 残っているかを実測で示すこと。**cp13 の18件それぞれについて「塞がった／残っている／別の形になった」を判定すること。**新しく生まれた抜け道が無いかも見ること。**

### Q3 — 起案 CC は、cp13 の P-2 を繰り返していないか

cp13 の P-2＝「自分の作ったものを、自分の作った検査に掛けた結果を貼っていない」。**データ2 の主張（実際に走る経路で確かめた）が、現物で再現するかを確かめること。**特に次の2点：

1. `RESULT: PASS` は、**照合A〜D が実際に走った結果**か。それとも途中で止まって出た表示か。
2. 起案 CC が「関数を直接 呼ぶテスト」で済ませた件が残っていないか。

### Q4 — 既存を壊していないか

データ3 を現物で確かめること。**特に、承認済みの控えを全件 走らせ、HEAD（今回の変更の前）と比べて結果が変わった件数を実測すること。**

### Q5 — 「まだ直していない」の申告（データ5）に、漏れは無いか

cp13 の Q5 は「残る穴の申告が5件しか書かれていない」と指摘した。**今回の申告3件に漏れが無いかを、実測した抜け道の一覧と突き合わせて判定すること。**

### Q6 — 目的に対して有効か

**この強制は「設計書に書いたとおりにしか実装できなくする」ことを目的にしている。**いまの実装が、その目的にどこまで届いているかを、外部の基準（下の外部検索要請）に照らして判定すること。**cp13 は「業界の最下層（参照の存在確認）にとどまる」と判定した。その位置づけが変わったかどうかを示すこと。**

### Q7 — 汎用性の高い強制になっているか（★まこさんの決定に直接あたる）

**まこさんの決定（2026-09-02）＝この強制は「今回の内容限定ではなく、今後すべてに対して、汎用的なもの」であること。**

**次の5つを、実物に照らして1つずつ判定すること。**

1. **いまの実装のうち、どの部分が「どの設計書にも効く」か**（＝強制の枠組み）。件数と、その根拠。
2. **どの部分が条件つきか**（＝何と照らすか。正本のファイルが在るものにしか効かない部分）。**条件つきのものは、条件が満たされないときに何が起きるかも書くこと**（黙って通るのか、止まるのか、件数に数えられるのか）。
3. **どの部分が「今回の設計にしか効かない」か。**在れば名指しすること。**無ければ「無い」と断言すること。**
4. cp13 の §6-A-2 は「**入れ物**（A-1・A-2・A-3・A-5・A-6・A-7・A-8）＝完全に汎用 ／ **中身**（A-4 と 6-A-1）＝正本が在るものにだけ効く」と判定した。**この判定が、いまの実装で変わったかどうかを示すこと。**
5. **次に書く設計書（`gen_indicator_switch.py` を直す M2-C-2 のやり直し）に、この強制がそのまま効くか。**効かない部分が在れば名指しすること。

**★「汎用だ」と書くなら、今回の設計書とは別の設計書（承認済みの控えなど）に対して実際に走らせた結果を根拠にすること。**今回の設計書1本で通ったことを、汎用の根拠にしないこと。
