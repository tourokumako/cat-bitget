## 監査観点 (本監査固有・Q1-Q6)

### Q1 — 設計書の「やること」が、全部 実装に入っているか

設計書 §3 の やること1〜5（1-a から 1-i・2-a から 2-c・3・4・5）を1件ずつ、**実物のコードを開いて**確かめること。**入っていないものが在れば、その番号と、実物のどこを見て判定したかを書くこと。**

### Q2 — 実装に、設計書に書いていないものが混ざっていないか

`git diff` を読み、設計書の やること に対応しない変更が在れば全部 挙げること。**とくに、CC がテストのために一時的に壊して戻した箇所が、本当に元に戻っているか**（CC の申告＝「印を探して0件」）。

### Q3 — CC が出した実測の数字は、実物と合っているか

データセット2 の14件を、監査者が**自分で数え直す**こと。合わない数字が在れば、CC の数字と監査者の数字を並べて出すこと。

### Q4 — 「埋まらなかった3件」は、本当に埋められないのか

データセット3 の3件について、**別の方法で確かめられないか**を検討すること。とくに次の2点。
- 5・T-d（前処理の道が通るか）＝engine_tuner を走らせずに確かめる方法は無いか
- T-e（需給の被覆）＝検査5 を通さずに `load_demand` の被覆を出す方法は無いか

**「CC の言うとおり無理」と判断する場合も、その根拠を実物で示すこと。**

### Q5 — 「作ってはいけないもの」に当たっていないか（とくに3番）

`engine_tuner_requirements.md` の「⛔⛔ 作ってはいけないもの」3件と照合すること。**とくに3番（既存の判定のコピー機）**＝今回 足した「ATR に連動する帯の許容幅」が、RG-v6 の判定を写したものになっていないか。

**照合の材料**＝`false_positive_incident_policy.md` §3 の #23（RG-v6 の再現を目的にした監査の出し方＝まこさんが「既存のレンジ判定のコピー作ってもしょうがないじゃん」と却下した事案）。

**CC の主張**＝「入れたのは『許容幅が値段の固定の割合ではなく、そのときの値動きの幅に連動する』という形だけで、RG-v6 の帯の定数（窓168h・束ね幅0.3%・スイング数2・幅0.4%）は1つも持ち込んでいない」。**この主張が実物と合っているかを確かめること。**
