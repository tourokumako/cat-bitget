## この監査は何のためか

**M2-C でオンにした指標のうち、教科書どおりの作りでないものを全部 見つけるため。**

2026-10-03 に、材料のカタログの指標の一部（pivot・POC/VAH/VAL・VWAP・S-Rタッチ数ほか）を、起案者（CC）が教科書と違う作り（移動窓・近似・決め打ちの数字）にしていたと分かった。参照表に「流儀に注意」「近似」と注記だけ書き、変えた理由は計算の楽さ・形をそろえる・理由なし、で、精度や net のために変えた記録は1件も無かった（worklog 20261003 §38・§39）。起案者は語で探しただけなので、ほかにもあるかが分からない。

engine_tuner は、この材料から条件を組む。材料の作りが目的に反する変更をしていると、engine_tuner がどう組んでも良い条件は見つからない。

**まこさんが決めた判断の基準（2026-10-03）**
1. 判断の目的は engine_tuner の目的（恒久の決まり §1＝「net利益を最大化させる条件（指標、閾値、時間、パラメータ）の組み合わせを、見つけることができる機械を作ること」）。**指標はレンジの判定だけでなく、上げ・下げ・急な値動きの判定、Entry と Exit の条件にも使うので、レンジに限って判断しない。**
2. **教科書と違っても、目的に貢献する変更は残してよい**（例＝値段で割って%にする＝要件 H6＝BTC の値段の高さに左右されない）。**直すのは、目的に反する変更。**
3. 判定するのは指標そのものの良し悪しではなく、**教科書から変えた中身（変更）**。指標そのものが役に立つかは、engine_tuner が選ぶ。

## 監査観点 (本監査固有・Q1-Q2)

### Q1 — オンの143のうち、教科書と違う作りはどれか（優先度 A）

**優先度の理由**＝見つけ漏れがあると、目的に反する作りが材料に残り、engine_tuner がどう組んでも良い条件を見つけられない。

2. 違いを全部 挙げる。違いの中身は「期間（移動窓か・期間で区切るか）・平滑のしかた・近似・決め打ちの数字・自作（教科書に無い）・符号や向き・未来のデータ」のどれかで書く。
3. 外部のライブラリ ta と照らしている登録がどれで、照らしていないものがどれかを数える。
4. 起案者が見つけた分（上の表）のほかに見つかったものを、別に数える。

### Q2 — 見つけたそれぞれの変更は、engine_tuner の目的に貢献するか・反するか（優先度 A）

**優先度の理由**＝直すのは目的に反する変更だけ（まこさん決定）。判定を間違えると、要る変更を消すか、反する変更を残す。

1. Q1 で見つけた変更ごとに「貢献する変更（残す）／反する変更（直す）／分からない（教科書の作りと変えた作りを比べて決める）」に分け、理由を書く。基準は engine_tuner の目的だけ。場面の判定（レンジ・上げ・下げ・急な値動き）・Entry・Exit のどれに使うかを考え、レンジに限って判断しない。教科書どおりかどうかは基準にしない。
2. 起案者の判定（上の表）が正しいかを判定する。
3. 「分からない」にしたものは、比べるときに何を比べればよいか（教科書の作りと変えた作りの、どの数字を並べるか）を書く。
4. 未来のデータを使う作りを見つけたら、目的に関係なく Critical にする。

直す範囲は まこさんが結果ファイルを見て決める。修正は重さの見出し（「### Critical」「### Major」「### Minor」「### Process」）の下に並べる。1件は次の形。

```text
### Critical

#### 修正 <番号>
対象のファイル: <リポジトリの中のパス>
直す箇所: <監査が読んだ時点の行番号の範囲>
直す前の文字:
~~~
<実物から1文字も変えずに写す>
~~~
直した後の文字:
~~~
<そのまま当てられる全文>
~~~
根拠の抜き書き: <ファイル名>:<行番号>「<その行の逐語>」
状態: <確定 / 未決 / 案が複数 のどれか>
```

- 対象のファイルは1件に1つ。
- 4の欄の見出しは「直した後の文字／足す文字／消す文字／走らせるコマンド」から1つ。
- 状態は「確定」「未決」「案が複数」の3つだけ。「分からない」に分けた指標の比べ方は「未決」で書く。
