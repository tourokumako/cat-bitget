## 監査対象の事実データ

### 1. R3 の設計（起案 CC が提出したもの・要約）

768列（指標96種 × 時間足8種）を平らに並べず、**役割を持たせた4つの部品に分け、違う部品から1つずつ取って重ねる**。

| 部品 | 役割 | 使う系統 | 使う時間足 |
|---|---|---|---|
| 環境認識 | いま逆張りしてよい地合いか | トレンド系（ADX・DI差・MACD・EMA傾き・close vs EMA/SMA） | 1h・2h・4h・6h・1d |
| トリガー | 建てる瞬間 | オシレーター系（RSI・Stoch・zscore・BB%b・RCI） | 5m・15m |
| 十分性 | 手数料を超える値幅があるか | ボラと出来高（ATR%・BB幅・realized_vol・Donchian幅・volume_ratio・MFI・CMF） | 15m・30m・1h |
| 位置 | レンジのどこにいるか | 構造（S/Rタッチ数・swing距離・高安からの距離・fib位置・POC/VAH/VAL） | 5m・15m・1h |

あわせて: 指標カタログは observe_diag から借りる（正本を2つにしない）／指標の形は水準だけでなく傾きとクロスも扱う／Entry と Exit をセットで動かし、いまの出口に無い「失速切り」「ピーク反転切り」の2枝を足す／閾値は値決め窓の分布の分位から決める（手打ちしない）。

### 2. R7 の設計（同・要約）

1試行は実測でおよそ7秒。全組み合わせは物理的に試せない。

- ① 落とすのは**値が無い列だけ**（値決め窓で半分以上が欠損）。効かなそうな列を単軸の成績で落とさない（組み合わせで効く列が消えるため）。
- ② 似た動きの列は**捨てずに束ねる**。代表1本で探索し、良ければ同グループの他の列でも試し直す。
- ③ **多重検定の補正を入れる**（DSR / PBO・道具は archive/dsr_pbo.py にある）。
- ④ **最良を1つだけ選ばない**。上位複数を残して確認窓で並べる。
- ⑤ 段ごとに 試行数・所要時間・落とした本数と理由 を機械出力（黙って切り捨てない）。
- ⑥ 並列で回す。時間の目標は1回30分以内（まこさん「2時間は長い」）。

### 3. CC が外した6項目（最初の案・すべて既存文書に書かれていた）

| 抜けていた点 | どこに書いてあったか |
|---|---|
| 系統を無視した総当たり（コンフルエンスは違う系統を重ねるから効く） | technical KB §2.3／§2.4（V9 P3 の3系統 AND） |
| 時間足を対等に並べた（上位足＝環境認識・下位足＝タイミング） | technical KB §2.1 |
| 多重検定の補正が無い | cat_requirements §4.6 H11（DSR>0.95／PBO<0.5） |
| 最良を1つだけ選ぶ前提 | （外部＝arXiv 2602.10785） |

| Entry だけ見て Exit とセットにしなかった | L-285／entry_exit_matrix ⚠️使い方 |

### 4. 制約（設計が守らねばならないもの）

- 採点窓（2026-03-01〜2026-06-30）を探索・選定に使わない（L-267）。値決めは 2024-04-01〜2024-07-31 のみ。確認窓 2025-12-01〜2026-02-28 は**表示のみで選び直し禁止**。

- 疑似シミュを使わない＝毎試行 実エンジンを回す（L-330＝疑似シミュの順位は実走で入れ替わる実証あり）。
- 予算 0.12 BTC は全採用戦略の共有枠（H1）。leak なし（H2）。
- E37 はスキャル＝件数/日 5 が絶対下限（§8.6）。件数を減らして net を作る形は却下。

## 監査観点 (本監査固有・Q0〜Q8)

### Q0 — ★そもそも要件が目的に対して適切か（設計より先に、ここを問う）

**設計が良くても、要件が的外れなら意味がない。だからここを最初に見る。**

engine_tuner の目的は2つ（まこさん確定 2026-07-27・逐語・正本＝engine_tuner.py の説明文）:

1. 新規で Entry/Exit ロジックを構築する際に、**設定した戦略や条件に沿った、指標・閾値・時間足・パラメータの組み合わせロジックを見つけ、利益最大化・損失最小化するまで調整する**
2. 既存 Entry/Exit に対しては、**目標達成するために改善すべき点を見つけ、利益最大化・損失最小化するまで調整する**

要件は12件ある（R1 既存ロジックも調整／R2 グリッド売買／R3 あらゆる組み合わせ／R4 戦略を外から渡す［完了］／R5 レンジ以外の相場／R6 保有上限をデイトレへ／R7 現実の時間／R8 何を最大化し何を最小化するか［完了］／R9 値を設定ファイルへ書き戻す／R10 診断結果の受け取り方／R11 役割から件数の下限／R12 途中から再開）。詳細は `.claude/ratchet/engine_tuner_requirements.md`。

以下の3つに答えよ。

- **(a) 要件12件は、この目的2つを満たすのに過不足ないか。** 目的にあって要件に無いものは何か。逆に、目的に紐づかない要件はあるか。⚠️ 特に目的1の「**調整しきる**」と目的2の「**改善すべき点を見つける**」が、どの要件で担保されているかを1つずつ対応づけよ。対応づかない目的が残るなら、それが抜けている要件である。
- **(b) R3 と R7 を最優先で着手するのは正しいか。** 12件のうち、目的の達成に対してより効く要件が他に無いか。順序を変えるべきなら、理由と共に示せ。⚠️ 起案 CC は「R3 と R7 は切り離せない」という理由でこの2件を選んだが、その判断自体が正しいかを評価せよ。
- **(c) R3・R7 の受け入れ条件（「何ができたら満たしたと言えるか」）は、目的を満たすのに十分か。** R3 の受け入れ条件は「entry_exit_matrix の軸カタログの範囲を、指標 × 時間足 × 閾値 × 上下どちら側か の形で扱えること／使える列の数が機械出力で出ること／Entry と Exit をセットで探せること」。R7 は「段階的に絞る手順が決まっていて、各段の所要時間が機械出力で出ること／絞ったときに何を落としたかが出ること」。**これを満たしても目的に届かない穴があるなら指摘せよ。**

⚠️ 要件そのものの追加・削除・順序変更を提案してよい（まこさんが最終判断する）。ただし決着済みの決定は蒸し返さない（E36 の対象外・窓の選定）。

### Q1 — 4部品への分け方は妥当か

「環境認識・トリガー・十分性・位置」の4分割は、コンフルエンスの業界標準（トレンド系＋オシレーター系＋ボラ系の相互補完）と整合するか。**足りない部品は無いか**（例＝需給・オーダーフロー／時間帯や曜日／建玉と玉間の状態／相関資産）。逆に**不要な部品は無いか**。E38 はレンジの逆張りで方向が場所で決まるため「方向を当てる部品」を置いていないが、この判断は妥当か。

### Q2 — 時間足の割り当ては妥当か

環境認識に 1h〜1d、トリガーに 5m・15m、十分性に 15m〜1h、位置に 5m〜1h を割り当てている。**スキャル（保有5〜60分）の戦略で、1d の指標を環境認識に使うことは意味があるか**。逆に、トリガーに 30m 以上を使う場面は無いか。MTF の業界標準（上位足で環境・下位足でタイミング）から見て過不足を指摘せよ。

### Q3 — 指標の「形」の扱いは十分か

設計は「水準・傾き・クロス」の3つを扱うとしている。**業界標準の使い方で抜けているものは無いか**（例＝ダイバージェンス／2本以上の指標間の関係／同じ指標の複数期間の関係／閾値の連続的な帯／状態の継続時間）。

### Q4 — 多重検定の扱いは十分か

設計は DSR と PBO を使うとしている。**探索が Optuna（TPE）で有望領域を掘る形である場合、独立試行を前提とする補正が適用可能か**。適用に条件があるなら明示せよ。White の Reality Check・偽発見率制御（DFDR）など、この設計により適した手法があるなら提案せよ。**「試行数 N」をどう数えるべきか**（Optuna の trial 数か、実質的な探索空間の大きさか）も答えよ。

### Q5 — 「単軸で落とさない」は実務として成立するか

設計は「効かなそうな列を単軸の成績で落とさない」としている。理由は「組み合わせで効く列が消えるため」。**この判断は正しいか。** 正しい場合、現実的な試行数に収める方法として何が業界標準か（例＝グループ化・階層的探索・ランダムサーチ・遺伝的アルゴリズム・ベイズ最適化の使い分け）。**1試行7秒・目標30分（≒約1,500試行を6並列なら約8,600試行相当）という制約で、768列 × 4部品の空間をどう扱うのが妥当か**、具体的に示せ。

### Q6 — Entry と Exit をセットで探す設計になっているか

設計は「Entry の組み合わせと Exit の値を同じ試行で動かす」としている。ただし **Exit の枝は「失速切り」「ピーク反転切り」の2つを足すだけで、これは V9 から選んだ2枝にすぎない**（起案 CC の自己申告）。entry_exit_matrix の X-a〜X-k のカタログ全体から、**レンジのスキャルに適した枝が他に無いか**を指摘せよ。⚠️ **V9 は下げトレンドの SHORT で稼いだ実装であり、レンジのスキャルとは役割が違う。V9 の枝をそのまま持ってくることの是非を評価せよ。**

### Q7 — 起案 CC の思考の偏りが残っていないか（観点⑦）

起案 CC は同じセッションで4回誤りを出した（浅い案／丸投げ／V9 の要約の誤り2点）。**書き直した設計に、同じ型の偏りが残っていないか**を見よ。特に:
- 技術的な最適化問題への翻訳（トレード設計の問題として見ていない）
- 検証していない引用（文書の要約を実装の事実として扱う）
- カタログの一部だけを名指しして「これで網羅した」とする矮小化

該当があれば、設計のどの記述がそれかを**逐語で引用**して指摘せよ。

### Q8 — この設計で「まこさんが検証できる状態」になるか

まこさんは ML/トレードの全知見を持たず、提案を1件ずつ検証できない。**設計の出力（何が機械で出るか）が、まこさんが判断するのに足りるか**を評価せよ。足りない場合、何を機械出力に足すべきか具体的に示せ。
