- SLSA v1.0 Security levels <https://slsa.dev/spec/v1.0/levels>
  逐語: Build L1 の provenance は ***"Can be used to prevent mistakes but is trivial to bypass or forge."*** ／ Build L2 は ***"Builds run on a hosted platform that generates and signs the provenance."***
  → **当てはめ**＝判定の道具・印・記録・hook が全部 CC の手の中に在る（実測で3経路）＝**L1 未満**。J-1〜J-3 を直しても置き場所は変わらない。CC が書けない実行の主体が記録を作って署名しない限り閉じない。

**4｜文法だけを確かめる操作（`bash -n`）が本当に副作用を持たないか（§データ7 の 1b・J-1）**

- GNU Bash Manual — Command Substitution <https://www.gnu.org/software/bash/manual/html_node/Command-Substitution.html>
  要旨（逐語を含む）: command substitution の *"side effects … take effect immediately in the current execution environment"*。`-n`（noexec）はコマンドを読むが実行しない。**ただし `bash -c '<コマンド>' -n` の `-n` は $0 になるだけで、`-c` の中身は実行される。**
  → **当てはめ**＝「文法の確認は実行しないから安全」という例外の前提が、`-c` と一緒に使われると崩れる。実測＝`bash -c "echo PROVEN > /tmp/…" -n` でファイルが作られた。
