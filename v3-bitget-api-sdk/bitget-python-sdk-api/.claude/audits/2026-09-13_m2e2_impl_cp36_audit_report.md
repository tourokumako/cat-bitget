# 10. 外部検索（依頼書 §8・WebSearch／WebFetch・読む側の Plan agent が実施）

1. **mutation testing の判定の基準**
   - killed の定義＝"If the result of running p' is different from the result of running p for any test case in T, then the mutant p' is said to be 'killed', otherwise it is said to have 'survived'."（Mutation Testing Repository, uni.lu ／ https://mutationtesting.uni.lu/theory.php）
   - mutation score＝"the ratio of the number of killed mutants over the total number of non-equivalent mutants."（同上）
   - equivalent mutant＝"syntactically different but functionally equivalent to the original program" ／ "Automatically detecting equivalent mutants is impossible"（同上）
   - 「壊したら落ちた」だけでは足りない＝落ちた理由がその test のものでなければ killed の証拠にならない（arXiv 1803.07901 "Selecting Fault Revealing Mutants" ／ UT Dallas SE6367 講義資料）。
   - 実務上の限界＝実行コストと equivalent mutant（SpringerPlus 2013 ／ SFU CMPT 275）。
   - **当てはめ**＝AUDIT-8（EXPECT_MSG）はこの線に合う考え方だが、9本で照合が効いていない（M-2）。#1 は mutant（法則の書き替え）に対応する test が無い＝mutation score を出せない（C-3）。§1-3 (i)・(iii) は「survived mutant」＝守りが無い実証。
2. **AST で乱数・定数の直書きを検出する限界**
   - "Function name is a string; static analysis can't resolve the actual call" ／ Meta Pysa "There are endless pathological examples of flows of data that Pysa cannot detect."（raven.io ／ https://raven.io/blog/why-static-analysis-falls-short-in-dynamic-programming-languages）
   - "For APIs that are instance methods of classes, identifying them in dynamically typed languages is an open problem"（arXiv 2002.01139）
   - Python の dynamic dispatch・first-class function・monkey patching が静的解析を阻む（PyFlow arXiv 2608.07026 ／ CEUR Vol-2508）
   - **当てはめ**＝`count_builder_literals.py` は名前一致（:56〜58）。別名の生成器・範囲外の関数経由・文字列に混ぜた番号は検出しない（別枠 S-2・S-1）。振る舞いの検査（T24②・T24⑥②）で補う形は正しいが、T24⑥② は1本目の stage1 だけを2回 作る（:6206・:6218）。
