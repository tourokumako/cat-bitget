### Q7 実装可能性と検収 — 手法は業界整合／**改善余地 4件（うち恒等検収の不成立が Critical）**

**§8-1 の実例（現行 S2 の書き写し）を e38_logic_parts.py と紙上で突き合わせた結果: 現形式の情報だけでは md5 一致は達成できない。根拠4点:**

1. **レンジ幾何列がカタログ未登録＝G6 により恒等レシピは生成すら拒否される。** S2 の入口は `pos = (c[i] − mid[i]) / (res_hi[i] − mid[i]) ≥ pos_min`（e38_logic_parts.py L95-99）。res_hi/mid は RG ゾーンビルダーの出力列で、indicator_reference_diag の105種×8足に無い。設計書は「location: fib位置 ≥ q」（L173）と書き写すが、fib位置（n本高安レンジ内位置・カタログ実在）は**別の式**＝値が一致せず md5 は一致しない。
2. **分位格子では S2 の生値閾値に一致させられない。** S2 の pos_min・th_roc24_2h 等は生値。q05刻みの格子（L95）は任意の生値を表現できない。恒等には「値決め窓分布からの連続分位の逆算」か「レガシー名前つき定数」が要るが、どちらも設計に無い。
3. **枝に価格水準のフィールドが無い。** 枝は fire/exec/scope/size_ratio のみ（§6 L139-144）。S2 の TP1/TP2 は**特定価格に事前に置く resting maker 指値**（バー内約定・H5）。バー確定時に評価する fire 条件木では「どの価格に指値を置くか」が表現できず、約定タイミングと価格が変わる。R13 枝一覧の第1行「固定の利確＝建値から固定％、またはレンジの幾何」（requirements L426）を書くフィールドが存在しない。
4. **エントリー執行仕様（指値オフセット close×(1∓0.0001)・TTL3・post_only）がレシピに無い。** H5 のグローバル定数で賄う意図なら成立するが、形式文書に明記が無く実装者裁量になる。

補足: S2 のトリガ（stoch_dc＝`k[i-1] ≥ d[i-1] and k[i] < d[i]`・L104-106）は形式の cross（2本足）と一致する✅。レンジ判定の参照は meta.regime token（"range_rg5"）で成立する✅が、「レンジの幾何を材料として使う」経路が上記1のとおり欠けている。

業界整合: 恒等検収（既存実装のデータ表現化→出力完全一致）自体は移行の業界標準手法。不成立なのは手法でなく形式のフィールド不足。
