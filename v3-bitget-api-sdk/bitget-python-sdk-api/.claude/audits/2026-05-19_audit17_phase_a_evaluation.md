## ⚠️ 外部基準から見た懸念点

### 懸念 1（最重要・発注前に修正必須）: 採用判定の複合化が §4b.1 と直接矛盾

**現状**: 発注書「軸 2-3: 採用判定方式の複合化」の記述:
> 「test 期間の一部（OOS 確認）で逆行していないか」を Exit 採用判定基準に含める

**問題**: `phase_compliance_checklist.md §4b.1` は「cluster_best_exit 選定は train PnL のみ（test 2025 PnL 禁止）」と明文規定している。test を見てから Exit type を採用・除外することは `false_positive_incident_policy.md §0-1`「test 結果を見て決めたパラメータ」の禁止に直接抵触し、類型 B（バックテスト固有のトリック）に該当する。発注書がこの正本違反を含んだまま CC に渡ると、Phase 4-b の全出力が §4b.1 違反として無効化リスクを持つ。

**修正の方向性**: 採用判定の test 使用を削除し「train PnL + train Sharpe のみ」に限定する。test での逆行確認は Phase 5 Replay の**事後評価**でのみ実施（採用判定への使用禁止）。発注書の該当箇所を修正してから GO。

---

### 懸念 2（重要）: -$985 → 全月 ≥$1,900 の逆転は 4 軸で構造的に届かない可能性

**現状**: 発注書の Phase A 目標:
> 「Phase A 実行後の Phase 5 月次 NET で: 全 12 ヶ月 ≥ $1,900 → Phase 6 (本テスト) へ」

**問題（数値根拠）**: audit#16 確定データより、前回強い 4 combo 合計 = +$5,177。全月 $1,900 クリアに必要な年間総額 = +$22,800（4.4 倍の拡大）。4 軸の改善効果を最大限見積もっても:
- 軸 1 (no_trade 解消): cap=3/5 で増えるのは「予測強度の低い combo」。LONG 系は前回 +$308（NET の 6.9%）しか貢献していない。LONG 強化経路が 4 軸に存在しない。
- 軸 2 (Exit 拡張): time_exit 代替に trailing や STOCH_REVERSE_EXIT が機能しても、MFE 予測精度が前回と同水準なら TP 水準が外れ続ける（懸念 3 参照）。
- 軸 3 (cluster 拡張): 方向性分類の改善は combo 選定精度を上げるが、損益の絶対値改善への直接寄与は限定的。
- 軸 4 (フラグ追加): feature_importance への貢献は Phase 1 実行後のみ判明。理論上は情報追加だが重複性の問題あり（懸念 5 参照）。

4 軸は「部分改善」として機能する可能性はあるが、「全月逆転」は Phase B/C/D を含む複数ラウンド後に到達できるかどうかの水準である。Phase A を「全月クリア」の合否判定で使うと、4 軸が一定効果を出していても「不合格」と誤診断される構造リスクがある。

**修正の方向性**: Phase A の合格条件を「全月クリア」から「前回比有意改善（例: 半数以上の月がプラス転換 かつ 月次 NET 最良値が前回 $1,265 を超える）」という中間目標に変更することを、まこさんに提案し GO を得てから発注する。「全月クリア」はあくまで大目的であり、Phase A の単独通過条件にすべきかはまこさんの判断。

### 懸念 3（重要）: time_exit 支配の根本原因を「Exit 設計」に帰属させているが「MFE 予測精度不足」の可能性を未診断

**現状**: 軸 2 の問題設定が「trailing 0 件採用 / Exit 種別不足 / 採用判定の単独化」に限定されている。

**問題**: time_exit が 16/19 combo を支配した根本原因として、「MFE 予測水準が低い → TP に届かずタイムアウト → time_exit が最良」という因果経路が未検討。Phase 2 の MFE RMSE・MFE_lift が前回から改善されなければ、Exit 種別を 3 → 11+ に増やしても TP 設定が外れ続け time_exit 支配は変わらない。発注書の Step 4（Phase 2 精度判定）に「前回比 MFE 予測精度の改善確認」が合否分岐として記載されていない。

**修正の方向性**: Step 4（Phase 2 精度判定）完了時に「前回比 RMSE・MFE_lift の改善確認」を必須 CP とし、改善がなければ Step 6（Phase 4-b Exit 再設計）の前に原因診断（MFE 予測精度不足 vs Exit 設計問題）を分岐として明示する。

---

### 懸念 4（要修正）: cap=3 / cap=5 の選定に数値根拠がない（ガード G 違反候補）

**現状**: 発注書「軸 1: B-8 cap 設計」:
> 「cap=∞（前回）/ cap=3 / cap=5 の 3 案を Phase 5 で比較」

**問題**: なぜ cap=2 でも cap=4 でも cap=7 でもなく cap=3 / cap=5 なのか、発注書に根拠が記載されていない。前回 replay_entries（10,686 トレード・audit#16 確認済み）から K96 LONG 切り捨て後の同時発火数分布を集計すれば、「cap=N で no_trade を何%削減できるか」の数値根拠が出る。恣意的な 2 点比較は発注書末尾「全パラメータ・閾値はデータ駆動で決定（ガード G）」と矛盾し、類型 C（多重検定・過剰最適化）のリスクを持つ。

**修正の方向性**: 発注前に前回 replay_entries CSV から同時発火数分布を集計し、cap の選択肢を数値根拠で決定する（例: 「同時発火中央値が N なのでcap=N±1 を探索」）。あるいは cap を連続探索（cap=2〜8 の全探索）とし、特定値を事前指定しない設計に変更する。

### 懸念 5: 軸 4 フラグの ML 有効性に 2 つの理論的問題（未決定・Phase 1 後に判明）

**問題**:
(a) 1,432 指標の中に既に MACD / Stoch / RSI 等の生値が含まれている。`is_p1_macd_golden`（MACD GC）は既存指標の組合せをブール化したもの。LightGBM は非線形変換を自分で学習できるため、既存指標から同等のパターンを既に捉えている可能性がある。フラグ追加が「既知情報の再整形」に留まるなら feature_importance への貢献は限定的。
(b) 発注書「Prime Directive verify: 各フラグ列の計算が推論時点 t で因果取得可能か 1 行ずつ宣言」の記述があるが、フラグが TOP20 に入らなかった場合の判断フロー（「→ 軸 4 は効果なし → Phase B で別軸へ」等）が発注書に空白。

**修正の方向性**: Step 3 完了時の CP1 に「軸 4 フラグの TOP20 出現数を確認し、0 件なら軸 4 の有効性に疑問を記録する」分岐を明示する。また、既存 1,432 指標との重複性についての理論的前提を発注書に一行記載する（例:「生値の非線形組合せを学習済みモデルに対してフラグ形式で再投入することで注意機構を明示化する、という設計意図」等）。

---

### 懸念 6: 「1 日以内」が物理的見積もりと乖離（スコープ過小評価リスク）

**数値根拠（推定）**:
- Phase 0 再生成（1,432 + 40 列）: 30〜90 分
- Phase 1 LightGBM 16 ラベル（約 394,753 行 × 1,472 列）: 80〜240 分
- Phase 4-a クラスタリング: 10〜30 分
- Phase 4-b Exit 再設計（11 種 × cluster × K × side 探索）: 60〜240 分
- Phase 5 Replay × 3 案: 90〜180 分
- 合計（楽観 4.3 時間〜悲観 13 時間）

エラー・STOP・CC との確認往復が発生した場合、「1 日以内」は設計上の前提として機能しない。

**修正の方向性**: Step 0 着手前に CC から「所要時間見積もり」を必須報告事項とし、1 日超見込みなら Phase A を Step 1〜3 と Step 4〜7 に分割する（発注書に「1 日超なら Phase 分割を CC が提案」とある点は評価できるが、分割時の中間合格条件が未記載）。

---

### 懸念 7: KMeans k=3 維持の根拠が「継承」のみ・前回 cluster 1 の test 崩壊が未診断

**現状**: 発注書「前提（動かさない）: KMeans k=3 維持（手法・k 値は変更しない）」

**問題**: 前回 cluster 1 は train 192,065 件に対して test 4,707 件（4.5%）と test で崩壊しており、これが時代依存（類型 D）なのか方向性未分類の問題なのかが未診断。軸 3 で 20 次元に拡張しても、元の k=3 設定が test 崩壊の根本原因であれば同じ問題が再現する可能性がある。k=3 維持の根拠が「前回も k=3 だった」というアンカリングに過ぎない場合、外部基準（統計学的クラスタリング選択基準）からは正当化できない。

**修正の方向性**: Phase 4-a 完了時の CP4 に「前回比で cluster の test/train 分布比の改善確認」を必須 CP として追加する。改善がなければ k=4 への変更を検討する分岐を記載する。

3. **【懸念 4 の補完】cap 選定の数値根拠収集**: 前回 replay_entries から同時発火数分布を集計し、cap=3/5 の妥当性を確認（所要 30 分以内・発注書に 1 行追記で対応可能）。

## 🔁 同型バイアス自己点検

- **懸念 3（time_exit 支配の根本原因）**: 「MFE 予測精度不足」という追加仮説は、発注書の軸 2 設定が「Exit 設計問題」として framing しているため、監査エージェントも当初は Exit 設計の問題として評価する傾向があった。framing を外して MFE 予測精度との因果を独立に考えることで追加した。
- **懸念 2（目標逆転の現実性）**: audit#16 の「4.4 倍改善が必要」という確定数値を起点としたため、Web Claude の楽観的設定を踏襲せずに済んだ。ただし「4 軸で届かない」という結論も claude 訓練ベースから来る可能性は排除できない（まこさんが「ML の知識がない私でも思いつくようなことをなぜやらないのか」と言い続けてきた理由がここにある可能性）。
- **懸念 5（フラグの有効性）**: 「既存指標と重複するかもしれない」という指摘は LightGBM の特性に関する训練知識から来ており、実測データなしの推測。フラグが TOP20 に入るかは Phase 1 実行後のみ判明する事実。

## 📝 まこさんへ

懸念 1（採用判定の test 使用）は正本違反として発注前に修正が必要です。残る懸念は「Phase A 単独で全月クリアが到達可能か」という目標設定の問題であり、これはまこさんが「どこまでを Phase A のゴールと定義するか」の最終判断です。4 軸が部分改善として機能することは期待できますが、-$985 から一気に全月 ≥$1,900 への逆転を Phase A の合否基準にすることで、4 軸が実際に効果を出していても「不合格」と判定されるリスクがあります。段階投入の第 1 ラウンドとして何を合格条件にするかは、まこさんの設計思想の問題です。
