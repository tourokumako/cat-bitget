＜見出し＝# やることの表｜工事 ＜工事の名前＞（＜何の工事かを1行で＞）＞

＜★この ひな型の使い方（工事の表には写さない）＞
＜・「＜ ＞」で囲んだ所を、その工事の中身に書き替える。見出しの文字は変えない。＞
＜・「＜見出し＝…＞」の行は、「＜見出し＝」と「＞」を外して、見出しの行として書く。「＜区切りの線＝---＞」の行は、--- だけを書く。＞
＜・出す順＝先に「向きを見る所」（下の ★ の付いた見出し）だけを書いて、まこさんに出す。OK の後で、案（設計書の4番の節から後ろ）を書く。見せた後で目標・範囲・やらないことが変わったら、変わった所を見せ直す。＞
＜・向きを見る所は、engine_tuner の中身を知らない人が読める文で書く。＞
＜・向きを見る所に まこさんの OK をいただいたら、その OK の発言を、発言を写したファイル（逐語のファイル）にして、工事のフォルダに置く。設計書には写さない（2026-10-20 まこさん「外す」）。プログラムは、OK された文の行が設計書から1つも抜けていないかを照らす。＞
＜・どの欄も、「〜か」と問う形で書かない。書くのは、主張・根拠（ファイルと行）・確かめ直すコマンドの3つ。「触らない」「関わらない」「変えません」にも根拠を付ける。判定は監査がする。＞
＜・同じ事を2か所に書かない。書くのは、この表の決まった1か所。ほかの場所へは、設計書を作るプログラムが写す。＞
＜・この ひな型は、engine_tuner（道具）の工事に使う。売買の戦略の設計書には使わない（恒久の決まりの70番）。＞

＜この行は、行の頭を「［手書き］」にして書く＝［手書き］この表は CC が手で書きました。数字や文を、何から書いたか＞
出どころ＝＜まこさんの決定の逐語のファイル・監査の修正の番号・読むもの宣言の OK＞

＜見出し＝### この工事が結ぶ要件と、減らす違い＞

★向きを見る所。この工事のやることの番号（やることリストに行が在る工事だけ）と、結ぶ要件は、プログラムが写す。CC が書くのは、下の3行。どの工事でも書く（道具や検査を直す工事も）。

＜見出し＝### 2-1 何を測るか＞

★向きを見る所。問題そのものを測る行を書く（誤りが通っている事実を、走らせた結果で）。実装の文字が在るかを数えるだけの行にしない。

| 何を測ったか | コマンド | 読み方 |
|---|---|---|
| ＜直す前は出来ない事＞ | ＜走らせるコマンド＞ | ＜直す前の結果と、直した後の結果＞ |

＜見出し＝### 目標＞

★向きを見る所。
| 番号 | 欄 | 中身 |
|---|---|---|
| ① | どの要件のためか | ＜要件はプログラムが写す。その要件との違いを、どこまで減らすかは、上の「この工事が結ぶ要件と、減らす違い」の2行目に書いた文を、プログラムが写す（ここには書かない）＞ |
| ② | 何が出来るようになるか | ＜「直す前は出来ない」＝2-1 の行と、「直した後は出来る」＝7-6 の行の対。向きを見ていただく時点では、2-1 の行の側だけを書く。7-6 の行の側は、案を書いた後に書き足す。当てた後の手順が済んでからしか確かめられない物は、7-6 の行でなく、「出る結果の姿」（4-12）の、後で走らせるコマンドを対にする＞ |
| ③ | net までのつながり | ＜この工事の出力を次に使う、やることリストの行の番号。net を直に測らない段では、途中で測る数字を名指しする。net を直に測る段では、単月ごとの net（全部の採用戦略を合わせた net）で判定するコマンドを書く。通算と平均では判定しない＞ |
| ④ | 無駄だったと分かる物 | ＜見るファイル・コマンド・どの段で見るか。空では出せない＞ |
| ⑤ | 済んだ直後に、②を何で確かめるか | ＜コマンドと読み方＞ |
| ⑥ | この工事が損なう恐れのある要件 | ＜要件定義の番号と、損なう道筋。無いと書くときは、根拠と確かめ直すコマンド＞ |
