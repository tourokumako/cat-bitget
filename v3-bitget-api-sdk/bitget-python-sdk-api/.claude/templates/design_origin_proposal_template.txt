＜★この ひな型の使い方（案には写さない）＞
＜・「＜ ＞」で囲んだ所を、その工事の中身に書き替える。【 】の見出しの文字は変えない。＞
＜・この案を書くのは、やることの表の「向きを見る所」に まこさんの OK をいただいた後。＞
＜・どの欄も、「〜か」と問う形で書かない。書くのは、主張・根拠（ファイルと行）・確かめ直すコマンドの3つ。「触らない」「関わらない」「変えません」「変わりません」にも根拠を付ける。判定は監査がする。＞
＜・［自動］と書いた所は、CC が書かない。設計書を作るプログラムが、置き場（要件定義・やることリスト・法則のファイル・型の表・役割と代表の値の表・実装の指示）から写す。＞
＜・「種類①」＝指標・探索・売買のロジック・設定に触る工事。「種類②」＝検査やプログラムを直す工事。種類は、直すファイルの一覧からプログラムが決める。＞
＜・要件定義との照らしの表（【0-R】）は、案に書かない。索引は、プログラムが作る。＞
＜・この ひな型は、engine_tuner（道具）の工事の案に使う。売買の戦略の設計書には使わない（恒久の決まりの70番）。＞
＜・【4-0】〜【4-18】のうち、その工事に当たらない項目は、見出しのすぐ下の1行目を「非該当＝理由」の形で書く。理由には、根拠（直すファイルの一覧など）を付ける。「種類①の工事では、必ず書く」と書いてある項目は、種類①の工事では非該当にしない。＞

案です（工事 ＜工事の名前＞＝＜何の工事か＞。＜まこさんの決定の逐語＞）。本物のコードには、まだ1文字も書いていません。
