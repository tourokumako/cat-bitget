## 1. ML 知識ベースアップ（L-263 対応・WebSearch 7本＋記事精読3本）
- **objective mismatch**: AUC/勝率は全サンプル同重みで方向の順位だけ測る。net は金額。de Prado は accuracy でなく logloss を推奨（高確信の大外し1件がPnLを壊す）。→ 答えは(a)損失関数に金額(下記)(b)ラベルを実Exitに一致(下記)。
- **Triple Barrier の鉄則**: ラベルを作るバリア＝採点・本番で使うExitと同じでないと学習が的外れ。E10 はこれの違反（ラベルMFE%0.905 vs 実出口TP1.2%）。
- **サンプル重み w=|net|**（AFML §4.6 Return Attribution）: ラベルは符号のまま、重みに|リターン|を渡し大勝ち玉の誤分類を金額比で罰す。E6（全玉同重み→勝率最大化でfat-tail切り）の是正。LightGBM sample_weight で渡す。H15（ラベルは符号）と両立。
- **Meta-labeling**（Entry「TPできるか」はこの型）: 一次=高recall候補生成（固定ルール可）→二次=「実出口でnetプラスか」二値→確率を採否/サイズに。QuantConnect批判=一次二次が同じML/同特徴量だと無効・較正見ずにサイズ化は負け・重複データleak。我々は一次が固定ルール（V9）なので「単純ルールの一次にこそ効く」に整合。
- **fat-tail のサイジング**（de Prado 第10章）: θ足切り（崖）でなく確率→サイズ連続写像（size=2Φ(prob)−1 等）。件数削らず期待値を配分で作る。

## 6. ★4実験で確定した構造知見（次セッション必読）
**P23 は「切る」系レバーが全部負ける**: 入口で切る(E8c−$373)・出口を一発で分ける(E10−$6,006)・保有中に切る(E14−$194)。全て同じ負け方=fat-tail勝ち玉（怖い形を経て反転）を巻き込む。**勝ち筋は「ポジションを減らさず、配分（サイズ）と利確の形で調整する」側だけ**（E13サイズ強弱が唯一勝った+$98.9と整合）。→ 次は E15（部分決済の刻み＝減らさず利確の形を変えるレバー・E0.3機構済・固定等分$338を超えるか＝MLの必要性検証）。

## 7. まこさんの重要発言（次セッションが踏まえる）
- 「サイズ調整は ML 化したかった本丸ではない。手動からMLに切り替えたのはそんな部分のためじゃない」→ サイズは足場。本丸=方針0（閾値/Exit/部分決済刻み/件数増まで net 最大化できる所は全部ML）。
- 「本番データ（建玉の持たせ方）は古いからそこに合わせないで」→ 連続モード（1ポジ一括決済）の古い土俵に縛られない。Bitget準拠（部分決済scale out＋枠空き再add）で進める。地面$925.73は1回目の土俵だが、E15以降は E0.3 機構（部分決済・$338素の土台）へ。
- 「手動ではTimeExitの巨額損失が消せなかったのでMLに期待する。徐々に改善を進めていい」→ TimeExit出血の解消が期待値。E14で保有中捕捉は可能（+$314）と判明したが一発切りでは負け。E15部分決済（伸びない玉を早めに利確で確保）で再挑戦の余地。
