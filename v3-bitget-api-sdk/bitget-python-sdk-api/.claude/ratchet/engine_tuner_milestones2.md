## §2.1 この順番にしている意図

### （1）まとまりの分け方

**決める（A・B）→ 作れるようにする（C・D・E）→ 測る（F）→ 重ねる（G・H）→ 確かめる（I・J）→ 詰める（K・L）→ 残り3つ（M）**

### （2）前のものが無いと次ができない関係

| 段 | 何が要るか |
|---|---|
| **B** | **A が要る**＝正解が変われば、目指す法則も変わる |
| **C** | **A と B が要る**＝正解と法則が、要る部品を決める |
| **D** | **A が要る**＝順位づけは「正解の印をどれだけ当てられるか」で測る（`observe_diag.py`:1602）。**正解が変われば順位が全部 変わる** |
| **E** | **C が要る**＝部品が無いと、法則どおりの形が組めない |
| **F** | **A が要る**＝成績は、正解と照らして出す |
| **G** | **F が要る**＝精度の高いロジックを選んでから重ねる |
| **I** | **C・E が要る**＝部品と実行器を触るので、H2 の検査を走らせ直す |
| **K** | **H が要る**＝形が決まってから値を詰める |
| **L** | **K が要る** |

### （3）承認で止まる番号

**M2-A-4・M2-C・M2-D・M2-E・M2-G・M2-K**（どれも `scripts/priority_rebuild/` を触るので、設計書と まこさんの承認が要ります）。

### （4）★いま見えている迷い所（1件）

**上げの判定を、レンジより先に作る必要があるかもしれません。**

- レンジの条件には「**上げ相場でないこと**」が入ります（法則 R8）。**その相手が「上げの判定」です。**
- **いまは RG-v5 の上げ判定（`rg5_uptrend`）を借りられます。**
- **engine_tuner が自分で組んだ上げの判定を使うなら、上げが先に要ります。**

**＝M2-M は最後に置いたまま、M2-H の時点で判断します。**
