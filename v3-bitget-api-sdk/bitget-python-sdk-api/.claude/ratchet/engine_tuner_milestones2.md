## 3.1 この順番にしている意図

### （1）まとまりの分け方＝道 → 部品 → 材料 → 組む → 見る → net

| まとまり | フェーズ | なぜこのまとまりか |
|---|---|---|
| 道 | M2-1 | 渡す場所が無いと、以降のどれを作っても走らない |
| 部品 | M2-2・M2-3 | この2つが無いと、比べる相手と同じものを組み立てられない |
| 材料 | M2-4 | 5,885列から乱数で引かないため。組む前に絞る |
| 組む | M2-5・M2-6 | 上の3つが揃ってから組む |
| 見る | M2-7 | net の前に絵で見る |
| net | M2-8 | 採否は net |

### （2）前のものが無いと次ができない関係

| # | 関係 |
|---|---|
| 1 | M2-2・M2-3 には M2-1 の道が要る（渡す場所が無いと、足した部品を確かめられない） |
| 2 | **M2-2 が無いと上げの判定を1バーも書けない**（§2.3 の1番＝連続2回で切替／§2.2 の3番＝その部品が0件） |
| 3 | **M2-3 が無いとレンジの判定を1バーも書けない**（§2.2 の4番＝帯の下端が書けない） |
| 4 | M2-5 には M2-2・M2-3・M2-4 が要る（部品と材料が揃う前に組むと乱数と同じ） |
| 5 | **M2-6 は M2-5 のあと**（比べる相手が在る側で仕組みの正しさを確かめてから、無い側へ進む） |
| 6 | M2-7 には M2-5・M2-6 で組んだ判定が要る |
| 7 | M2-8 は最後 |

### （3）承認と hook で止まる所

| フェーズ | 何で止まるか |
|---|---|
| M2-1・M2-2・M2-3 | `engine_tuner_exec.py` は `scripts/priority_rebuild/` の中。受け入れ条件と まこさんの承認が要る |
| M2-2・M2-3・M2-5・M2-6 | 承認済みの型の表と、その ハッシュ値 に効く。まこさんの再承認が要る |
