**★要件の言葉（`title`・`accept`・`state`）は、要件の json からの複写です。私が書き写しません。**
**★毎回 作り直すので、古くなりません。**だから文書に差し込みません。差し込まないので、ハッシュ値で見張る仕組みも要りません。

### 3.3 足す関数（5つ・全部 `verify_design_contract.py`）

| # | 名前 | 何をするか | ★既に在るどの関数と同じ判定か（監査の指摘 P-2） |
|---|---|---|---|
| 1 | `outside_fence_lines(md_text)` | ``` の囲みの中と `>` の引用を外した行を返す | **`extract_block` が内側に持っている判定と同じ。**だから `extract_block` も この関数を呼ぶ形に直す（同じ判定を2か所に作らない） |
| 2 | `requirements_index()` | 要件の json を読み、`{"R17": {title, accept, state}}` を返す。json が無い・壊れているときは例外を投げる（黙って空を返さない） | 同じ判定は無い（新しい） |
| 3 | `extract_requirements(md_text)` | 設計書から要件の番号を取り出す（決まりは §3.4） | 囲みの判定は 1 を呼ぶ |
| 4 | `req_map()` | 要件から見た表と、設計書から見た表のデータを作る | 設計書の一覧は `scan_contracts` を呼ぶ（**二重に足さない**＝`scan_contracts` は `acceptance.md` を最初から含む） |
| 5 | `format_req_map(data)` | 4 のデータを、画面に出す文字列にする | 同じ判定は無い（新しい） |

**コマンドの旗（1つ）**＝`--req-map`。

### 3.4 要件の番号の書き方（★決まりを全部 書きます・監査の指摘 I-4）

| # | 決まり |
|---|---|
| 1 | **目印は `REQUIREMENTS:` の1つだけ**（半角・大文字・コロンも半角）。小文字や全角は目印にしない |
| 2 | **行の先頭に在るものだけを数える**（前に在ってよいのは空白だけ） |
| 3 | **``` の囲みの中と、`>` の引用の行は数えない** |
| 4 | **番号の形は `R` ＋ 半角の数字。**区切りは半角のカンマ。前後の空白は無視する |
| 5 | **同じ設計書に目印の行が2つ以上あれば、番号を全部 合わせる**（和にする） |
| 6 | **同じ番号が2回 出たら、1件に畳む** |
| 7 | **番号が0件のときは「番号なし」として表に出す**（止めない） |
| 8 | **要件に実在しない番号は「要件に無い番号」として表に出す**（止めない） |

**★`REQ_MARK` の値は `"REQUIREMENTS:"`（コロン込み）に統一します。**v1 は本文とコードで食い違っていました（監査の指摘 A-5）。
