## A. これは何か（1行）
v6r で確定した真因（**混合母数そのものが型内ランキングを半減させる**）に対し、**検出器の fit と θ 選定をイベント型ごとに分け、be≥1.0 に届いた型の帯だけを合併して執行する**。イベント5型・OOF 測定系・執行/出口/サイズ・停止ガードは v5/v6 のまま不変。TP-viability（v6r 承認済み部品）は同梱を継続。

## B. 深掘り4点
### ① 真因
検出器母数の混合が型内ランキングを半減させる。v6（二値）vs v6r（net/fee 回帰）の対照実験で「教師の金額非整合」仮説を棄却（q0.95 be0.498→0.508＝物差しを替えても不変）。同頻度対照＝v5 単独母数 top10% **be1.01@3.7イベント/日** vs 混合母数 top5% be0.51@3.6イベント/日（同じ evt_mr 玉を含むのに半減）。新型の教師 2.2倍が学習容量/勾配を占有し型内の細かい序列に容量が回らない（ledger ARC20）。

### ② 期待値分解
- 動かすのは「執行する場面の質」＝執行イベントの平均gross÷往復コスト（be）。**be≥1.0 帯のみ執行**することで1件あたり期待値をプラス側に固定する。
- 件数/日は「帯が立った型の合計」で作る（深いMR 型は v5 で be1.01@3.7イベント/日 実証済み＝型別 fit はこの単独母数 fit の再現構造）。
- TP-viability: TP 目標が手数料床未満の毒（6.5/日・be−2.43）を教師・エンジン双方から機械除去（v6r で実証済み）。

### ③ root か symptom か
**root**。θ 規則（v6 で反転済み）・教師の物差し（v6r で回帰化済み）という symptom 候補は対照実験で消去済み＝残った構造要因（混合母数）への直接対策。型の手動取捨はしない（どの型が使えるかは型別 OOF フロンティアの be≥1.0 判定＝データが決める）。

### ④ ベースアップ（2026-07-04 実施・検索3本/種別2/精読2本）
- **戦略タイプ別の独立メタモデルは業界実践**: Hudson & Thames のメタラベリング検証は、トレンド追従と平均回帰それぞれに独立のランダムフォレスト・メタモデル（特徴量セットも別）を構築。教師が薄い場合はクラス不均衡への対処（アップサンプリング）が必要と指摘。https://hudsonthames.org/does-meta-labeling-add-to-signal-efficacy-triple-barrier-method/
- **MoE（専門家の分業）**: 単一モデルより専門家分割＋ルーティングが汎化に優れる（Sharpe 等で+25%級の報告）。https://arxiv.org/abs/2501.09636 ／ 専門家プール分割（市場全体 vs 業種特化）の設計例 https://arxiv.org/pdf/2510.25091 ／ https://arxiv.org/abs/2411.00782
- **局面別分割の一般論**: 分割の優位は分割の質に依存（過度に複雑な分割は逆効果）＝型は教科書 a-priori の5型のまま増やさない（1変更）。https://arxiv.org/pdf/2601.14031

## E. やること（実装項目・1つずつ照合）
1. e37_range_scalp.py に --v7 追加（**既定 OFF＝v5 恒等**）。
2. TP-viability ゲート（_tp_viable・v6r 実装済み）をイベント候補に適用（教師生成とエンジン執行に同一適用・当該バー close/sma/std のみ＝t 時点因果）。
3. **型別 fit（_fit_detector_per_type）**: イベント型ごとに検出器 LightGBM を独立 fit。教師＝その型のイベントのみ（エンジン同一執行 Triple Barrier・学習窓のみ）・特徴 2603列＋side（label_exclude_assert 適用）・purged 5fold（embargo 1日）で OOF → 学習窓全体で再fit。
4. **型別 θ 選定（_select_theta_per_type）**: 型ごとに学習窓 OOF フロンティア → be≥BE_FLOOR(1.0) を満たす分位のうちイベント/日最大。帯なしの型は不使用。**全型で帯なしなら SystemExit（停止ガード・採点温存）**。
5. 執行: be≥1.0 に届いた型の帯を合併（OR・各イベントは自型の θ で判定）。執行エンジン・出口（TP=SMA∓0.5σ maker／SL=2×ATR maker／60分 TIME taker）・サイズ（0.024・MAX_ADDS=1・サイドごと単一スロット）は v5 不変。
6. 型別ログ: 型ごとの教師件数・正例率・OOF フロンティア・選定 θ・執行帯を stdout＋params_sidecar に記録（lever-bites＝型別寄与の分離）。

## H. 受け入れ判定（判定は score.py・件数＝一級基準）
- 学習窓: 型別 OOF フロンティアで **be≥1.0 帯が1型以上立つ**こと（全型帯なしなら停止ガードが走行を止める＝その事実と型別フロンティアを ledger に記録）。
- precheck: 学習窓 breakeven ≥1.0 PASS。
- 両窓 score.py: E37 地面（マイナス）超え。
- **件数/日を上げる（高頻度＝スキャル役割・合格基準）**: 執行 0件/日（v6/v6r 停止）から be≥1.0 帯の執行で件数を作る。帯が深いMR 型のみに留まった場合は、**件数を上げる次の一手（型の追加＝VP端・ピボット・セッション境界／TF 変種 15m/30m MR で帯の本数を増やす）を ledger 問5 に必ず書き、次 iter で件数を育てる**（黒字帯の頻度の積み上げが本戦略の件数の作り方）。
- **⑦手数料を超える TP 幅（maker 往復）**: TP=SMA∓0.5σ に SCALP_FLOOR 0.08%（maker 往復 0.028% 超）を強制＋TP-viability が entry 時点で幅不足の候補を排除。
- **⑨短保有（分単位）**: 60分 TIME backstop・保有中央 20-30分想定（v5 実測 28-31分・時間単位の保有には戻らない）。
- **⑫5分足設定（RSI9/MTF・technical_kb §4/§5）**: 5m 足ベース・検出器特徴 2603列に rsi_9 各TF・MTF 整合（15m/30m/1h/4h/1d）を含む（v5 重要度 top10 に rci_26__5m・rci_9__15m・body_ratio__1h 等の MTF 実績）。
