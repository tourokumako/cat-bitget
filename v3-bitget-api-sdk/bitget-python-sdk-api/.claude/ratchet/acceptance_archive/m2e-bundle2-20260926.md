### 4-0 この仕組みは何か（全体・一続きの文章で書く）

**この項目に書くこと**＝何を作るのか／どういう流れで動くのか／何ができるようになるのか／完成したとき何が出るのか。★項目に分けない。ここだけ読めば全体が分かる状態にする。★★必ず「なぜこの形にするのか」を、ほかの形と比べた実測の数字で書く（この形を取らなかったら何通り・何時間 掛かるか）。★なぜ必須か＝まこさん指摘 2026-09-10「2-2の設計思想は、総当りで組合わせロジックを出すと数百年かかるので、段ごとに絞り込んでいくという方法ということを、このセッション内で何度も言ってるのに、毎回抜けるから、いい加減にしてほしい」。私は「段＝枠を埋める順番」と読み、「段＝候補を絞る段階」という思想を毎回 落とした。

**この仕組みは、帯の許容幅（サポート・レジスタンスの線に「触れた」と数えるときの線の太さ）を、1時間足の値動きの幅に連動させる部品を正しい形で作り直し、その前に許容幅が上下限に張り付く割合を足ごとに測り、あわせて §2.2 の値の範囲と刻みを出どころつきの表にするものです。**3件を1つの設計書にまとめた理由は、3件とも触るファイルが `observe_diag.py` と `observe_config.json` で同じで、承認を1回にできるためです（まこさん OK 2026-09-24「上記でOK。」）。

**①いま何が起きているか。**帯の部品は、いま `S-Rタッチ数(窓, 許容幅)` だけで、許容幅は 0.0015・0.003・0.006 の固定です（`observe_config.json` の `sr_tol`）。相場の荒れ方が変わっても、線の太さは動きません。2026-09-05 に、許容幅を値動きの幅に連動させる部品（S-RタッチATR）を足しましたが、渡された足の ATR% を使っていました。出どころの逐語は「1時間足の ATR%」です（`observe_config.json` の `sr_tol` の説明に写してある逐語 `tol=clamp(K×ATR%_1h,0.15%,0.6%)`）。5分足の値動きの幅は1時間足より小さいので、倍率 0.5 を掛けると下端 0.15% を割り、許容幅がいつも 0.15% に固定されました。観察の検査12 の実測で、既存の `S-Rタッチ数(288,0.0015)` と相関 +0.9999978（監査 cp22 の N-1）＝同じ列だったので、2026-09-06 に部品から外しました。いまは部品に0件です（監査 cp24 の実測）。

**②どう変えるか。**部品 S-Rタッチ1時間ATR の許容幅を「1時間足の ATR% × 倍率」にし、0.15%〜0.6% に収めます。タッチは、その足の高値・安値で数えます（`_sr_touch` をそのまま使う）。1時間足の ATR% は、1時間足以下の足ではその足のバーを1時間足にまとめ直して作り、1時間足より長い足では列を作る道が置き場 `_H1_BASE` に入れた5分足から作ります。1時間足の値は、その1時間足が閉じた時刻から使います。

**③なぜ全部の時間足で作るのか（ほかの形と比べて）。**部品の関数はその足のバーだけを受け取るので、2時間足より上では1時間足を作れません。型の表は部品を全部の時間足に並べ、外すのは標本不足（禁止3）だけです（`gen_signal_families.py` の `timeframes=tfs`）。実行器は、作れない列に当たると止まります（`engine_tuner_exec.py` の「材料 … をその場で作れなかった」）。だから「2時間足より上では作らない」形にすると、型の表と組む側にも2時間足より上を外す禁止を足す工事が要ります（案A）。まこさんは 2026-09-26 に案B（全部の時間足で作る・1時間足の値動きの幅は5分足から作って部品に渡す）を選びました。なお、禁止3 で窓 288 は2時間足より上、窓 144 は4時間足より上で外れる見込みです（窓 × 足の分 ÷ 1440 日を値決め窓 548日・n_min 30 で割った私の計算・worklog 20260926 の 3-9）。

**④張り付きを先に測る理由。**上下限 0.15%〜0.6% は1時間足で校正した数字です（136番）。その足の ATR% で測ると、5分足では下端に、長い足では上端に張り付く見込みでした。検査16 で、その足の ATR% と1時間足の ATR% の両方の張り付き割合を、足ごとに出します。1時間足の ATR% は、どの足でも同じ1時間足の値を使うので、足ごとの差は小さい見込みです。倍率 1.5 は上端に張り付きやすく、既存の `S-Rタッチ数(n,0.006)` に近づく恐れがあります。張り付いて既存の部品と同じ中身になる倍率が見つかれば、まこさんに出します（まこさん決定 2026-09-26 の①）。

### 4-19 通しの例（最初から最後まで、1件を追いかけた例）

**この項目に書くこと**＝実際の1件が、入口から出口までどう通るか。★読み手が設計を確かめられる唯一の欄。

**通しの例（参照表の既知答えの見本3・窓 144・倍率 1.5・ATR の期間 14）。**数字は私が式から手で計算した値です（走らせた結果ではない）。

1. **データ。**5分足 721本。60時間ぶん、1時間ごとに 100.0 と 100.5 を交互に並べ（1時間の中は平ら）、最後の1本だけ 100.0 です。最後のバーは 60時間ちょうどに始まり、5分後に閉じます。
2. **1時間足の ATR%。**最後のバーが閉じた時刻までに閉じた1時間足は、59時間目に始まり60時間ちょうどに閉じた足（100.5 で閉じる）です。TR は2本目から 0.5 なので、ATR14＝0.5×(1−(13/14)^59)＝約 0.4937、ATR%＝0.4937÷100.5＝約 0.491% です。
3. **許容幅。**倍率 1.5 × 0.491%＝約 0.737% は上端 0.6% を超えるので、0.6% に置き換わります。帯は 100.0±0.6 です。
4. **タッチ。**窓の 144本は 12時間ぶんで、半分（72本）が 100.0、半分（72本）が 100.5 です。100.0 は必ず帯に触れます。100.5 は、安値 100.5 が 100.6 以下なので触れます。数は 144 です。
5. **倍率 1.0 なら。**許容幅は約 0.491%＝帯は 100.0±0.491 で、100.5 は触れません。数は 72 です。
6. **外した形（5分足の ATR%）なら。**1時間の中は平らなので、5分足の TR は1時間に1回だけ 0.5 で、ATR14 は約 0.061、ATR% は約 0.061% です。倍率 1.5 でも約 0.091% で、下端 0.15% に置き換わります。帯は 100.0±0.15 で、100.5 は触れません。数は 72 です＝期待の 144 と違うので、番人 T-A1 が落ちます（壊すプログラム b104 が毎回 これを確かめる）。
7. **4時間足なら。**4時間足のバーからは1時間足を作れないので、`build_features` が置き場に入れた5分足から1時間足を作り、4時間足のバーが閉じた時刻までに閉じた1時間足の ATR% を当てます。置き場が空なら止まり、列は作られません（番人 T-A3 と壊すプログラム b107 が確かめる）。

    for i, t in enumerate(d.index.floor("h")):
