## 2｜なぜ作るか（深掘り4点）

### ① 真因

**レンジの相場の法則10件のうち、審査に効いているのは3件（R1・R7・R8）だけ。**残り7件は「機械が読む判定」を持たないので、破った束がそのまま通る。**さらに、いまの判定の型は「部品が在るか」しか見ない**＝「弱い」「狭い」（側）・「同じ1本で系統と時間足を満たす」（かつ）・「同じ系統を重ねない」・「何本 続いたか」（streak）が書けない。実測＝組む側の30案のうち12案が R3（上位足のゾーン）を破っている（worklog §7（4））。

### ② 期待値分解（勝率／平均利益／敗率／平均損失）

**非該当。この直しは売買を1本も出さない。**net への効き方は間接＝法則 → 審査 → 場面の判定の質 → 入口の選別 → net。

### ③ root か symptom か

**root。**M2-B-3（監査）・M2-B-4（部品を数える）・M2-B-5（満たさない案を捨てる実測）・M2-E（法則から組む）の全部が、10件が読める状態の上に乗る。

### ④ ベースアップ（この設計の前に開いたもの）

**外の新しい検索は使っていない。材料は全部 実物**＝`engine_tuner_exec.py`（1022-1061 の判定の型と鍵・1092-1188 の数えと審査・4230-4325 の G7/B0 の自己検査）／`engine_tuner_gen.py`（2159-2197 の組む側）／`gen_materials.py`（386-393）／`regime_laws.json`（法則50件の形）／`regime_detection_kb.md`（798-811 の 11-2）／`indicator_reference_diag.py`（REFS・FAMILY_LINEAGE・RANGE_GEO_TF）／`regime_r9_diag.py`（1-20）／`gen_regime_kb.py`（462-477）／`materials.md`・`materials.json`・`engine_tuner_milestones.md`・`engine_tuner_milestones2.md`（gen_materials が作る文書）。**実データ**＝5分足の正本 CSV を値決め窓で切り、`material_array` で 1h の材料22本を作って順位相関を測った（worklog 20260830 §7）。
