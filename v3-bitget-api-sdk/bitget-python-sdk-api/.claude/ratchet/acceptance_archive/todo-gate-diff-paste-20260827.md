### 7.2 直す中身（5つ）

|---|---|---|
| 1 | `SHOWN` の中身 | ハッシュ値ではなく**本文**を保存する |
| 2 | 判定 | 前の本文と いまの本文を比べ、**変わった行**を出す。**その行が全部チャットに在れば通す** |
| 3 | 同上 | **4行の型（【いまの工程】【ToDo】【止まっているもの】【次】）は、いまの版の4行がチャットに在ることを毎回 求める** |

### 7.3 「変わった行」の決め方

- **前の本文に無くて、いまの本文に在る行**を、変わった行とします。
- **空の行は数えません。**
- **行の前後の空白は落として比べます。**
- **並べ替えただけの行は、変わった行になりません**（中身が同じなので）。

## §10 限界（正直に書きます）

1. **貼った行が「本当に ToDo の行として」貼られたかは見ません。**返信のどこかに同じ文字が在れば通ります。
2. **消した行は見ません。**行を消しただけなら、何も貼らずに通ります（中身が減る向きなので、害は小さいと考えます）。
3. **前の本文は1つしか持ちません。**2回続けて直すと、直前の版との差分になります。
4. **この hook 自身を書き換えれば無効にできます**（ほかの hook と同じ・`git diff` には必ず出ます）。
5. **最後の関所は まこさんの目です。**
