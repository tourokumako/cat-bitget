**2本目の処理の順番（直した後）。**いま在る A（帯の幅・R7）・E（状態を保つ・C6）・D（向きの否定・R8）・F（持続・R4）は変えません。変えるのは B・C・G の3つの材料の取り方です。

**`stage_keep_of(limits, n)` の決まり。**`stage_keep_range` の `lo`・`hi` を読みます。`hi` が null なら n（その段の候補の本数）。返すのは `hi`（上端）です。`lo` が 1 未満、`hi` が n を超える、`lo` が `hi` を超える、のどれかなら `SampleError` で止めます（fail-closed・数字を作らない）。欄そのものが無ければ、既定＝`lo` 1・`hi` null（いまの設定ファイルの値と同じ）。★なぜ上端を使うか＝この工事では「範囲の中を動かす」ことはしません。動かすのは M2-F（測って並べ替える段）です。上端は「この段で使ってよい候補の本数の上限」として読みます（決めてほしいこと2）。

**`_stage_pick(cands, keep, rank_pos, stage, extra)` の決まり。**`rank_pos` が `keep` を超えたら `SampleError`（文言＝「{stage} の候補の上位 {keep} 本の外（順位 {rank_pos}）」）。`rank_pos` が一覧の本数を超えても `SampleError`。返すのは (cond の深い写し, 記録)。記録の鍵＝rank・col・種類・時間足・label・horizon・分離力・候補の一覧・上位 ＋ extra。

**★向きについて。**帯 B の向き（above／below）は、直す前と同じく案の番号で決まる `side_b` を使います。1本目の一覧の `cond.side`（法則の側・段1 は above）は使いません。理由＝帯は上側でも下側でも跳ね返りを見るもので、両方を試すのが直す前からの承認済みの動き（T24④）です。C と G の側は、1本目が法則から付けた側をそのまま使います（直す前も法則の側でした）。

**★何が変わり、何が変わらないか。**変わる＝B・C・G の材料が「外す時間足を含まない・元データの中・abs 付き」になる。同じ案の番号でも、材料が変わり得ます（一覧の順位が、直す前の順位と同じとは限らないため）。変わらない＝A・D・E・F の作り方、束の形、引いた記録の既存の鍵、乱数0件、法則番号の直書き0件。

## 7｜付録（hook が求める項目）

### 7-1 深掘り4点

**① 真因（root cause）**＝1つです。3つの絞り（外す時間足・元データ・前処理）を1本目（候補の一覧）に入れたとき、2本目（実際の束）はそれを読まず、別の道（法則の系統／family で順位から引く）で材料を取っていました。同じ役目の判定が2か所に在り、片方だけ直りました。設計書（前の版の §4-4 手順2〜4）は「2本目が1本目を呼ぶ」と書いてありましたが、実装は呼びませんでした。それを測る自己テスト（T24⑤・T35）も作られていませんでした（2026-09-11 の私の判断「別の自己テストが既に測っている」が実測で成り立たなかった）。

**② 期待値分解**＝売買のロジックには触れません。勝率・平均利益・敗率・平均損失は、この工事だけでは動きません。動くのは3つです。①実際に組まれる束の帯の枠に10分足が出る本数（監査の実測 200本中78本 → 0本）②向きを持つ指標の強さの否定に abs が付く本数（0本 → その材料が出た全部）③法則を1件 書き替えたときに束が変わることを、機械で測っているか（測っていない → T24⑤ が測る）。

**③ root か symptom か**＝root です。2本目の材料を引く関数に絞りを写して足すだけなら symptom です（次に絞りを足したときに、また片方だけ直ります）。2本目が1本目の一覧を読む形にするので、絞りは1か所にしか在りません。

**④ ベースアップ**＝この工事では外の検索をしていません。使ったのは監査 cp36 が §10 で引いた外部の定義です＝mutation testing の killed の定義「その test が落ちたときだけ killed」（Mutation Testing Repository, uni.lu）。これを T24⑤・T42 の期待の書き方（C4・R3 は「変わらない」を期待に書く／向きを持つ C が出なければ「測れない」で落ちる）と、新設する壊すプログラムの EXPECT_MSG（❌ を含む文字）に使いました。実物は、読むものの宣言の22件を Read tool で開きました（design_read_plan.md・まこさんの OK 2026-09-13「了解。OKなので修正を進めてよい」）。
