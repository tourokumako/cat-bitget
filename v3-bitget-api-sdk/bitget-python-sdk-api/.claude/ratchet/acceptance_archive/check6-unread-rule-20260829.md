# 検査6｜「強制する」と書いてあるのに engine が読んでいない読み込ませる法則を見つける

まこさん承認 2026-08-29（逐語「よい」）。

## 何を作るか

`gen_composition_rules.py` の `check_rules()` の末尾に、**検査6** を1つ足します。

**やること**＝読み込ませる法則30件のうち「機械が強制するか」が true のものについて、**その枠の名前（`scene_rules` など）が engine の本体（`engine_tuner_gen.py` と `engine_tuner_exec.py`）の中に1か所でも出てくるか**を数えます。1か所も出てこなければ **`RuleError` で止めます**（fail-closed）。

## なぜ作るか

### ① 真因

**「設定ファイルに書いてある」と「engine_tuner が読んでいる」を、確かめずに同じものとして扱っていました。**

2026-08-29 に、Q-1（枠 `question_map`）と RD-2（枠 `redundancy`）に「機械が強制する＝true」と書いてあるのに、engine の本体がどちらの枠も1か所も読んでいないことが分かりました。**2026-08-08 に仕分けたときから今日まで、誰も確かめていませんでした。**

**いまの `gen_composition_rules.py` は「機械が強制するか」の欄をそのまま文書に写すだけで、その枠を本体が読んでいるかを見ていません。**

### ② 期待値分解

**この検査は net の数字を直接 動かしません。**動かすのは、そこへ至る途中の正しさです。

「機械が強制する」と書いてあるのに読まれていない法則が在ると、**その法則を破った案が捨てられずに残ります。**残った案の中から net が一番よいものが選ばれるので、**本来 捨てるはずの案が採用される道が開きます。**

いま実際にそうなっていたのは2件（Q-1・RD-2）です。どちらも「同じものを見ている指標を2本 入れない」という内容で、**重なった指標を2本 持つ案が、いままで素通りしていました。**

### ③ root か symptom か

**root です。**今日 見つけた2件を直すだけなら symptom（症状）の手当てです。同じ取り違えは、次に法則を足すときにも起きます。**書いてある内容と実物を毎回 突き合わせる仕組みを入れるのが root の直しです。**

### ④ ベースアップ

**実物を開いて確かめました。**

- `gen_composition_rules.py` の検査1〜5 を読み、`RuleError` で止める形（検査3）と、警告だけ出す形（検査1・2・4・5）の2通りがあることを確かめました。
- `composition_rules.md` と `composition_rules.json` を開き、「機械が強制するか」の欄がそのまま文書に写されていることを確かめました。
- `engine_tuner_gen.py` と `engine_tuner_exec.py` の本文を機械で数え、`question_map` と `redundancy` が **0か所**、`scene_rules` が **10か所**、`roles` が **35か所**、`count_range` が **18か所**であることを実測しました。
