# 設計書｜監査 cp23 の X-7 後半＝承認の機械が表の列数を数える（2026-09-06）

TARGET: .claude/tools/run_breaks.py, .claude/breaks/b31_column_count.sh

（`b31_column_count.sh` は 2026-09-06 に作りました。手本＝`.claude/breaks/b14_breaks_tampered.sh` と `.claude/breaks/lib.sh`）

## 1. 何を作るか

**完成の条件の表を読むとき、見出しと列の数が違う行が在れば止めます。**

いまは、欄の中に生の縦棒（`|`）を書くと列がずれ、**別の欄の文字を「壊すプログラムの名前」として拾います。**それでも止まりません。

## 2. なぜ作るか

**監査 cp23 の X-7 の逐語**＝「完成の条件4 の行に生の `|` を書き、承認の機械が列をずらして読んだ」「あわせて、承認の機械が列数を数えて、想定と違う行を弾くようにする」。

**実際に起きたこと**＝`m2c4-add-parts-20260905.breaks.json` の 24-27行で、`"no": "4"` だけ `"script": "実経路"` になっています（ほかの行は `null`）。**記録に実在しない行が1つ 増えた**ということです。

**2026-09-03 に `\|`（打ち消した縦棒）は列の区切りにしない直しを入れました。**しかし**生の `|` を書いたときは、いまもずれます。**

## 3. 深掘り4点

**① 真因**＝表を読む処理が、行ごとの列の数を1度も数えていません。見出しの列と本文の列がそろっている前提で、番号を決め打ちで取っています。

**② 期待値分解**＝この工事は売買のコードを1行も触りません。**勝率・平均利益・敗率・平均損失のどれも動きません（net への影響はゼロ）。**動くのは「ずれた表で承認が通るかどうか」だけです。

**③ root か symptom か**＝root です。「その1行を直す」（symptom）ではなく、「ずれた表を読ませない」（root）を作ります。

**④ ベースアップ**＝外の資料は使いません。直す中身は監査 cp23 の X-7 の逐語から来ています。

**疑似シミュ（probe）から出た数字を、1つも固定値にしていません。**

- **(a)** この工事で使う数字は、表の列の数（プログラムが数えた結果）だけです。閾値・期間・パラメータを1つも決めていません。
