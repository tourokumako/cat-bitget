## 1｜概要

壊すプログラム（`.claude/breaks/*.sh`）が壊すために探している文字を、プログラムが1本ずつ取り出し、いまのコードに何か所あるかを数えます。0か所なら、その壊すプログラムは何も壊せません（L-605 の b95 と同じ型）。2か所以上なら、どこを壊すかが定まりません。作るものは2つです。①走らせる道具 `run_breaks.py` に、読むだけの口 `--count-targets` を足します。壊すプログラムの中の python の部分を構文の木で読み、`s.replace(探す文字, …)`・`探す文字 not in s`・`s.count(探す文字)`・`re.sub(探す形, …)` の探す文字を取り出して、壊す相手のファイルで数えます。文字で探さない壊すプログラム（入力を変える・json を書き替える）は「数えない」に分けて本数を出します。②承認のプログラム `approve_impl.sh` が、壊すプログラムを走らせる前にこの口を呼び、**その設計書の完成の条件に載っている壊すプログラム**が 0か所・2か所以上なら承認を取り消します（ほかの壊すプログラムの食い違いは画面に出すだけ）。あわせて、土台ゲート `require_acceptance_before_impl.sh` がこの口を私の Bash から通すように1枝 足します（hook の直し）。

**この仕組みは、壊すプログラムが「壊す相手を本当に壊せるか」を、承認の前に機械が数えるものです。**

**いま何が起きているか。**壊すプログラムの多くは、壊す相手のコードの行を文字で探し、別の文字に書き替えてから検査を走らせます。コードの行を直したのに、壊すプログラムの探す文字を直さないと、探す文字が0か所になり、壊すプログラムは何も壊せません。103回目に b95 がこれで rc=0 になりました（L-605）。この設計の途中でも、b52 が同じ状態だと分かりました（2-1 の表）。仕組み1の前半の hook は「直して消える行」しか見ないので、既に消えている探す文字は見つけられません。私が手で grep するのを忘れると、誰も気づきません。

**どう変えるか。**`run_breaks.py --count-targets` が、壊すプログラム92本を1本ずつ開き、中の python の部分（`python3 - "$変数" <<'PYEOF' … PYEOF`）を構文の木で読みます。壊す相手のファイルは、bash の変数（`TIDY="$ROOT/.claude/tools/tidy_next_step.py"` など）と `lib.sh` の変数（ROOT・SDK・PR・VERIFY）から決めます。探す文字は、`s.replace(A, …)` の A・`A not in s` の A・`s.count(A)` の A（A が文字の定数か、定数を入れた変数のとき）と、`re.sub(形, …)` の形です。数えた結果を3つに分けて出します＝①1か所（壊せる）②0か所か2か所以上（壊せない・定まらない）③数えない（文字で探さない・相手を決められない）。

**承認の前に止める。**承認のプログラムは、壊すプログラムを凍結する前にこの口を呼びます。その設計書の完成の条件に載っている壊すプログラムが②なら、承認を取り消します。載っていない壊すプログラムの②は画面に出すだけにします（古い設計書の壊すプログラムで、いまの承認を止めないため）。

**完成したときに出るもの。**`--count-targets` が「1か所 N本 ／ 0か所か2か所以上 M本（名前と探す文字の先頭）／ 数えない K本」を出し、M が1本以上なら rc=1 を返します。いまの実物では b52 が②に出ます。売買のロジックにも審判にも触りません。net はゼロのままです。
