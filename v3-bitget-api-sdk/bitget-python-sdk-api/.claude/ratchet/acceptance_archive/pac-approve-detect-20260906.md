## 1. 何を作るか

**まこさんが `--approve` を打ったかどうかを、承認の印のファイルで確かめます。**

いまは `--verify` が **必ず**「まこさんの承認が済んでいない」を返します。**まこさんが実際に打っても、返ります。**

## 2. なぜ作るか

**この道具は「まこさんが打ったか」を1度も見ていません。**判定は「`rc` が `None` かつ種類が `approve` なら、承認が済んでいない」だけです（`verify_problems`）。

**`rc` が `None` になるのは、その2本を私が打たないからです**（打つのは まこさん）。**＝打っても `None` のままで、永久に「監査に出せません」になります。**

**実測（2026-09-06）**＝まこさんが4行を打ち、型の表と出口の表の承認が済んだ後でも、`--verify` は「承認が済んでいない」を2件 返しました。

## 3. 深掘り4点

**① 真因**＝「私が打たない」ことと「まこさんが打っていない」ことを、同じ `rc=None` で表していました。2つは別のことです。

**② 期待値分解**＝この工事は売買のコードを1行も触りません。**勝率・平均利益・敗率・平均損失のどれも動きません（net への影響はゼロ）。**動くのは「監査に出せるかどうか」の判定だけです。

**③ root か symptom か**＝root です。「今回だけ手で通す」のではなく、**承認の印を見る**形に変えます。

**④ ベースアップ**＝外の資料は使いません。承認の印の名前（`signal_families_approved.txt`・`exit_families_approved.txt`）は、`gen_exit_families.py`:60 と `.claude/ratchet/` の実物から取りました。
