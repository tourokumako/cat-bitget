## 2｜深掘り4点

### ① 真因（root cause）

**engine_tuner が条件に使える材料は「観察の道具が作る列」だけで、そこに無いものは、どれだけ回しても永久に候補に上がらない。**需給3種は観察の道具では列になっているのに、型の表の部品に入る道が無かった（部品は build_catalog の名前だけから作られ、需給はその外の別枠だったため）。MMI は法則 R5 が名指しする「トレンドの強さ」の物差しなのに、計算式そのものが実装に無かった。帯の許容幅は値段に対する固定の割合しか無く、相場の荒れ方が変わっても幅が動かなかった。

### ② 期待値分解

**この設計書は売買のコードを1行も変えません。**勝率・平均利益・敗率・平均損失は、この工事では1つも動きません（売買を1件も回さないため）。動くのは「engine_tuner が組める条件の種類」だけです。

- 部品の数＝**551件 → 増える**（MMI の期間4通り ＋ ATR 連動の帯の組）。実測の数字は、実装したあとに機械で数えて出します（いま予測の数字は書きません）
- 別枠の材料＝レンジ幾何・時間帯の2枠 → **需給を足して3枠**
- 場面の判定で使える形＝前処理を付けられる道が **0 → 1**

### ③ root か symptom か

**root です。**「この条件が書けない」という個別の症状に1件ずつ当てるのではなく、**材料が入る道そのもの**（別枠の枠組み・材料の定義表・前処理の道）を通します。ただし ⑤（文書の訂正）だけは symptom で、実測と文書の食い違いを1件 直すだけです。

### ④ ベースアップ（参照した資料・記憶ベースではありません）

- **MMI**＝The Financial Hacker「The Market Meanness Index」の**記事本文から逐語を取りました**（検索結果の要約では書いていません＝恒久の決まり43番）。C のコードの逐語＝`double m = Median(Data,Length); for(i=1;i<Length;i++){ if(Data[i]>m && Data[i]>Data[i-1]) nl++; else if(Data[i]<m && Data[i]<Data[i-1]) nh++; } return 100.*(nl+nh)/(Length-1);`。期間の逐語＝`int MMIPeriod = optimize (0,200,500,100)`

- **ATR に連動する帯**＝**うちの実物**が出どころです（observe_config.json:255 の説明の逐語＝「出どころ＝e37_scalp.py:213 の逐語『V25_K = 0.5 # 束ね幅 tol=clamp(K×ATR%_1h,0.15%,0.6%)』」）
