## 順番と、その理由

1. **F-2（読む口が登録の名前を返す）が最初**＝F-1 の build_catalog は、組ごとの登録の名前で make_material を呼ぶので、読む口がそれを返さないと書けない。
2. **F-3（写す元の関数）と F-4（写すプログラムの呼び先）は、F-1 と同じ設計書で一緒に当てる**＝F-1 だけを当てると、写すプログラムの写す元が indicators.json 自身になる（--verify が自分と比べる）。
3. **F-6（gen_materials の数える相手）は F-3 の後**＝F-3 の関数の名前が要る。
4. **F-5（H2 の対象）は F-1 と一緒**＝F-1 の後は build_catalog が indicators.json を読むので、同じ時から印に見張らせる。
5. **確かめは最後**＝自己テストと --verify → G2 → H2 → 列の比べ → 監査に出す前のチェック（4-4 の順）。
6. **171番は、この工事の後**＝engine_tuner の経路の7本を読む口へ向け直す前に、列を作る所が読む口から作れることを確かめておく。
