## ① DPO（修正37）

**前提**
- オン・オフの表は、指標を「使う」にする理由（源）を4つ持っています。そのうちの1つが「ta」です。
- 「ta」は、有名なライブラリ ta に同じ指標があれば「使う」にする源です。ライブラリの指標とうちの指標の対応は、TA_CLASS_MAP という表に書いてあります。
- うちの DPO% を「使う」にしている源は、ta だけです（indicator_switch.json で確かめました。法則・個別の決定の源には入っていません）。

**問題**
- ta の DPO と、うちの DPO% は、計算が違います。
  - ta：k本前の終値 − いまの n本平均（教科書の形）
  - うち：いまの終値 − k本前の n本平均
- 違うものを「同じ」として対応させているので、うちの DPO% は誤った理由で「使う」になっています。

**私の案**
- ta の DPO は、K-3 で足す教科書の版の DPO に対応させます。
- 今の DPO% は、比べるために残します。M2-C-14 で「比べる指標は、教科書の版を足し、今の版も残す」と決まっているためです（DPO は監査の修正45 の「比べる」に入っています）。

この案なら、すでに決まっていることだけで決まります。

## ② 2つ目の設定の数字（修正64）

**前提**
- 指標には、期間のほかに「ならしの強さ」などの設定を持つものがあります。T3 の 0.7、PSAR の 0.02 と 0.2 などです。
- 今は、この数字が教科書の既定値1つに決め打ちされています。engine_tuner は、ほかの値を試せません。

**決めること**
- この数字も、範囲を決めて engine_tuner に探させるか。

**実際に範囲になるもの**
- OK いただいた選び方を当てた表では、9つのうち多くが1点のままです。T3 は 0.7、KAMA は 2 と 30、MAMA、JMA、SSF も同じです。
- 範囲になるのは次の3つだけです。
  - PSAR：上限 0.018〜0.2、増やす幅 0.01〜0.02
  - CKSP：倍率 0.5〜5.0、本数 9〜20
  - ALMA：offset 0.85〜0.86

**私の案**
- 探させます。範囲は、OK いただいた選び方で出た範囲だけにします。私は新しい数字を作りません。
- 理由は、「探す値を点の一覧で先に限定しない」（要件の作ってはいけないもの2番）です。

## ③ 帯の1時間足の区切り（修正69）

**前提**
- 帯（レンジの上と下の線）は、5分足をまとめて作った1時間足から作っています。
- うちの1時間足の区切りは、10:05〜11:05 のように、正時から5分ずれています。取引所の1時間足は 10:00〜11:00 です。
- 監査によると、未来のデータは使っていません（閉じた時点で確定しています）。

**決めること**
- 区切りを取引所と同じ正時にそろえるか。

**そろえたときに起きること**
- 帯の値が少し変わります。
- E38 の S2 が前と同じ結果を出すかの検査（恒等）と、古い正解の表 labels_v17.csv との一致が崩れます。
- labels_v17.csv を今どこで使っているかは、まだ確かめていません。

**私の案**
- K-8（上位足の1本の遅れ）と同じ扱いにします。今の区切りと正時の区切りを切り替えられる形にして、一致率で比べます。
- 理由は、どちらが良いかが資料では決まらないためです。
