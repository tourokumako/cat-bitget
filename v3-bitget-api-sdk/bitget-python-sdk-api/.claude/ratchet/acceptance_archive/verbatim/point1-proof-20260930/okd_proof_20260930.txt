【4-0 この仕組みは何か】
設計書の道具 gen_acceptance.py の穴2つを直し、1点目の確かめ方 P1-1〜P1-6 を機械で確かめられる形にする。
1つ目の穴＝設計書に、工事のフォルダの置き場（作業中の .claude/state/verbatim/…）をそのまま書いている。承認でフォルダが archive へ移ると、--verify が作り直す 0-1 と食い違い、承認した設計書は必ず ❌ になる（worklog 20260930 §31）。
2つ目の穴＝--verify は囲みの中しか見ない。囲みの外に誰かが書いた行が在っても見つけられず、P1-1・P1-5（出どころの無い文が0行）を機械で確かめられない。
直した後は、置き場を「verbatim/<工事名>/…」の形で書き、--verify は設計書全体を工事のフォルダから作り直して、囲みの外の行も照らす。

【4-1 システムの境界】
動かすのは CC（gen_acceptance.py --work <工事名> --write と --verify・--selftest）。
設計書を読むのは、まこさん・承認のプログラム・承認の前の検査・監査。

【4-2 入力と出力】

出力＝設計書 acceptance.md（置き場の書き方だけ変わる）と、--verify の結果（囲みの外で食い違った行を出す）。

【4-3 部品と責任の割り当て】
- gen_acceptance._wlabel（新しく作る）＝工事のフォルダの中のパスを「verbatim/<工事名>/…」の形の文にする。
- gen_acceptance.build_source・page＝工事のフォルダの置き場を _wlabel で書く。置き場の説明の1文を添える。
- gen_acceptance._outside_mismatch（新しく作る）＝いまの設計書と作り直した設計書を1行ずつ比べ、囲みの中・完成の条件の表・2-1 の測った結果の列を除いて、違う行を返す。
- gen_acceptance.verify＝囲みの照らしの後に、工事のフォルダから設計書を作り直して _outside_mismatch を掛け、違う行が在れば ❌ にして出す。
- gen_acceptance.selftest＝場面を2つ足す（見本の工事のフォルダを archive の側へ移しても --verify が通る・囲みの外に1行 足すと --verify が ❌）。

【4-4 処理の流れ】
- ①--verify が囲みを今までどおり照らす。
- ②工事のフォルダから設計書を作り直す（本物の設計書には書かない）。
- ③囲みの中・完成の条件の表・2-1 の測った結果の列を除き、残りの行を1行ずつ比べる。
- ④違う行が在れば、その行を出して ❌ にする。

【4-5 異常系】
- 作り直しが止まる（工事のフォルダが無い・逐語が記録と食い違う）＝--verify も ❌ にする。
- 違う行が多い＝最初の10行だけ出し、全部の数も出す。
