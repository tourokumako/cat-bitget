直した案です。誤り3つと、読みにくい所を直しました（worklog 20260929 §94）。見出しに項目の名前を足しました。OK をいただいたら、逐語の道具でこの返信を写し、設計書の道具が【】の番号の項目に写します。手書きの5項目は [やることの表.md](.claude/state/verbatim/point1-design-autogen-20260929/%E3%82%84%E3%82%8B%E3%81%93%E3%81%A8%E3%81%AE%E8%A1%A8.md) の最後の節に在ります。

【4-0 この仕組みは何か】
設計書の道具 gen_acceptance.py に、工事のフォルダから設計書を組む口（--work）を足す。
工事のフォルダには、CC が手で書く やることの表.md と、逐語の道具が記録から写したファイル（まこさんの発言・まこさんが OK した CC の案）が在る。
道具は、やることの表の「手書きの項目」から手書きの5項目を写す。それ以外の項目は、OK された案の【番号】の見出しの下の行から写す。
こうすると、CC が設計書に直接 書く文は5項目だけになる。
いまの形（元データの JSON に CC が全部の欄を書く）では、CC の手書きの欄が26欄ある（next_step.md 39行目）。

【4-1 システムの境界】
動かすのは CC（gen_acceptance.py --work <工事名> --write）。
結果の設計書 acceptance.md を読むのは、まこさん・承認のプログラム・承認の前の検査・監査。
道具は、設計書の中身の正しさは判定しない。

【4-2 入力と出力】
入力＝.claude/state/verbatim/<工事名>/ の やることの表.md と、逐語のファイル（.txt と .meta.json）。
出力＝.claude/state/acceptance.md と、同じフォルダの 要件のまとめ.md（作り直し）。

【4-3 部品と責任の割り当て】
- src_from_work＝工事のフォルダを読み、設計書を組む関数 page が読む形を作る。
- _md_table・_sections・_text・_json_block＝表と見出しと json を読む。
- _wtag＝見出しの下の印を、割り当てどおりに出す。
- write＝［手書き］の印が5つかを数える。
- gen_verbatim.py の drop_reason＝要件のまとめで、要件でない行を分ける。

【4-4 処理の流れ】
- ①やることの表を読む。②逐語のファイルを1つずつ記録と照らす。
- ③話し手が CC だけのファイルを【番号】で切る。④番号ごとに設計書の欄へ写す。
- ⑤足りない欄を全部 集め、1つでも在れば止まる。
- ⑥page で設計書を組む。⑦［手書き］の印を数える。⑧書く。

【4-5 異常系】
次のどれでも止まる。やることの表が無い。手書きの5項目の見出しが無い。表の見出しの欄が違う。json が読めない。知らない【番号】が在る。逐語が記録と食い違う。必要な欄が無い。
足りない所は全部 一度に出す。設計書は書かない（途中の物を残さない）。

【4-6 制約】
非該当＝相場の法則・型の表・承認済みの設定を使わない道具の直し

【4-7 探索の範囲】
非該当＝値の範囲を探す工事ではない

【4-8 データ構造】
新しい形は2つ。
- やることの表.md の節「## 手書きの項目」（見出し5つ。2-1 と 3-1 と 3-2 は表）。
- OK された案の【番号】の見出し（番号の後ろに名前を書いてよい。道具は最初の語だけを番号として読む）。
写した後の欄の名前は、従来の元データの欄の名前と同じ。

【4-9 設定】
- 旗 --work <工事名>＝gen_acceptance.py。--out と一緒に使える。--src とは一緒に使えない。
- 旗 --drop＝gen_verbatim.py の --write と一緒に使う。要件のまとめで外す行の番号。
どちらも付けなければ、従来の動き。

【4-10 保存先】
設計書は .claude/state/acceptance.md に上書き（permanent_rules.md の §0-2）。要件のまとめ.md は工事のフォルダに上書き。

【4-11 時刻の扱い】
非該当＝時刻の列・足の区切りに触らない

【4-12 出る結果の姿】
設計書の見出しの下の印は、［手書き］が5つ、ほかは［自動］。
冒頭に「CC が手で書いたのは、やることの表の手書きの項目の5つだけ」の1行が出る。

【4-13 影響範囲】
従来の道（--work を付けない）は変えていない。
道具の自己テスト12件と、道具の名前で grep して当たった壊すプログラム3本（b72・b73・b89）は、--work を付けずに道具を呼ぶ。
承認のプログラムと承認の前の検査は、設計書の見出しと目印を読む。見出しは変えていない。

【4-14 性能】
非該当＝走る時間は1分以内（自己テスト 28秒）

【4-15 競合】
非該当＝同時に2つ走らせない

【4-16 セキュリティ】
非該当＝鍵・本番の発注・承認の記録に触らない

【4-17 ログと進捗表示】
非該当＝止まるときは足りない所の文を出し、書けたときは書いた置き場と行数の行を出すだけ。途中経過は出さない

【4-18 再利用】
手本＝従来の page。写した後の欄の名前を従来の元データと同じにして、page をそのまま使う。
逐語の読み方の手本＝gen_verbatim.py（記録から逐語を写し、照らす）。

【5 決めたことと理由】
| 決めたこと | 理由 | 捨てた案 |
|---|---|---|
| 自動の項目は OK された案の逐語から写す | 実物から作れない中身があるため | CC が元データの JSON に書く（従来） |
