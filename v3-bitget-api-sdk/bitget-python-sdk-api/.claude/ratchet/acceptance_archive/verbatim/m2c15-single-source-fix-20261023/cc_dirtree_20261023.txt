## 1. 指標の構造（オンの185種）

1種の指標の情報は、いま7つの所に分かれています。

| # | 置き場 | 持っている情報 | 数 |
|---|---|---|---|
| a | 表 INDICATOR_TABLE（indicator_reference_diag.py:957） | 役割・札・方向・性質・値域・注記 | 185行。役割ありは149 |
| b | 定義表 `_r(...)`（同:1262） | 列の名前の型・定義・流儀・照合用の計算（tb）・照合の式（ext）・既知答え（known）・mako | 179か所＋ループ3行（6種） |
| c | 計算の登録 `_reg(...)`（observe_diag.py:1018） | 本番の計算・列の名前の作り方 | 185種すべてにある。**32種は名前が表と違う**（例：表「当日VAH」／登録「close vs 当日VAH%」） |
| d | パラメータの値（observe_config.json） | 古い鍵33個のループで列を作る（observe_diag.py:1820〜）。material_params が87種を上書きする | 鍵から読む種類は133。**18種は2つ以上の鍵から読む** |
| d' | パラメータの値（コードの中） | 計算の関数の引数の既定値（例：STC の 10・12・26＝observe_diag.py:1455）か、ライブラリの既定値 | **52種** |
| e | 範囲（search_limits.json の material_param_ranges） | 最後の段階で探す幅 | 117種 |
| f | オン・オフ（indicator_switch.json） | 使う／使わない | 185／116 |
| g | 表の外の辞書20件・json（ratchet ほか） | ライブラリとの対応・出口の水準・V9 の名前ほか | 185種すべての名前が、どれかにある |

- **つながり方**：a と b は種類の名前でつながっています。b と c は、列の名前（例：「ADX14」）でしかつながっていません（observe_diag.py:1028〜1048）。
- **列**：列は652本で、全部がどれかの種類に当たります。swing高値距離・swing安値距離の2種は、列が0本です（省く設定で、close vs n本高値% に置き替えられています）。
- **まだ確かめていない所**：json のファイル名を書いている行が、実際にそのファイルを開いて読んでいるか。

## 2. どういう修正をすべきか

1. **①集める**
   - 指標1種につき1つの記録を作り、上の a・b（計算の本体を除く）・c の名前の型・d・d'・e・f・g を全部その記録に入れます。
   - 名前は、種類の名前1つにそろえます（32種のずれを無くします）。
   - d' の、コードの中のパラメータ（52種）も、記録の値にします。
2. **②元の場所を消す**
   - `_r(...)` の呼び出しを消します。
   - 観察の道具の古い鍵33個・material_params・material_first_hidden・search_limits.json の範囲・indicator_switch.json・表の外の辞書20件・対応の決まりの写し・資料の表3つを消します。
   - ratchet の表（型の表ほか）からも、指標1種ごとの欄を消します。
3. **③読む側を向け直す**
   - 列を作る所（build_catalog）は、記録のパラメータだけから列を作ります。
   - engine_tuner_gen・exec・gen_*・hooks・tools は、全部その記録から読みます。読む口は1つのプログラムだけにします。
4. **戻らないようにする**
   - 記録の外に指標の名前を持つ辞書や json を書くと止める hook を作ります。
   - 数える道具が、`_r`・`_reg`・関数の既定値も数えるように直します。
