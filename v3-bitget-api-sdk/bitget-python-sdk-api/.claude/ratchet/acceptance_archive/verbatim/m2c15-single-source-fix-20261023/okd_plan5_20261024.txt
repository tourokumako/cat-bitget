結論です。次の5つを、この順にやれば達成できます。

1. **物差しを先に直す**
2. **1つのデータを作って、全部集める（①）**
3. **読む口を1つにして、全部のプログラムをそこへ向け直す（③）**
4. **元の置き場を全部消す（②）**
5. **外に作れない仕組みで守る**

## 1. 物差しを先に直す
- 数える道具（ss_outside_probe.py）は、いま次の3つを数えていません。
  - `_r(...)`（298か所）
  - `_reg(...)`（254か所）
  - 計算の関数の中のパラメータの既定値（52種）
- このままでは、0件になっても完成と言えません。そこで、数える道具にこの3つを足し、読む所（ファイル:行）も全部数える形にします。

## 2. 1つのデータを作って、全部集める（①）
- 置き場は、`scripts/priority_rebuild/indicators/indicators.json` の1本です。指標1種につき1つの記録を持ちます。
- 記録に入れる物は、89番で数えた置き場の全部です。
  - 名前、列の名前の型
  - 計算の関数の名前、照合の関数の名前、既知答え
  - パラメータ（すべての引数について、最初の値〔スキャル／デイトレ〕と範囲）
  - 役割・札・方向・性質・値域・注記・オン/オフ・mako
  - ライブラリとの対応・出口の水準・V9 の名前
  - 教科書の出どころ（逐語・URL）
- 記録は、いまの置き場からプログラムで1回だけ写して作ります。手では書きません。
- 名前は、表の名前1つにそろえます（計算の登録の名前が違う32種）。
- コードの中にあるパラメータの既定値（52種）も、記録の値にします。

## 3. 読む口を1つにして、向け直す（③）
- `indicators/indicators.py` を1本作り、indicators.json を開くのは、このプログラムだけにします。
- 列を作る所（build_catalog）は、記録のパラメータだけから列を作ります。古い鍵33個は読みません。
- engine_tuner_gen・engine_tuner_exec・gen_*・観察の道具・hooks・tools は、全部この読む口から読みます。

## 4. 元の置き場を全部消す（②）
次の物を消します。
- `_r(...)` の呼び出し、INDICATOR_TABLE、`_reg(...)` の名前と型
- 表の外の辞書20件、対応の決まりの写し
- observe_config.json の指標の部分（material_params・material_first_hidden・古い鍵）
- search_limits.json の範囲、indicator_switch.json
- 資料の表3つ、r1_role_map.json を読む所
- ratchet の表の、指標1種ごとの欄

計算の関数の本体は、コードとして残します。記録が関数の名前で指します。

## 5. 外に作れない仕組みで守る
- 記録の外に、指標の名前を3つ以上持つ辞書や json を書いたら止める hook を作ります。
- 1の数える道具を、監査に出す前のチェックに入れます。

## 方向と性質
- 205回目の案（F-2）のとおり、役割と値の作りからプログラムが決めます。
- 決めた値がいまの値と違う種類（オンで48種）は、一覧にしてまこさんに伺います。

## 確かめ方
- 直す前と後で、列652本の名前と計算した値が同じであること
- 数える道具（1で直した物）の結果が0件であること
- `--count` で、役割が空の種類と、食い違いが0であること
- 材料の検査 → G2 → H2 → 監査に出す前のチェックが通ること

## 進め方
この中身で、地図の文書とやることの表を書き直します。まこさんの OK をいただいた後、設計書（gen_acceptance.py）→ 設計書の監査 → 承認 → 実装 → 実装の監査、と進めます。この中身は、205回目に分けた a（役割）と b（パラメータ）の両方にまたがります。ゴールは、両方を済ませて初めて達成されます。
