【4-0 この仕組みは何か】
指標1つの役割の情報は、札（系統）・方向の欄・性質の欄・教科書の役割の4つです。いまは、この4つが、定義表（indicator_reference_diag.py）の各行の引数（方向の欄・性質の欄）・別の表 FAMILY_LINEAGE（札）・資料の表 indicator_roles_thresholds.json（教科書の役割）に、別々の言葉で在ります。4か所の間に対応の決まりが無く、CC が別々に手で書きました。材料の検査1 は、方向の欄と性質の欄の対応（observe_diag.py:6068 の _HOUKOU2PROP）を見ますが、2026-08-06 から 10-22 まで一度も走りませんでした。
この工事は、定義表の中に、指標1種につき1行の表（INDICATOR_TABLE）を置きます。表は、新しい道具 gen_indicator_table.py が書きます（--write）。1行の欄＝役割（教科書の区分と出どころ）・札・方向（区分と読み方）・性質（今の値）・性質（方向から＝検査1 の決まりで決めた値）・値域（検査2 用）・注記。役割は、資料の表と、R-1 の90種の札の正本（封つき r1_role_map.json）から写します。札は、役割の区分から1対1で決めます（区分が2つ以上の種類は、今の札に合う区分）。方向・読み方・性質（今）・値域・注記は、今の定義表の行・札の表・observe_diag の値域の一覧から写します。CC は値を1つも書きません。
定義表の各行（_r(...) の呼び出し）からは、方向と性質の引数を消します。_r は、表から方向と性質を読みます（表に無い種類は、読み込んだ時点で止まります）。札の表 FAMILY_LINEAGE は、表から作る関数 _lineage_from_table() に置き替えます（読む側の10本は、名前を変えずに読めます）。観察の道具の値域の一覧（_OSC_BOUNDS・_OSC_PCTL）は、表の値域の欄から作ります。材料の検査1 に「役割の欄が空」を ❌ に数える行を足します。監査に出す前のチェック（pre_audit_check.py）に、表の照らし（--verify）と材料の検査（検査1〜3）を足します。定義表を保存する瞬間に --verify を掛ける hook を足します（登録は まこさんの手）。
