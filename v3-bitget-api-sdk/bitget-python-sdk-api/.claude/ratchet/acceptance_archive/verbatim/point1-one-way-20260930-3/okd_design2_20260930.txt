【4-0 この仕組みは何か】
設計書の作り方を、工事のフォルダから組むやり方の1本にする。
いまは、元データの JSON から組む古い口が、設計書の道具・依頼書の道具・当てる道具の3本に残っている（worklog 20260930 §18）。古い元データには、途中でやめた5点まとめの中身が残っていて、設計書の道具の自己テストがそれを本物として読む。そのため、ほかの道具を正しく直しただけで自己テストが落ちた（監査 cp52 の修正20）。
直した後は、3本とも工事のフォルダだけを読む。古い元データは archive へ移す。自己テストは、一時の置き場に作る固定の見本だけで試す。
あわせて、承認の前の検査の A9 を、承認した後の凍結（設計書の impl_functions）と比べる形にする。

【4-1 システムの境界】
動かすのは CC（gen_acceptance.py --work <工事名> --write・gen_audit_docs.py request-design <種類> --work <工事名>・apply_audit_fix.py）。
設計書を読むのは、まこさん・承認のプログラム・承認の前の検査・監査。
自己テストを走らせるのは CC と壊すプログラム（b72・b73）と監査の結果の直し（修正20）。

【4-2 入力と出力】
入力＝工事のフォルダ（やることの表.md と逐語のファイル）。古い元データは読まない。
出力＝今までと同じ（設計書 acceptance.md・依頼書・当てた結果）。自己テストの出力は一時の置き場だけに書く。

【4-3 部品と責任の割り当て】
- gen_acceptance.src＝工事のフォルダからだけ組む。工事名が無ければ止まる。
- gen_acceptance.verify・main＝工事名が無ければ、設計書の ARC の iter から読む。--src を消す。--out は --work と一緒のときだけ。
- gen_acceptance.page・section4・build_selftest・build_checklist・build_source・_wtag＝古いやり方の文の分かれ道を消す。
- gen_acceptance._sample_work（新しく作る）＝一時の置き場に、見本のやり取りの記録と、逐語の道具で写した逐語と、見本の やることの表を作る。
- gen_acceptance.selftest＝_sample_work の見本だけで試す。前と後で本物の設計書と ratchet の sha256 が同じかも見る。
- gen_audit_docs.build_design_src・request_design・main・selftest＝--work だけを受ける。自己テストは gen_acceptance._sample_work を使う。
- apply_audit_fix.impl_src_mismatch・main＝--design の実装の指示を、設計書の iter の工事のフォルダ（src_from_work）と照らす。--src を消す。selftest は見本の実装の指示を関数の引数で渡す。
- require_design_check_before_approval.a9_contract_full＝照合A〜D を、凍結＝設計書の impl_functions として走らせる。
- forbid_edit_generated_docs.check＝設計書の直し方の案内を、工事のフォルダのやり方にする。
