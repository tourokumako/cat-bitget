### Q10 — 隠れた数字を②④のパラメータの軸へ写す規則（範囲の合わせ方・代表の値・まだ決めていない）が、要件3と作ってはいけない物2に合うか（優先度 A）

隠れた数字は、2つの測り方で集めます。1つ目は、172番の道具の measure です（計算式の引数の既定のうち、列が変わる物）。2つ目は、計算式が呼ぶ自前の関数の数の既定のうち、計算式から渡していない物です（監査 CP91 の修正1。帯VA・帯VA1時間ATR の va_pct・rows）。範囲は、measure の範囲の出どころが「固定」でなければそれを使います。「固定」のときは、意味の対応表 MEANING_MAP（8種・12の軸）で資料の表のパラメータの名前を引き、今の値が資料の表の範囲の中に在るときだけ拾います。どちらも無い軸は「まだ決めていない」です。写しの実測では、パラメータの軸431本のうち、範囲を持つ軸が254本、まだ決めていない軸が177本でした。代表の値は、observe_config.json の material_first_hidden、資料の表の最初の値、いまの値（コードの既定値）の順で決めます。

1つ目に、MEANING_MAP の12の対応が、資料の表の軸の意味と合っているかを答えてください。例は3つです。Stoch%K の smooth_k は「%K の平滑（slow）」、UO の fast は「短い本数」、PSAR加速 の af0 と af は「step（開始値と増やす幅）」に対応させています。資料の表の該当する行を開いてください。

### Q14 — 「①写す」の行の置き場を名前で探す規則が、写し漏れと写し違いを生まないか（優先度 B）
理由：規則が緩いと、別の代入を写す（写し違い）。厳しいと、一覧が古いだけで止まる（いまの形の不具合と同じ）
対象の問い：2
いまの写すプログラムは、一覧の行の範囲だけで置き場を探すので、一覧が古くて行がずれると、比べる前に止まります（worklog 20261031 §12）。この工事では、名前で探します。探す範囲は、一覧の行が関数の中なら、その関数の中です。外なら、ファイルの一番外です。1か所なら、それを写します。2か所以上なら、一覧の行と同じ行に代入が在ればそれを写します。無ければ、一覧の同じ名前の行の数と合うときだけ、行の順に対応させます。合わなければ止まります。報告の行（拾えなかった行の節）は、名前の語を1つずつ探し、略された名前は1つ目の頭を付けて探します。照らし（coverage）も、ファイルと名前で照らします。
次の2つに答えてください。
1つ目に、「2か所以上で、一覧の行の数と合うときだけ行の順に対応させる」規則が、別の代入を写す場面（例＝同じ名前の変数を、同じ関数の中で違う意味に使い回す所）を生まないかを答えてください。
2つ目に、照らしをファイルと名前で行う形で、「①写す」の行の抜けを見逃す場面が無いかを答えてください。
