## 工事ごとの問い
### Q8 — 工事 A の後、札を実際に直せるか（優先度 A）
理由：直せなければ、M2-L で札が外れていたと分かったときに、札を直して段1から並べ直せない（この工事の目的が満たされない）
写しの作業場で、次の3つを試してください。①regime_label.json の数字だけを書き替えて（例＝er_median の先を見る本数・band_hold の倍率の範囲）走らせ直すと、コードを1文字も変えずに札が作り直されるか。②札の定義を変えたいときに、新しい版を1つ足す手順が部品の作りから決まっているか（どのファイルのどこに何を書けば、採点に使う版として選べるか）。③設定 regime_label.json を読むのが、札を作る部品だけか（観察の道具と測る道具の式を部品に切り替えるのは工事 B なので、いまは観察の道具にも式が在ってよい）。直せない所や、直すのに部品の外を書き替える所が在れば、全部 挙げてください。

### Q9 — 札の「いままでの版」（er_median）が、観察の道具の _regime_labels と同じ答えを出すか（優先度 A）
理由：違えば、工事 B で観察の道具と測る道具をこの部品に切り替えたとき、札が黙って変わり、M2-F-1〜M2-F-5 で測った数と比べられなくなる
同じ5分足のデータと同じ先を見る本数（24本・288本）で、regime_label.py の er_median と、observe_diag.py:5831 の _regime_labels の「強さ」を比べてください。1本でも違うバーが在れば、そのバーと両方の値を示してください。設定に移した先を見る本数（regime_label.json の「先を見る本数」）が、search_limits.json:42 の state_hold_bars_range の両端（24・288）と同じかも見てください。

### Q10 — 「帯・幅・続く」の版（band_hold）が、M2-F-6d の注意の定義の文のとおりに計算しているか（優先度 A）
理由：定義と違えば、まこさんが⑪タブで値を選んでも、選んだ定義の札にならない
定義の6つを1つずつ、regime_label.py の行と照らしてください。①見る過去は、そのバーの前の「保有の上限×倍率」の本数 ②山と谷は、前後 m 本の中で最も高い高値・最も低い安値 ③高さの差が手数料の床以内の山を1つにまとめ、c 個以上で上の線（谷で下の線） ④上の線と下の線の差÷終値が、幅の線以上 ⑤次のバーから「続く本数」まで、終値が全部 帯の中 ⑥帯・幅・続くが全部 合格で「レンジだった」。あわせて、壊すプログラム b118 が「続く」の判定を外したとき、設計書 4-19 の959本目が「レンジだった」に変わり、自己検査 T10 が落ちるかを確かめてください。

### Q11 — 数字が全部 設定（regime_label.json）に在り、コードに数字が無いか（優先度 A）
理由：コードに数字が残れば、設定を書き替えても札が変わらない（まこさんの要望「この数字の値はあとで変更して、答えを作り直せるようにすること」）

### Q12 — H2 の見張りの一覧に足した2行で、札の部品と設定を書き替えると H2 の印が外れるか（優先度 B）
理由：見張りに入っていなければ、札を書き替えても、H2（未来参照の検査）を取り直さずに engine_tuner が回る
leak_causality_diag.py:253 の2つのパスが、regime_label.py と recipes/regime_label.json の実物を指しているかを見てください。写しの作業場で、2つのどちらかを1文字 変えたとき、H2 の印（h2_pass.json）と合わなくなり、engine_tuner が止まるかを確かめてください。

### Q13 — 採点に使う版が er_median のままで、band_hold の「使う値」が空（null）のままか（優先度 B）
理由：CC が値を選べば、まこさんが⑪タブと検査15で値を決める順番を飛ばす（やることの表 3-1 のやらないこと）
