【4-0 この仕組みは何か】
指標には、1つずつ系統の札が付いています（indicator_reference_diag.py の FAMILY_LINEAGE）。engine_tuner は、この札を読んで、どの役割（合図・環境・十分さ・場所・出口の枝）にどの指標を使えるかを決めます（型の表の役割ごとの系統・出口の枝の使える系統）。札は、同じ系統を同じ役割に2本置かない決まり（G3）と、法則 R1・R2・R3 の数え方にも使われます。
この工事は、札を教科書の役割に合わせます。①系統の区分に「強さ」と「勢い」を足します（8区分から10区分）。②88種の札を、出どころの役割とまこさんの決定のとおりに直します（変える76種＝オシレーター49・勢い16・強さ7・ボラ3・トレンド1／変えない12種）。札の正本は、プログラム（r1_role_map_build.py）が出どころと決定から作った r1_role_map.json です。③型の表の環境の役割に強さ・勢い、十分さの役割に強さを足し、出口の2つの枝の使える系統に強さ・勢いを足します（3-2 の1件目「今その指標が使えている役割を失わないように足す」）。④役割の一覧を作る道具が、直した札と調べ直した役割で照らす形にします。
完成すると、教科書が「強さ」と書く ADX・CHOP・ER・VHF・MMI・経過バー2種と、「勢い」と書く MACD・PPO・KST・TRIX・AO ほかが、それぞれの札を持ちます。終値と線の離れ（close vs 〜%）の47種と Keltner上・下は、行き過ぎの札（オシレーター）になります。
なぜこの形か＝札を直すだけで区分を足さないと、強さ・勢いの指標を近い札（トレンド・ボラ）に寄せることになり、法則 C3 の原文「同じ系統でも見ているものが違うことがあり（ADX は強さ・DI差は向き）」が今のまま残ります。型の表と出口の枝に新しい2つの系統を足さないと、写しで数えた結果、強さ・勢いへ移る 21 種が、前から使えた役割を失います（例＝ADX は 出口の枝 BREAKOUT・出口の枝 REVERSE_IND・型の表の env・MACD線% は 出口の枝 BREAKOUT・出口の枝 REVERSE_IND・型の表の env）。足すと、強さ・勢いへ移った指標が使えなくなる役割は 0 です（R-1 の確かめ R3）。
