### 4-0 この仕組みは何か（全体・一続きの文章で書く）

**この項目に書くこと**＝何を作るのか／どういう流れで動くのか／何ができるようになるのか／完成したとき何が出るのか。★項目に分けない。ここだけ読めば全体が分かる状態にする。★★必ず「なぜこの形にするのか」を、ほかの形と比べた実測の数字で書く（この形を取らなかったら何通り・何時間 掛かるか）。★なぜ必須か＝まこさん指摘 2026-09-10「2-2の設計思想は、総当りで組合わせロジックを出すと数百年かかるので、段ごとに絞り込んでいくという方法ということを、このセッション内で何度も言ってるのに、毎回抜けるから、いい加減にしてほしい」。私は「段＝枠を埋める順番」と読み、「段＝候補を絞る段階」という思想を毎回 落とした。

**この仕組みは、承認をお願いする前に、私が壊すプログラムを1本ずつ先に測れるようにするものです。**

**いま何が起きているか。**承認の前の検査 B1（`require_design_check_before_approval.py`）は、完成の条件の表に載った壊すプログラムを、私がいちばん新しい書き替えより後に `run_breaks.py --measure-only` で測り、「期待どおり」だった記録を探します（2-1 の表）。記録が無いと、承認のお願いに「承認は もう1回 要ります」と書かないとターンを終われません。ところが測るだけの口は、表に載った壊すプログラムを全部 1回で走らせます。束1 は4本で約16分かかり（b77・b99 が各 約7分半＝監査 CP43 の B3-c）、私が前面で1回に走らせられる10分を超えます。裏で走らせると、結果の文字が検査の見る記録に残りません。★そのため束1 では、私は承認の前に確かめられず、承認が通るかどうかを まこさんに打っていただくまで分かりませんでした（9/21 の まこさんの指示「何度も同じ承認をさせることをしないでほしい」と逆の形）。

**どう変えるか。**旗 `--only <名前>` を足します。`--measure-only --only b77_no_streak.sh` と打つと、表に載った b77 の1本だけを走らせ、いままでと同じ形の行を出します。1本ずつなら、どれも10分以内です（1本あたりの打ち切りも600秒で同じ）。検査 B1 は壊すプログラムごとに「期待どおり」の記録を探すので、4回に分けて測れば4本とも数えます。

**なぜこの形か。**①承認のプログラムの経路（記録と「済」を書く）は、表の全部を走らせる必要があります。だから `--only` は測るだけの口に限り、承認の経路では使えないようにします（使えば rc=2）。②検査 B1 の判定を緩めず、出力の形も変えません。裏で走らせた結果を数えさせる直し方は、走らせたフリの道になるので取りません。③表に載っていない名前は止めます。設計書と関係の無い壊すプログラムを走らせる道を作らないためです。

**完成したときに出るもの。**`python3 .claude/tools/run_breaks.py --design <設計書> --measure-only --only <名前>` が、その1本の行（「✅ 期待どおり #番号 名前 rc=…」）と「止まった 1/1」を出します。表に無い名前と、`--measure-only` の無い使い方は rc=2 です。売買のロジックにも審判にも触りません。net はゼロのままです。
