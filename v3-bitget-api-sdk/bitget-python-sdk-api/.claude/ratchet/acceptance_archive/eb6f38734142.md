## A 74番＝売買の突き合わせが、切った日の手前3日を比べていない

### ① 真因
- `compare_trades`（`leak_causality_diag.py`:495〜505）は `exit_time < CUT−3日` の売買だけを比べる。余白3日を取った理由＝切った走行では、データの終わりで持っている玉が強制決済される（未来参照ではない）から。
- **ところが、売買ループの中の未来参照で結果が変わるのは、見ようとした先が CUT を越える玉＝CUT の直前の玉だけ。**その玉が余白の中に居るので、3日（864本）より近くを覗く型は捕まらない（worklog 20260823 §13.3・チャットで まこさんに説明して「理解した」）。
- 説明文（:29「売買ループの中で先の足を覗く型はここで捕まる」）は書き過ぎ＝3日より遠くを覗く型だけ。

### ② 期待値分解
- net を動かす直しではない。**動かすのは「未来参照を見逃す確率」**＝売買ループの局所の覗き（1本〜864本）が、いまは 0% 捕まる → 直すと CUT をまたぐ玉で必ず捕まる（余白0日）。

### ③ root か symptom か
- **root を直す＝Y。**余白という「一律に外す」やり方をやめ、外すべき玉（強制決済）だけを名指しで外す。余白を短くする（symptom）ではない＝短くしても「余白より近くを覗く型」は残る。

### ④ ベースアップ
- 実物＝`e38_logic_parts.py`:401・:548、`e37_scalp.py`:1573・:1655、`engine_tuner_exec.py`:2450＝データの終わりで決済した玉は **決済理由 `FORCE_CLOSE_EOD`** で記録される（`score.py`:58 の taker に登録済み）。＝名指しで外せる。
- `false_positive_incident_policy.md` §5 関所B＝「leak チェックを ML 特徴量に限定しない。Entry / Exit / Replay / PnL 計算のすべてで verify」。いまの検査は Exit の局所を見ていない＝関所B の趣旨に届いていない。
