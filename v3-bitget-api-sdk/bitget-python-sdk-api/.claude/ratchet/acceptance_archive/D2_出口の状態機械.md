## ① 真因（root cause）

生成器 engine_tuner_gen.py の `_make_exits`（282行）が作れる出口の枝は4つだけ（SL・TP2・TIME・確率で TP1）。
枝の中身と種類が固定で、順番だけが乱数。**「玉がどう動いたかで枝が切り替わる形」を1つも組み立てられない。**
実行器の側は状態列9種・scope（積み増し回数・保有時間）・置き場所7種を持っているのに、生成器が使っていない。

## ② 期待値分解（どこを何 pt 動かすか）

- **損失最小化**＝逆行して終わった玉（採用土台 v59d_164 の採点窓 実測＝326玉／1,693玉）の逆行幅を、
  資金防衛の枝（FINSTOP）と満期の前倒し（TIME_DOWN）で頭打ちにする。実測の分位＝中央値 0.255%・75% 0.435%・95% 0.769%。
- **利益最大化**＝含み益が乗ってから消える玉を、ピーク戻し（PEAKLOCK）・同値撤退（BEEXIT）・長持ち玉の利確（MFEEXIT）で確定する。
- **⑨巻き込み検証**＝切る系の枝（FINSTOP・TIME_DOWN・BREAKOUT）は勝ち玉に当たる量を必ず数える。
  そのため格子は実測の中央値より上に置いた（普通の往復では発火しない）。数字は検収の実走で出す。

## ③ root か symptom か

root。出口の枝が4種固定である限り、入口をいくら直しても「伸びる玉を伸ばす・負けを早く小さく」が組めない。
