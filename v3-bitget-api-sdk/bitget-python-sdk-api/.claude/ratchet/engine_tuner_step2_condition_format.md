## 0. この形式が何を解くか（1段落）

いまの engine_tuner が組み立てられる入口の条件は「1本の列に閾値を当てて上か下か」の1種類だけで、実際に稼いでいるロジックは1本も書けない（CP2 根拠3）。本形式は、**ロジック1本を「レシピ」という1個のデータで完全に表し**、探索器が構造ごと生成でき、実行器が読んで売買でき、検証器が壊れた組み合わせを生成段階で拒否できる形にする。値だけでなく、条件の本数・形・つなぎ方・出口の枝の構成・玉の持ち方までがデータになる。

---

## 1. 全体の形＝レシピ（ロジック1本の完全なデータ表現）

```json
{
  "meta":       { "strategy": "e38", "logic_id": "S2x", "side": "SHORT", "regime": "range_rg5" },
  "pre_filter": [ 条件, ... ],
  "entry":      { "connective": つなぎ木, "conditions": [ 条件, ... ] },
  "exits":      [ 枝, 枝, ... ],
  "position":   { "mode": "avg | separate", "max_adds": 1, "add_trigger": {...}, "unit": 0.024 }
}
```

- **meta** … 戦略 token・ロジックID・方向（E-h・§1.2.1 で固定＝探索対象にしない）・局面ゲート（E-b・戦略の担当局面。レンジ以外は R5 で拡張）。
- **エントリーの執行仕様はレシピに持たない**＝指値オフセット close×(1∓0.0001)・TTL 3本・post_only は実行器のグローバル定数（H5・exchange_spec 準拠）。レシピは上書きできない（CP3 Q7-4 への回答＝実装者裁量を残さないための明記）。
- **pre_filter** … 方向ごとの共通の事前フィルタ（V9 の LONG 共通フィルタと同じ位置づけ・0本以上・状態評価・引き金は置けない）。
- **entry** … 条件のリスト＋つなぎ木（§3）。
- **exits** … 枝のリスト（§6）。**並び順がそのまま優先順位＝データ**（探索でも PDCA でも調整できる・まこさん指示 2026-07-30）。
- **position** … 玉の持ち方（§7・R14）。

## 2. 条件1つ＝役割・形・材料・側・値 の5部品

```json
{
  "role": "env | trigger | sufficiency | location",
  "form": "level | band | band_exclude | slope | slope_avg | cross | streak | within_n | diff | touch | candle_dir",
  "material": [ { "family": "RSI", "param": 9, "tf": "15m" } ],
  "side": "above | below",
  "value": { "threshold_q": "q80", "lookback": 3, "tol": "TOL_SR", "na": "fail | pass", "offset": 0 }
}
```

### 2.1 役割と発火の意味論（CP2 4-2・CP3 提案4 への回答）

| 役割 | 意味 | 評価のしかた | 本数の規則 |
|---|---|---|---|
| trigger 引き金 | 入る瞬間を決める | **縁（エッジ）評価＝前バー不成立 → 今バー成立 の変化で発火** | **発火経路ごとにちょうど1本**（下記） |
| env 環境認識 | 上位の地合い・向き | 状態評価（成立している間ずっと真） | 上限 E_MAX（値はまこさん） |
| sufficiency 十分性 | 行き過ぎ・勢いの量 | 状態評価 | 上限 S_MAX（値はまこさん） |
| location 位置 | レンジ内・構造上の場所 | 状態評価 | 上限 L_MAX（値はまこさん） |

**発火の意味論（1文で確定・CP3 提案4-①）**: エントリー発火＝**その発火経路の木全体が当バーで真 ∧ その経路の引き金が当バーで縁**。

**発火経路（CP3 Q1-2・V9 P22 型 OR への回答・まこさん GO 2026-07-30）**: つなぎ木の**最上位が any のとき、any の各枝が1つの発火経路**になる。経路ごとに引き金ちょうど1本（G1）。これで P22 の「強い系統か緩い系統かのどちらかで発火」が書ける。**引き金は経路の最上位 all の直下にだけ置ける**（any や if-then の内側には置けない＝CP3 提案4-② の確定）。経路数の上限 P_MAX はまこさん（§11）。**探索の既定は1経路**＝複数経路の解禁は歩4 の段の構成で決める（形式が持つことと、探索が使うことは別）。

- 引き金の縁の「前バー」＝同じ条件を t−1 時点で評価した値（定義として同値・キャッシュは実装の自由）。
- 引き金ゼロ・経路内2本以上は、生成の段階で作れない。縁評価だけの引き金にすることで「水準条件だけのレシピが毎バー発火し続ける」も塞ぐ（発火の高頻度自体は B3 件数下限が受ける）。
- 条件の合計本数は範囲で制約する（下限〜上限・値はまこさん。参考＝実際に稼いでいるロジックは5〜10本・材料C）。

### 2.2 形（11種＋offset・CP3 提案4 の意味論確定込み）

**形ごとに「必要な値」が変わる。この対応表が、探索器が可変構造を生成するときの型（R3 完了の線⑤の土台）になる。**

| 形 | 材料 | 必要な値 | 実例（v9_logic 4章） |
|---|---|---|---|
| level 水準 | 列1本 | threshold_q または 名前つき定数・side | 全ロジック |
| band 帯 | 列1本 | 下限・上限（分位 or 定数） | ADX 30〜50 |
| band_exclude 抜き帯 | 列1本 | 下限・上限 | ADX 40〜50 を抜く |
| slope 傾き | 列1本 | lookback N・閾値・side | RSI の3本差分 |
| slope_avg 傾きの平均 | 列1本 | lookback N・平均 M・閾値・side | BB 中央線の傾き5本平均 |
| cross クロス | **列2本** | 向き（上抜け/下抜け） | MACD×Signal・StochK×D |
| streak 連続 | **内側の条件1つ** | 連続本数 N・**offset（0 or 1）** | Stoch の N本連続 |
| within_n 過去N本以内 | **内側の条件1つ** | 遡る本数 N・offset | P4 の押し目（過去10本） |
| diff 差の量 | **列2本** | 閾値・side | StochK−D の差 >0.3 |
| touch タッチ | **列2本** | 許容幅（名前つき定数） | EMA20 タッチ・BB上限タッチ |
| candle_dir ローソクの向き | ローソク列 | 陽/陰 | ほぼ全ロジック |

**意味論の確定（CP3 提案4-③④⑤）**:
- **単純形＝入れ子形（streak・within_n）以外の全部**。列2本の形（cross・diff・touch）も内側に置ける（P22 の「直近2本のどちらかで BB 上限タッチ」＝within_n(touch, N=2) が書ける）。入れ子は1段まで（streak の中に within_n は置けない）。
- **streak と within_n は当バーを含む**＝窓は [t−N+1 .. t]。**offset=1 のときは窓を1本ずらして [t−N .. t−1]**。
- **書き方7「N本連続で成立してから転換」の書き方**＝引き金に cross（縁）を置き、十分性に streak(内側=水準, N, offset=1) を置く＝「t−1 まで N本連続 ∩ t でクロス」。役割が分かれるので G1 と整合（CP3 Q1-1 の解消）。
- **V9 の書き方14種の被覆＝14種すべて書ける**（書き方7 は offset・書き方13 は発火経路で解消。CP3 が「包含は過大主張」と指摘した2件を上の2機構で閉じた）。
- MTF傾き整合（軸カタログ E-c の未実装1件）は、**列ではなく条件の組**＝env 役割で「EMA傾き%__1h が上」∩「EMA傾き%__4h が上」のように同 family 別 tf を重ねて表す。

### 2.3 材料＝ファミリー×感度パラメータ×時間足 の3軸（CP2 4-1・4-3 への回答）

```json
{ "family": "RSI", "param": 9, "tf": "15m" }
```

- **名前に時間足を焼かない。** 列名（RSI9__15m）は3軸から機械で組み立てる（分解の正本＝indicator_reference_diag の正規表現と family・登録なしの材料は使えない＝G6）。
- **param は「カタログに実在する変種」から選ぶ離散軸。** 同 family の隣＝1段隣接（RSI9 の隣は RSI7 と RSI14）。tf も {5m…1d} の並びで隣接。「期間を1段動かす」が近傍探索になる（CP2 4-1 の解消・KB §1.1）。
- **名目窓長を機械導出する**＝max(材料の数値パラメータの最大値, 助走+1)。検査5 の補正後独立標本数（G2）の分母に使う。再帰型（RSI・ADX 等＝助走1本）でも名目期間で補正が効く（CP3 提案1 の強化・流儀として明記＝EMA 系の実効記憶は名目より長いことがあるが、CP2 4-4 の病型＝長窓 rolling の水増しを正しく潰す）。
- **需給3種**（taker_ls・L-S比・CVD）は family=需給・tf 軸なし（5分固定・被覆3窓 100%・DEMAND_REF 済み）。
- **時間帯の列**＝時刻（0〜23）・曜日（0〜6）を材料に追加（E-j・カレンダー由来・登録は実装時）。
- **レンジ幾何列を材料に追加する（CP3 提案2-(a)・恒等検収の前提）**＝res_hi・res_lo・sup_hi・sup_lo・mid・W（帯幅）と、そこから導く帯内位置%（(close−mid)/(res_hi−mid) 等）。family=構造・位置。**登録は歩3 の冒頭に行う**（indicator_reference_diag に定義・流儀・因果性・既知答えを登録してから＝登録なしは selftest が落ちる）。RG ゾーンビルダーの出力は当該バーまでの確定値（H2）＝因果性の検査4 も掛ける。

### 2.4 側と値（CP2 4-1・CP3 提案3・6 への回答）

値の体系は**4区分だけ**。生の数字のフィールドは存在しない。

| 区分 | 何に使う | 決まり |
|---|---|---|
| ① 分位 threshold_q | カタログ列の閾値 | q 格子（刻みはまこさん）。**実値への解決は値決め窓の分布から探索開始時に1回だけ**（rolling しない・CP3 提案6）。解決表（分位→実値）を機械出力 |
| ② 名前つき定数 | 教科書の固定水準・許容幅・物理定数 | **正本レジストリ**を indicator_reference_diag の定義表と同居で持つ（例＝RSI_OB=70・RSI_OS=30・ADX_TREND=25・STOCH_OB=80・中立点 0/50/100・手数料床 FEE_FLOOR・TOL_SR=0.003）。**各定数に出典を必須**（教科書/KB/exchange_spec）。レジストリに無い名前は使えない＝恣意的な追加は番人が止める |
| ③ 整数グリッド | lookback・streak/within の N・hold_min・peak_age_bars | 候補格子（値はまこさん・§11） |
| ④ legacy 値 | **恒等検収レシピ専用**の生値（現行実装の 0.55 等） | `"legacy": 0.55` の明示フィールド。**探索は生成できない**（生成器が拒否・番人で確認）。恒等検収と過去資産の書き写しにだけ使う（CP3 提案2-(c)） |

- **ポジション状態列の閾値は分位を使えない**（レシピ自身の売買結果でしか分布が決まらない＝自己参照・CP3 提案3）。体系＝**含み損益系（unreal_pct・mfe_pct・mae_pct・dist_be_pct）は名前つき定数「手数料床の倍数」（FEE_FLOOR×k）と「ATR 倍数」（atr_entry×k）**・**時間系（hold_min・peak_age_bars）は整数グリッド**。k と格子の値はまこさん（§11）。
- **na（欠損の扱い）**を条件ごとに選べる（fail / pass・V9 P22 の実例）。

## 3. つなぎ方（R3 完了の線③・CP3 提案7 の正規化込み)

```json
{ "any": [ { "all": [ 引き金, 条件, { "if": 条件, "then": 条件 } ] },
           { "all": [ 引き金, 条件 ] } ] }
```

- **3種**＝all／any／if-then。最上位 any の各枝＝発火経路（§2.1）。木の深さは上限つき（値はまこさん）。
- **構文の正規形（重複レシピの抑制・CP3 提案7）**: streak/within_n の N=1 は生成禁止（素の条件と同値）／all の入れ子は平坦化する／band は level 2本に分解しない（band を正とする）。同値の別表現は生成段階で正規形に寄せ、生成内訳の統計を歪めない。

## 4. 生成の物理制約（生成の段階で作れないもの）

| # | 制約 | 中身 | 出どころ |
|---|---|---|---|
| G1 | 引き金は発火経路ごとにちょうど1本 | §2.1。ゼロも2本以上も拒否。経路数 ≤ P_MAX | CP2 4-2・CP3 Q1/Q2 |
| G2 | 適合制約 | 材料列の**補正後独立標本数（値決め窓）≥ N_MIN**。補正後＝非欠損バー数 ÷ 名目窓長（§2.3・検査5 が機械出力）。分位解決に使う標本も同じ線 | CP2 4-4・**CP3 提案1** |
| G3 | 同系統の重ね掛け制限 | 系統（トレンド／オシレーター／ボラ／出来高／ローソク／構造・位置／需給／時間帯の8系統）を **family→系統の割当表**で機械付与（indicator_reference_diag に持たせる・割当表は全 family を列挙＝載っていない family は生成不可・**両属性の family は主用途で単一割当し割当表に理由を書く**＝例 MFI はオシレーター）。同一系統は同一役割に1本まで・レシピ全体で K_MAX 本まで（値はまこさん）。残余の相関は R7②の束ねと ⑧(b) の ONC が吸収 | CP2 4-5・CP3 Q4 |
| G4 | リスクリワードの事前担保 | レシピから損切り幅と利確1段目の幅を機械計算し、比率 ≥ R_MIN（値はまこさん・手数料床と併用）。**幅が生成時に計算できない構成（ゾーン幾何依存の SL 等）は、1トレード最大許容損失枝（X-d(11)）の併設を必須にする**＝SL 系の枝も許容損失枝も無いレシピは生成拒否 | E-i・CP3 観点② |
| G5 | 役割・本数・深さの規則 | §2.1・§3 の上限（値はまこさん） | CP2 4-2 |
| G6 | 未登録の材料・形・定数の拒否 | indicator_reference_diag に無い材料、対応表に無い形、レジストリに無い定数は生成不可 | 検査3・検査7 と同じ思想 |

**拒否は黙って行わない**＝生成拒否の理由別件数（G1〜G6 別）を機械出力する。

## 5. 機械出力（R3 完了の線⑤・CP2 根拠4 への回答）

5. **legacy 値の使用一覧**（恒等レシピ以外でゼロであること＝番人）。

## 6. 出口＝枝のリスト（R13 完了の線①〜③・CP3 提案2-(b) 反映）

```json
{
  "fire":  { つなぎ木＝条件と同じ形式。材料に「ポジション状態列」を使える },
  "exec":  { "method": "maker | taker | post_only | stop | ...(X-k 10種)",
             "placement": { "kind": "resting | on_close",
                            "level": { "ref": "幾何参照 | 建値比 | 定数", "k": "FEE_FLOOR×1.5 等" } } },
  "scope": { "adds": [1, 3], "hold_min": [0, 240] },
  "size_ratio": 0.5
}
```

- **fire** … 入口と同じ5部品の条件。材料に**ポジション状態列**を追加: unreal_pct・mfe_pct・mae_pct・peak_age_bars・hold_min・add_count・dist_be_pct。値の体系は §2.4（分位不可＝定数倍数と整数グリッド）。
- **exec.placement（CP3 提案2-(b)＝恒等検収の成立に必須）**:
  - **resting**＝エントリー時（または枝の武装時）に**価格水準を計算して指値を置く**。バー内タッチで約定・約定価格＝置いた水準（H5 の悲観側規則に従う）。水準 level は3種＝幾何参照（レンジ幾何列の式・例「mid + tp1_frac×(res_hi−mid)」）／建値比（avg×(1±k)・k は名前つき定数）／定数（FEE_FLOOR×k 等）。
  - **on_close**＝バー確定時に fire の条件木を評価し、成立したら次バー以降に執行（成行 taker or 建値フロア maker）。
  - S2 の TP1/TP2/SL（resting・幾何）と TIME→建値フロア（on_close→resting）が両方書ける。
- **exec.method** … X-k の10種。**既定は指値 maker**。成行 taker は時間切れ・前提崩れの能動クローズに限る（H5）。score.py の maker/taker 登録との一致を機械検査。**iceberg・TWAP・VWAP は enum に持つがバックテストの約定意味論が未定義＝歩3 の実行器では「登録済みだが実行不能」として拒否側に倒す**（CP3 Q1）。
- **scope** … 積み増し回数の区間と保有時間の区間。**separate 形の adds＝その玉の序数**（同時保有玉数ではない・CP3 提案5）。
- **size_ratio** … 段階決済の比率（0〜1・探索対象）。
- **並び順＝データ**＝上から先勝ち。時間切れの含み損係数は専用フィールドを作らず一般形の2本の枝で表す（重複表現は §3 の正規形で抑制）。

## 7. 玉の持ち方（R14 完了の線・CP3 提案5 反映）

```json
{ "mode": "avg | separate", "max_adds": 3, "add_trigger": { "kind": "resignal | adverse_pct | time | profit_confirm", "value": "..." }, "unit": 0.024 }
```

- **mode 2形**＝平均建値へ積み増す形（取引所の実際の持ち方）と、別々の玉の形（いまの engine_tuner の形）。
- **avg 形の状態列の式（1つずつ確定・CP3 提案5）**:
  - 保有中の**最有利価格 best_px と最不利価格 worst_px を保持**する（積み増してもリセットしない）。
  - mfe_pct = (best_px − avg_now) / avg_now × 方向符号 ／ mae_pct = (worst_px − avg_now) / avg_now × 方向符号 ＝**その時点の平均建値 avg_now で換算し直す**（積み増しで avg が動けば mfe_pct も動く）。
  - peak_age_bars＝best_px を最後に更新してからの経過バー数。**積み増しでリセットしない**。
  - unreal_pct・dist_be_pct も avg_now 基準。
- **max_adds は探索対象**。add_trigger は4種（X-i(9)）。
- **枠の占有の機械出力**＝最大占有 BTC と時間占有率（判定への組み込みは歩5・H1）。
