## この道具は何か

実エンジン × 審判で Entry/Exit の値を調整しきる道具（旧 engine_search_e38.py・改名 2026-07-27 まこさん確定）

値を1組決めて、売買エンジンを最初から回して、審判で採点する。これを何度も繰り返して、
値決め窓で一番よかった値を出します。**採否は決めません。**

## この道具の目的（まこさん確定 2026-07-27・正本は engine_tuner.py の説明文）

・新規で Entry/Exit ロジックを構築する際に、設定した戦略や条件に沿った、指標、閾値、時間足、
  パラメータの組み合わせロジックを見つけ、利益最大化、損失最小化するまで調整する
・既存 Entry/Exit に対しては、目標達成するために改善すべき点を見つけ、利益最大化、損失最小化するまで調整する
※ 調整しきるの主語は【ロジック1本】。目標額（月 net $1,900）は【全戦略の合算】にかかるもので、
  ロジック1本にはかからない。全ロジックと E36 と E38 は同じ 0.12 BTC を取り合うので、単独 net の
  足し上げは合算にならない（実測＝P21 月$401.51 ＋ P23 月$241.72 を一緒に回した E32b は月$616.55）。
  だからこの道具が出せるのは「このロジックはこれ以上出ない」まで。目標に届いたかは統合の段で
  合算して判定する（正本＝pdca_flow §6.1・まだ一度も行っていない）。まこさん確認 2026-07-27。

この2つに紐づかない機能は足しません。

## 言葉の説明

この説明書と engine_tuner の出力に出てくる言葉です。先にここを読んでください。

| 言葉 | 意味 |
|---|---|
| 試行 | 値を1組決めて、その値で売買エンジンを最初から1回まるごと回して、審判で採点するまでの1回。試行の回数は --trials で決める。 |
| 値決め窓 | どの値が良いかを決めるために使う期間。この期間の成績だけを見て値を選ぶ。 |
| 確認窓 | 値決め窓で選んだ値を、そのまま1回だけ走らせて表示する期間。ここの成績で値を選び直さない。選び直すと確認の意味が消えるため。 |
| 採点窓 | 採否を決めるための期間。探索には一切使わない。ここを探索に使うと、その期間に一番合う値を選ぶことになり、本番で再現しない（L-267）。 |
| 分位から決める閾値 | 閾値を値そのもので指定せず、その期間の分布の何%の位置かで指定するやり方。相場の水準が変わっても同じ意味の条件になる。CC が数字を手で打たない仕組みでもある。 |
| 目的関数 | 探索が最大にしようとする数字。いまは値決め窓の審判の純益。 |
| 件数の下限ゲート | 1日あたりの件数がこの数を下回った試行を捨てる仕組み。純益だけを見ると、ほとんど建てずに損を減らすだけの形に逃げ込むため。 |
| 入口の型 | どんな値動きで建てるかの種類。戻り売り、上抜け失敗、統計的な行き過ぎ、など。型ごとに専用の関数がある。 |
| 確認の部品 | 入口の条件に足す2つ目・3つ目の条件。上位足が過熱していないか、ボラと出来高が足りているか、を見る。 |
| 汎用部品ロジック | e38_logic_parts.py の共通の売買ループで動くロジック。値を差し替えるだけで走るので探索できる。これに当てはまらないロジックは、いまの探索器では扱えない。 |
| ロジック | 1つの入口と出口の組み合わせ。例えば S2 の戻り売り。engine_tuner が値を調整する単位はこれ。 |
| 戦略 | 複数のロジックを優先度で並べた全体。例えば E38 は S1・L1・S2 … を優先度順に並べる。同じ予算 0.12 BTC を取り合い、優先度の順に枠を取る。ロジック単体とは成績が変わる。 |

## 実行のしかた

```
TAGLESS_OK=1 python3 scripts/priority_rebuild/engine_tuner.py --logic <ロジックid> --trials <試す回数>
```

| 引数 | 意味 |
|---|---|
| --strategy | どの戦略を調整するか（tuner_adapters の接続ファイル名・在るのは e37, e38） |
| --logic | 調整するロジック id（例 S2・接続ファイルの logics() が一覧） |
| --trials | 試す組み合わせの数（1試行につき売買エンジンを最初から1回まるごと回す） |
| --seed | 探索の乱数の種（同じ種なら同じ順で試す＝結果を再現できる） |
| --log | 試行ログの出力先（既定は engine_tuner_<戦略>_<ロジックid>.log） |
| --minimize | 減らしたい損失の出口理由（例 TIME_EXIT）。指定するとその損失を最小化する。省略すると合計 net を最大化する（従来どおり） |
| --net-floor | 合計 net の下限。値決め窓の合計 net がこれを下回った試行は捨てる。--minimize と併用する歯止め＝損失を減らすつもりで勝ち玉まで削る形を弾く。値はまこさんが決める（省略＝歯止めなし） |

売買記録CSVは書きません。だからこれは実験ではなく、値を選ぶための装置です。
試行のログだけがファイルに残ります。

## 1回の試行で起きること

```
1. 探索器が値を1組えらぶ
2. その値で売買エンジンを最初から回す（値決め窓の全期間）
3. 出てきた売買記録を score.py にかけて純益を出す
4. 件数の下限を下回っていたら、その試行を捨てる
5. 純益が一番大きい組を覚えておく
```

**採点は score.py をそのまま呼んでいます。** 手数料・funding・約定のしかたは審判の式のままです。
探索器は純益の計算に手を触れません。

## observe_diag との違い

どちらも条件を探します。評価のしかたが根本的に違います。

| | engine_tuner | observe_diag |
|---|---|---|
| 何をする道具か | 候補の値を決める | 観察して材料と候補を出す |
| 売買エンジンを回すか | 回す | 回さない |
| 審判の式を使うか | 使う | 使わない |
| 手数料・約定・funding | 入る | 入らない |
| 同じ枠の取り合い | 入る | 入らない |
| 玉の集合 | 条件を変えると変わる | 条件を変えても変わらない |
| 使う期間 | 探索窓と確認窓 | 採点窓だけ |
| 出す数字の意味 | 候補の順位づけ | 材料。順位づけまで |
| 採否を決めるか | 決めない | 決めない |

engine_tuner は、条件を変えるたびに売買エンジンを最初から回し直します。
だから玉の集合そのものが変わります。同じ枠を別の玉が取り合う動きも入ります。
observe_diag は、既にある玉や場面のバーに条件を当てはめて数えるだけです。玉は増えません。

## 使う順番（まこさん確定 2026-07-27・正本は engine_tuner.py の説明文）

```
▼既存のロジックを直すとき
  実装 → テスト結果が出る → observe_diag で診断 → 改善点を見出す → その改善案に基づき engine_tuner で
  最適化すべき部分をチューニング【Entry/Exit セット → Entry 調整＝Exit を固定して入口を磨く →
  Exit 調整＝Entry を固定して出口を磨く → 全体詳細調整＝セット微調整と優先度・サイズ・add・最終採否】
  → 実装
▼新しいロジックを作るとき
  型を選ぶ（人・entry_exit_matrix のカタログ）→ 機会の在庫を数える（observe_diag・1日に何回来るか）
  → 指標と閾値と時間足を探して調整しきる（engine_tuner）→ 実装 → テスト → observe_diag で診断
※ observe_diag は「数える」と「診断する」の2つだけを担当する。順位づけと候補選びはしない
  （疑似シミュの順位は実走で入れ替わる＝当てにならない順位で絞ると本当は稼げる候補を捨てる・L-330）。
```

## いまできないこと

要件定義を決めるための材料です。すべて上の表から出た事実です。

- 登録 12 本のうち 4 本が調整できません： S1（実装が e37_scalp＝共通の売買ループで動かない） ／ L1（実装が e37_scalp＝共通の売買ループで動かない） ／ S5（入口の型 grid_short が実装されていない） ／ L5（入口の型 grid_long が実装されていない）
- 接続ファイルは 2 枚（e37, e38）です。これ以外の戦略は渡せません。どの戦略を対象にするかは要件定義書 engine_tuner_requirements.md の「この道具でやらないこと」を見てください（E36 は対象外と決まっています）。
- 入口に足せる確認の部品は 9 個だけです。指標も時間足も、この一覧の外は試せません。
- 指標カタログ 768列 のうち、いちばん広いロジックでも触れているのは 9本（1.17%）です。**残りは試していません。**
- 局面の判定はレンジに固定です。共通の売買ループが range_ok_rg5 を前提にしています。
- 保有の上限の候補は分単位に固定です。デイトレの時間単位を試せません。
- 調整の単位はロジック1本です。**戦略まるごと**（複数のロジック＋優先度＋枠の配分）を一度に調整することはできません。ロジック単体で最善にしても、他のロジックと同じ予算を取り合うと全体では変わります。

## この道具では分からないこと

- 採否は決められません。採否は score.py を採点窓に通して、まこさんが決めます。
- 値決め窓と確認窓の成績は、採点窓の成績を約束しません。
- 建てなかった場面のことは分かりません。建てた玉の結果しか見ていません。
