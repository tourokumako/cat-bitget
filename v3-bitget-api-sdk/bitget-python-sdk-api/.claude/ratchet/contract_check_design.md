### 5.2 B｜設計書と実物を両方向で突き合わせる（`verify_design_contract.py` に足す）

> **★新しいファイルを作りません（56回目に決めました）。**理由は2つです。
> ①**新しいファイルは受け入れ条件の TARGET にできません。**受け入れ条件を通すか止めるかを決めるチェック（`require_source_read_before_acceptance.py`）が「TARGET を Read tool で開いたか」を見るためです。まだ無いファイルは開けません。**実物で試して確かめました**（`check()` が「A 直す対象を開いていない」を返した）。**この噛み合わせは `next_step.md` の「あとで直すこと」に記録します。**
> ②同じ目的のプログラムを2本に分ける必要がありません。`verify_design_contract.py` は既に、実行の前に呼ばれる位置に在ります。

#### B-1 `SPEC` の形（設計書に手で書く・プログラムが読む）

```
SPEC
{"impl_file": "<相対のパス>",
 "public_functions": {"<関数名>": ["<その関数が呼ぶ名前>", ...], ...},
 "constants": {"<定数名>": <値>},
 "cli_flags": ["--xxx", ...]}
```

| 欄 | 意味 |
|---|---|
| `impl_file` | 突き合わせる実物のパス |
| `public_functions` | **公開する関数と、その関数が必ず呼ぶもの。**アンダースコアで始まる名前は書きません（下の限界を見てください） |
| `constants` | 実物の一番外側に書く定数と、その値 |
| `cli_flags` | そのプログラムが受け取るコマンドの旗 |

#### B-2 `spec_from_impl()`＝実物から同じ形を書き出す

**実物のコードを構文の木として読み、次を集めます。**文字を探すのではありません。

| 集めるもの | どうやって |
|---|---|
| 公開する関数・クラス | 一番外側の `def`・`class` のうち、アンダースコアで始まらないもの |
| その関数が呼ぶ名前 | その関数の中の呼び出しのうち、同じファイルで定義されているもの |
| 定数 | 一番外側の代入のうち、名前が大文字と数字と下線だけで、右辺が数字・文字・真偽のもの |
| コマンドの旗 | 一番外側の文字のうち、2つのハイフンで始まるもの |

**★コメントの中・説明の文章の中の名前は数えません。**構文の木は、それらを含まないためです。

#### B-3 `diff_spec()`＝両方向で突き合わせる

| # | 出す違い | 意味 |
|---|---|---|
| 1 | **設計に在って、実物に無い関数** | **設計どおりに作られていない** |
| 2 | **実物に在って、設計に無い関数** | **設計に書いていないものを作った**（★いままで見ていなかった向き） |
| 3 | 設計が「呼ぶ」と書いたのに、実物では呼んでいない | 中身が空の関数 |
| 4 | 定数の値の食い違い | 設計と違う値を焼いた |
| 5 | コマンドの旗の食い違い | 設計に無い旗を足した／書いた旗が無い |

**出す文字列（固定）**

```
齟齬: N件
  設計にあるが実物に無い関数: <名前>
  実物にあるが設計に無い関数: <名前>
  <関数名> が呼ぶはずの <名前> が実物に無い
  定数 <名前> の値が違う（設計=<x> 実物=<y>）
  コマンドの旗 <名前> が <どちら> に無い
```

**終了コード**＝齟齬が1件でも在れば 1。0件なら 0。

## §8 リスク・限界（隠しません）

| # | 守れないこと | なぜ |
|---|---|---|
| 1 | **`SPEC` を薄く書けば、突き合わせも薄くなる** | 書くのは私です。**ただし「実物に在って設計に無い」の向きが在るので、実装だけ厚くして設計を薄くすることはできません**（差が出ます） |
| 2 | **関数の中身が目的に合っているか** | 名前と呼び出しの関係しか見ません。**まこさんが読む必要があります** |
| 3 | **アンダースコアで始まる関数は見ません** | 内部の小さい関数まで設計書に書くのは現実的でないためです。**＝内部の関数だけを直せば、この検査は通ります** |
| 4 | **定数の値は、数字・文字・真偽だけ見ます** | 式で書かれた定数は見ません |
| 5 | **私がこの設計書自身を書き換えれば、突き合わせの相手が変わる** | ただし承認のハッシュ値が外れます |
| 6 | **hook のファイル自体を書き換えれば無効にできる** | プログラムでは防げません。`git diff` には必ず出ます |
| 7 | **`self_check_calls`（名前が在るかだけ）は残します** | 消すと既存の `e35_design.md` の契約が後戻りします。**弱いままです。**上に §5.2 の突き合わせを足して二段にします |
