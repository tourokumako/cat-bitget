## 1. ベースアップ（WebSearch 4本＋KB 2本・タスク1）
- 部分利確の数学: 満額到達玉には blended R:R を必ず下げる（50%@1:1+残り@2:1=1.5R < 2.0R）。トレンドフォロー（低勝率×高 R:R）は特にダメージ大 ＝ E0.3 固定等分 $338 < $926 の実測と理論が一致。partial が勝つのは late-reversal 回避＝伸びない玉のみ。
- ML 化の業界形（quantstrategy.io）: 「最適な刻みパターンを当てる」より「状態の分類（伸びるか/失速か）」が学習しやすい。保有継続側で fat-tail を捕捉。
- de Prado AFML Ch10（精読）: 確率→サイズは連続写像・discretization の刻み幅下限は取引コストが決める・継続的サイズ調整はオーバートレーディング（手数料負け）が失敗モード。部分決済への直接言及はなし（averaging active bets が最近接）。
- KB entry_exit_relationship_kb §10: 分割利確＋残しトレーリングのハイブリッドが実務標準・「入口の質が高いほど残し玉を厚く」。

## 2. E15 の経緯（設計→実装→棚上げ）
- 設計（章7-4・まこさん承認）: 教師=保有中スナップ（30分以降・ロット2以上）・ラベル=「今1ロット降り＋残り V9 続行 − 全量持つ」の差額符号・重み|差額|・アクションとラベル完全一致。運用=最古ロット1つを成行降り（1バー1ロット・prob 低下で停止・最後の1ロットは V9 出口・枠空き再add）。
- 実装の学び: 自己検査①が初回 FAIL（net $2558.80 は1円一致・行数 2038 vs 1232 不一致）＝出口の行出しを常に FIFO 複数行にしていた移植ミスを自己検査が正しく捕捉 → ML off は満玉1行に修正して完全一致。**自己検査は「net 合計」と「行構造」の両方を見るから機能した**。
- 検証（全て学習期間内）: 教師 7,471枚/258ポジ・「降り得」率 51.5%（E11 の偏りなし）・B sim 実測 1.2ms/枚（見積 17ms の14倍速）・vol_share 0.257。OOF Spearman −0.026（fold別 +0.13/+0.14/−0.11/+0.27/+0.01）・較正非単調。hold-out 6案: 含み益のみ降りが一貫優位（上位20% +$52.6）・含み損でも降りる無条件案は全敗（−$93〜−$219・E14b R1 と整合）。
- **★対照実験（このセッションの方法論的成果）**: 「prob を逆にして下位20%で降りる」を1本回す → +$85.0 ＞ 本命の上位20% +$52.6。**ML に情報があるなら逆降りは悪化するはずが逆に良かった＝プラスの源泉は「含み益のとき刻む」機械ルール側で ML 寄与はゼロ〜逆と1本で確定**。E13 の玉単位分解（+$98.9 の 2/3 が副作用と判明）に続く「正の結果の検証ツール」の新しい型。安い（1ループ3分）。
- 判定: 採点せず棚上げ（採点1回を温存・事前宣言の手順どおり）。**TIME_EXIT 出血は entry 予測（E13: 74件中7件）・保有中一発切り（E14: −$194）・ML 部分降り（E15: 寄与なし）の3方向すべてで取れずと確定**＝TimeExit 単独レバー打ち止め（まこさん「単純な止血では無理だからな」と確認）。
