## M5｜値を範囲で探せて、その値が本物だと言える（直す前の③と④を1つにした）

engine_tuner が、閾値とパラメータを範囲から探せる。メニューにするのは、本当に選択肢のものだけ。
**あわせて、そのロジックで出し切ったか（A）と、その数字が本物か（B）を、1枚の表で判定できる。**

**条件**

- 探索する値のうち、範囲で探せるものと、メニューのままのものが機械出力で出る。
- メニューのまま残すものに、1件ずつ「本当に選択肢である」理由が付いている（玉の持ち方・条件のつなぎ方・時間足・指標の種類）。
- 疑似シミュで当たりを付けた値の前後を範囲として事前に指定して探せる。
- **★選んだ値の前後でも成績がほとんど変わらないことが、機械出力で出る。変わるなら、その値を採らない。**（まこさん決定 2026-08-09・逐語「２と３はOK」）

**★4つ目を足した理由。**範囲を広げただけだと、engine_tuner は「その期間でたまたま一番 net が良かった1つ」を拾います。その1つは過去のデータにだけ合った値のことがあり、本番で通じません。業界には名前が付いていて、測定もされています。

- Build Alpha「Robustness Testing Guide」の逐語＝「if the best parameter setting is 20 then we should aim to see at least +/- 10% showing about as good of performance」「large drop in performance, then the optimal parameter setting is too fragile and likely just overfit to the historical data」
- 同じ逐語＝「Do not optimize every penny or hundredth to find the "holy grail". It is the surest way to overfitting.」
- ScienceDirect（parameter plateau の論文）の逐語＝「A plateau score algorithm is developed to replace the conventional approach of selecting the best in-sample parameters」「parameters with high plateau scores exhibit more stable and consistent out-of-sample performance」

**★engine_tuner には既に DSR（試した回数が多いほど合格の線を厳しくする仕組み・`tuner_stats.py`）が在りますが、別物です。**DSR は「たくさん試したから厳しくする」。この4つ目は「隣の値でも同じ成績か」。DSR では前後の安定性を見ていません。

**★参考（値を細かく刻む効果の実測・外部の逐語）**＝arXiv 2504.10914「Breaking the Trend: How to Avoid Cherry-Picked Signals」＝「Sharpe ratio is not so sensitive to the parameters around the optimal as expected: Sharpe is 1.25 for ARP(100) and 1.21 for ARP(150)」／「correlation between strategies using different single parameters was extremely high (0.96 between 80 and 150-day parameters)」。**＝正しい値の近くで細かく刻んでも成績はほとんど動きません。範囲にする価値は「代表値そのものが外れていた場合に拾えること」にあります**（このプロジェクトの実例＝BB Squeeze の業界定番 10% が BTC では 5%・`technical_analysis_knowledge_base.md` §I.2）。
