## §0 P23 検証の目的（★最初に読む・CC が毎回外す事故の防止・2026-06-07 まこさん確定）

**目的**: P23 の **手動ロジック（V9 の Entry/Exit）をそのまま土台に使い**、その中で「**ML で調整できる部分**」（＝人が手で決めた数字）を調整したら、**NET 利益が地面 $925.73 から どれだけ伸びるか**を検証する。

- ❌ **目的でないこと**: 複雑な ML パイプライン（期待値予測・帯分け・k-fold 等の独自構造）を作ること。CC は毎回これを持ち込んで目的を外す（まこさんが毎回訂正・L-250）。**独自フレームを足す前に本 §0 に照合せよ**。

- **土台（変えない・V9 のまま）**: P23 の型（stoch デッドクロス＋陰線）／ add（サイドごと積み立て・§8.0）／ Exit の 12 種類。

## §2 なぜこの設計か（E4の学びから）
- **E4（勝率二値メタ・全Priority混在・破棄）**: AUC 0.673 出たが net は θ↑で悪化。`corr(ml_prob, net)=−0.027`（無相関）。勝率を上げると大勝ち（P23＝下落を持つ）を切る＝edge逆行。
- **根本原因2つ**: ①ラベルが勝率（net金額でない）②スタイルの違うPriorityを1モデルに混ぜた。
- **直し**: Priority（スタイル）別 ＋ net目的 ＋ Entry/Exitセット。

## §3 構成（段構造）
1. **候補生成（V9・踏襲）**: V9のセットアップが各局面（regime割当）で発火 → 候補（side・priority・regime・5m指標）。

4. **net最適化**: 入口選別×出口設定の組合せを `score.py` の net（全体＆Priority別）で判定。

## §5 ML 調整の方針（平易版・詳細は §10）

**① 何を ML で調整するか ＝ 手動ロジックの「人が手で決めた数字」を全部（§10.4）**

### 8.0 P23 の本質（構造の決定事項・毎セッション最初に読む）

**P23 ＝ 下げトレンドの戻り売りに順張りで乗り続けるトレンドフォロー。**（2026-06-07 ソース再精読で確定）

- **入口**: 4 つの確認のコンフルエンスで「再下落の入口」を取る【`cat_v9_decider.py:469-484`】— ①下げトレンド地合い（bb 中心線が下向き・ADX 効く・ボラあり）②直前に戻り＝一時的な上げ（stoch_k>stoch_d が 2 バー）③その戻りが切れた（stoch デッドクロス＋クロス幅 d−k>0.3）④陰線で下げ出した（close≤open）。
- **add（売り増し）**: 同じ戻り売りシグナルが再発火するたびに積む**順張りピラミッディング**（最大 5 回・`MAX_ADDS=5`）【`replay_csv.py:1342-1350`】。価格逆行に買い増すナンピン（averaging down）ではない。
- **出口**: 下げが続けば伸びを待つ（TP1.2%・最大 8 時間）／外れたら小さく早く撤退（失速カット・stoch 再上昇・PROFIT_LOCK）。
- **稼ぎの構造**: 外れ（戻りで終わった玉）を小さく切り、当たり（下げ継続）で売り増して伸ばす＝**損小利大**。低めの勝率は損小利大の自然な結果であって、勝率を上げること自体は目的でない。
- **ML 化の方針（決定）**: 勝率の足切り（θ）はしない（損小利大の心臓部を壊すため）。「この戻り売りが再下落につながって**伸びるか**」を入口判別（ラベル＝伸びるか／期待値）し、**Exit とセットで net 最適化**する（§8.5・§10）。

### 8.1 狙う値動き ＝ 戻り売り（核は確定）
**狙いは「下降トレンドの戻りを売る＝戻り売り」**【まこさん確認済 2026-06-05】。
- ⚠️ **下の具体条件（bb傾き<-10 / ADX30-50 / ストキャス デッドクロス＋陰線＋クロス幅0.3 / ATR150 等）の "そのタイミング・その数値" は、意図的に設計したものではない**【まこさん 2026-06-05】。＝「戻り売りを捕まえる」ために置いた手段の数字であり、**ML調整・置き換えの対象**（cat_requirements §6: V9数値を焼き込まず木に side別の切れ目を探させる）。
- 現状の捕まえ方（コード事実・**意図ではない**）: 場＝`bb_mid_slope<-10` / `ADX30〜50` / `ATR14≥150`（ADX≥40なら ATR≥200）。引き金＝stochが上がった後（`k>d` 2バー）に **デッドクロス**（`k<d`）＋ **陰線** ＋ クロス幅 `d−k>0.3`。出典 `cat_v9_decider.py` L469-484。

### 8.2 稼ぎ方 ＝ 戻り売りで取る（add/単発/出口幅は "手段"・固定意図ではない）
- **まこさんの願い**【確認 2026-06-05】: **単発でも稼げるといい**。現状の結果は **add（売り増し）で利益が上がっている**（add2-5 で **+$1,991** / 単発(add1) **−$497** / 強い下げ bb≤-30 329件 $2,002）が、**これは意図した設計でなく "結果"**。
- **TimeExit幅を伸ばせばある程度稼げるかもしれないが、それも特に意図ではない**【まこさん 2026-06-05】。
- ＝add・単発・出口幅は **手段**。「addで大勝ちが正解」と焼き込まず、net が上がる方向を検証で選ぶ。
- **add方式**【事実＋まこさん 2026-06-05】: 現状は「同方向P23シグナルが再発火するたびに売り増し」（平均建値・`replay_csv.py` L1194-1210）。**ただし add は深く検証せず入れた暫定**。「**価格が○%下がったら売り増す**」ナンピン方式も効果が出そうなら検証したい。

### 8.3 出口 ＝ 伸びを待つ／伸びなければ小さく早く撤退【事実】
- **TP 1.2%**（指値maker）/ **TIME_EXIT 480分**（8h・伸びを待つ）。
- **MFE_STALE_CUT**: 益$4以下が30分続けば切る（失速カット）。
- **STOCH_REVERSE_EXIT**: stoch再上昇(ゴールデン)＋益$20＋150分以上で撤退。
- **PROFIT_LOCK V2**（add非依存・現状ENABLE）。
- 出典: `cat_params_v9.json` L33-150 / `replay_csv.py` L222-266・L304。

### 8.4 Entry と Exit のセット関係【意図・要確認】
- Entry「戻り天井で売る＝**再下落を取りに行く**」→ だから Exit は「**伸びを待つ**」（time480・TPを近すぎなくする）で**対になっている**。
- 賭けが当たれば（再下落）売り増して大勝ち、外れれば（横ばい/反発）失速カット・stoch反転・時間切れで**小さく早く撤退**。
- ＝入口の「伸びる前提」と出口の「伸びを待つ／外れたら早逃げ」がセット。**片方だけいじるとちぐはぐになる**（E4=入口だけ勝率で絞り大勝ちを切った／E7=入口サイズだけ振り儲け頭を薄くした）。

### 8.5 弱点と ML 化の的（次のPDCAの起点）【データ＋意図】
- **弱点**【事実・report】: 時間切れ −$2,367・失速 −$837 ＝ **再下落しなかった玉（賭け外れ）で出血**。伸びた玉(MFEピーク$15超)144件 +$3,182 / 伸びない玉336件 −$2,276。
- ＝V9は型が合えば一律に入るので、Entryが**「伸びる戻り売り」と「伸びない戻り売り」を入口で判別できていない**。
- **ML化の的**＝「この戻り売りが再下落につながって**伸びるか**」を入口で見分ける（MFE/payoff）。Entry: 伸びる場面に絞る/厚く ＋ Exit: 伸びない玉を早く切る・伸びる玉は伸ばす → **セットで net 最適化**（§5）。
- **検証順序（まこさん 2026-06-05・すべて score.py の net で判定）**: まず **【1】Entry（伸びる戻り売りの入口判別）× Exit（TP/SL/時間＝ラベルを決める Triple Barrier）をセットで最適化**して土台を固める（入口指標は trade_methods_study §6・MTFコンフルエンス中心）→ その後 **【2】add方式**（現状のシグナル再発火 vs 価格○%下落ナンピン）を検証。add は土台の上の増し玉なので順序が逆だと評価できない。
- add・出口の "型" はV9を起点とするが、まこさんの意図は **「戻り売りで稼ぐ」** であって型の固定ではない＝net が上がるなら手段は検証で選ぶ。

## §9 ML化アプローチ 2路線（常に深掘りできるよう明記・2026-06-05）

> 詳細・出典＝[`trade_methods_study.md §6.1`](../memory/trade_methods_study.md)（まこさん共有＋WebSearch）。深掘りは本節のリンクから都度。

| 路線 | 中身 | 位置づけ |
|---|---|---|
| **B 教師あり（現方針・採用中）** | Entry 条件から「次の逆シグナル/損切りまでの**最大利益幅(ATR N倍)**」をラベルに LightGBM/XGBoost（時系列は LSTM）。＝**MFE/payoff 予測・Triple Barrier**。 | **今これ**。データ量に合い ratchet で1手ずつ回せる。E5/E6/E8 はこの路線。 |
| **A 強化学習(RL)** | 状態(価格/指標)→行動(Buy/Sell/Hold)→**報酬(損益 or Sharpe・コスト/DD ペナルティ)** を直接最適化。PPO・Stable-Baselines3・OpenAI Gym。 | **将来候補**。Entry/Exit/add を**統合最適化する本命**だが**小データ過学習リスク大**（リスク調整報酬で緩和）。 |

- **A への切替条件**: B で土台（Entry×Exit セット）が固まり、Entry/Exit/add/サイジングを**統合最適化**したくなった段階／データ拡張・正則化で過学習耐性が確認できた段階。
- **共通必須（どちらでも）**: ① MTF 特徴量（上位足マクロでダマシ減）② 取引コスト（手数料/slippage/funding）を報酬・シミュに組込み（既に `score.py`/`eval_engine` で担保）③ regime(ボラ)切分けで過学習防止。
- **深掘りリンク**: [RL trading (QuantInsti)](https://blog.quantinsti.com/reinforcement-learning-trading/) / [Sharpe報酬 arXiv2506.04358](https://arxiv.org/pdf/2506.04358) / [Triple Barrier (mlfinlab)](https://deepwiki.com/quantopian/mlfinlab/6.3-triple-barrier-method) / [MTF pullback](https://tradeciety.com/how-to-perform-a-multiple-time-frame-analysis)。

## §10 E8b 詳細設計書（業界標準構成・2026-06-07 全面改訂）

> 旧 §10（入口の期待値予測 × Exit グリッド × 帯 × k-fold）は §0 の目的に対し過剰だったため破棄。本版は WEB検索した詳細設計書テンプレ（[SDD](https://gist.github.com/iamhenry/2dbabd0d59051eae360d8cfa6a2782bd)）＋ ML 設計書テンプレ（[eugeneyan/ml-design-docs](https://github.com/eugeneyan/ml-design-docs)）に準拠。

### 10.1 ドキュメント概要
- **目的**: §0 の通り — P23 の手動ロジック（V9 Entry/Exit）を土台に、人が手で決めた数字を ML で学習・調整し、連続モード(cap遵守)の NET が地面 **$925.73** からどれだけ伸びるかを検証する。
- **関連**: cat_requirements §4.6（H1-H14）／ ledger E0.2（地面 $925.73）／ §8.0（P23 構造）／ trade_methods_study §6（Entry/Exit 連動）。

### 10.2 用語定義
- **連続モード**: 1 建玉を閉じてから次を建てる運用（同時保有が自然に 0.12 以内・`replay_csv.run()` と逐次一致）。
- **前向き sim**: ある時点から実価格を 1 本ずつ進め、V9 ルールで決済し最後の net を計算（未来を先読みしない＝leak なし）。
- **cap**: 予算 0.12 BTC（全建玉合計上限・cat_requirements §6.1）。**leak**: 未来参照。**期待値**: net 期待値（勝率×平均勝ち − 負率×平均負け）。

### 10.3 問題設定
P23 の手動ロジックは「下げトレンドの戻り売りに順張りで乗るトレンドフォロー」（§8.0）。その中で人が手で決めた数字（Entry 指標期間・Entry 閾値・Exit パラメータ）を ML で学習・調整し、**連続モード(cap遵守)の NET が地面 $925.73 を超えるか（＝伸びしろがあるか）**を検証する。型（stoch デッドクロス+陰線）と add（サイドごと積み立て）は土台として変えない（add は E9）。

### 10.4 ML 調整対象（人が手で決めた全数字・グリッド固定しない）
WEB検索（[neuravest](https://www.neuravest.net/a-machine-learning-approach-to-target-gain-stop-loss-learn-when-to-exit-a-position/)）: グリッド（全場面共通の総当たり）より、**ML が場面別に最適 Exit を学習する方が robust**。よって TP/TIMEExit も ML 学習対象。

| 区分 | 数字 | V9 現値 | ML での扱い |
|---|---|---|---|
| **Entry 指標 期間** | stoch_k/d 期間・ADX 期間・ATR 期間・bb 期間 | V9 値 | 複数期間を特徴量化し木が有効な期間を選ぶ |
| **Entry 閾値** | gap / ADX min,max / ATR min / bb傾き | 0.3 / 30,50 / 150 / −10 | 木が net 最大の切れ目を学習（型は残し閾値を外して候補拡大） |
| **Exit 種類＋数値** | TP / SL / TimeExit / **トレーリング（シャンデリア/ATR）** / **分割利確** / 失速カット | V9=TP1.2%・時間480・SL5%(add2+)・失速$4/30分。**トレーリング・分割は V9 に無いが追加**（P23 のトレンドフォローに最適・WEB検索） | 木が場面別に最適な **Exit 種類＋数値**を出力（短い TimeExit も候補＝add1 スキャル成績も見る） |

### 10.5 データ（入力・型・制約）
- **入力**: `data/BTCUSDT-5m-2021-04-01_03-31_1826d_V9FULL_safe.csv`（5m OHLCV 5 年・float）。
- **期間分割（H8）**: 学習 2021-04-01〜**2024-12-31** ／ **embargo 2025-01〜03**（leak 防止の緩衝・学習にも採点にも使わない）／ 採点 2025-04〜12 ／ **封印 2026Q1（iteration 中 不参照）**。
- **制約**: `assert 学習末 ≤ 2024-12-31`・embargo 2025Q1 を学習/採点とも除外・採点開始 2025-04 を assert。

### 10.6 特徴量（★軸1「ボラ逃げ」回避・2026-06-08 改訂・E8b第1回違反を受けて）
- **方向の主役 ＝ regime 系（下げの方向・強さ・継続性）**: bb_slope_pct（中心線の向き）, adx, stoch_k, stoch_d, stoch_gap（戻りの高さ＝売り場）, rsi, rsi_slope, ret_5 ＋ MTF(15m/30m/1h/4h の下げ揃い)。複数期間版を含む（木が有効期間を選ぶ）。
- **⚠️ ATR（揺れ幅）は entry 方向スコアの主役にしない（軸1）**: atr_pct は方向判定の特徴量から**外す**。役割を移す先（**捨てない＝軸1「役割を正す」**）＝ **(a) ラベルを決める TP/SL バリアの幅 `entry×(1±k×σ)`（§10.7・B改訂）／ (b) サイジング入力（将来 E9）／ (c) コスト見合い entry フィルタ**。bb_width も同じくボラ系として方向主役から外す。
- **MTF（leak-safe backward merge・過去の確定上位足）**: 15m/30m/1h/4h の上記 regime 系。
- **制約**: 結果列（net/exit 等）を特徴量に入れない（H2 assert）・USD 絶対値 blacklist（H6）・**学習後に feature importance で揺れ幅(ATR/bb_width)系が上位を支配しないことを確認（軸1 受け入れ条件①・支配したら設計やり直し）**。

### 10.7 ラベル（★軸1「ボラ逃げ」回避・2026-06-08 B 改訂・barrier をボラ基準に）
- **Entry 学習用 ＝ 方向ベース（金額の大小を消す）**: 「この戻り売りが**再下落して下げ方向が当たったか**」を符号でラベル化（+1 下げ到達 / −1 逆行 / 0 時間切れ＝Triple Barrier の符号・**金額でなく方向**）。
- **★ ラベルを決める TP/SL バリアは固定%でなく「ボラ基準」＝ `entry × (1 ± k×σ)`（σ=ATR/EWMA・k=1〜3）**: 固定%だと高ボラ時にノイズで簡単に到達し**ラベル自体がボラを写し込む**（＝軸1の残存）。ボラ基準にすると**どの局面も同難易度**になり ○× が方向(実力)を映す。これで ATR は「方向当て」でなく「**バリア幅を決める相棒**」として活き、**軸1 受け入れ条件③（ボラ系を TP-SL/フィルタに接続）を満たす**。出典: [arXiv 2508.20108](https://arxiv.org/html/2508.20108v2) / [quantinsti Triple Barrier](https://blog.quantinsti.com/triple-barrier-method-gpu-python/) / [quantreo Targets](https://www.newsletter.quantreo.com/p/how-to-build-targets-that-make-sense)。
- ⚠️ **「net 金額の大きさ＝伸びるか」をラベルにしない**（高ボラほど net が伸びる＝ボラ依存＝軸1違反・E8b第1回の敗因）。代替候補（任意・将来検討）＝**ボラ正規化リターン**（forward return ÷ σ・クリップ付き）も金額を消す有効手段（[arXiv 2508.20108](https://arxiv.org/html/2508.20108v2)）。
- ⚠️ **MFE ピークでラベルしない**（Prime Directive・H2）。
- **Exit 学習用（6-2・後段）**: 各 Exit 候補を前向き sim した実出口 net → net 最大の Exit を教師（Exit の数値最適化は net 基準でよい＝サイズ同一なら方向と整合）。

### 10.8 手法・モデル
- **教師あり（LightGBM・現方針）**。RL（DQN/PPO）は土台後（§9・小データ過学習を抑えてから Entry/Exit/add 統合最適化）。
- **Entry の学習**（§10.13 の 6-1）: (A) **閾値**＝木の split が「ADX>X」「bb傾き<Y」等を net 最大になるよう学習（V9 手書き閾値を置換）／ (B) **指標期間**＝複数期間（例 stoch 5/9/14・ADX 7/14/21）を特徴量化し木が feature importance で有効な期間を選ぶ。
- **Exit の学習**（§10.13 の 6-2）: (B1) **場面→最適 Exit 設定を予測**（各 Exit 候補を前向き sim→net 最大を教師・まず これ）／ (B2) **保有中の各バーで「今出るか」を逐次判定**（メタラベリング・トレーリング的に伸ばす/切る）。
- **過学習対策**: num_leaves 小・min_child 大・L1/L2・学習期間のみ・embargo・purged k-fold。
- グリッド（全場面共通の総当たり）は **ML の比較ベースライン**として併走（ML が場面別でグリッドを上回るかを示す）。

### 10.9 検証・成功指標
- **成功指標（主）**: 連続モード(cap遵守) `score.py` の NET（採点 2025-04〜12）が地面 **$925.73 を超えるか**。
- **ガードレール指標**: 全採点 9 ヶ月の各月 net **AND**（§11 逆算）・異常値 STOP（H12）。
- **検証法**: time-based split ＋ k-fold（過適合検出・WEB検索標準）。**閾値・パラメータは学習期間で決定し採点期間を覗かない**（類型C）。
- **最終封印（全月クリア後 1 回のみ）**: 2026Q1 で DSR>0.95 / PBO<0.5。

  - **自己検査** ＝ ① ML 無効（部分利確ゼロ）で地面 1232件・$2558.80 と完全一致 assert ② 教師 sim の「降りない版」がその玉の final_net と一致（サンプル assert・移植の正しさ）。
  - **検証** ＝ 候補を事前宣言: しきい値分位（降り判定をスナップ上位 5% / 10% / 20%）× 降りる条件（無条件 / 最古ロットが含み益のときのみ）の6案。OOF 健全性（purged k-fold・ポジション単位）＋学習期間内 hold-out（ポジ後半30%）の運用ループで6案を比較して1案選定 → まこさん報告 → GO 後に採点1回。判定＝①地面 $925.73 超え ②固定等分 $338 比（ML の必要性の直接検証）。採点期間 2025-04〜12 は選定に一切使わない。
  - **H1** ＝ 部分利確はサイズを減らす方向のみ・add は V9 枠判定 → cap0.12 違反は構造的になし（同時保有実測 assert＋score.py ゲート二重）／**H15** ＝ ラベル符号（金額は重み）・vol_share（<0.5）監視／**H16** ＝ 1変更（保有中の条件付き部分利確のみ・Entry/add/既存 Exit/サイズ不変）。過去設計との差分＝E0.3 固定等分（全玉無条件）→玉別条件付き／E14 全量一発切り→1ロットずつ＋prob 低下で停止／E11 パターン多クラス→1段差額の二値。
  - **値（承認済）** ＝ 判定開始＝保有30分（E14 承認値踏襲）／降りる単位＝1ロット 0.024（V9 unit）／執行＝成行 taker（確実に降りる・1回目）／しきい値・降りる条件＝上記6候補から学習期間内で1案選定（採点前にまこさん承認）。
- **章7 学習する Exit（TP/SL を場面別に学習・2026-06-10 改訂・まこさん承認「一旦 CC 想定で実装してテスト」・★E11 スモークで保留中＝上の★追記参照）**:
  - **木が当てる対象** ＝ 各建玉に最適な **TP/SL の組**（場面別）。最適 TP/SL は単一指標でなく指標の組み合わせ×閾値で変わる（コンフルエンス）→ 木が分岐で自動探索。**net 金額は当てない**（どの組が net 最大かを選ぶ多クラス分類＝連続回帰でない・E9 の R² 破綻を回避）。MFE% ラベルにもしない（E10 で 伸びる確率 prob と実 net が −0.08 の無相関だったため・net 基準に変更）。
  - **入口** ＝ θ足切りせず広く取る（件数を減らさない・方針1）。木は入口選別でなく出口 TP/SL の場面別使い分けに使う。
  - **学習対象 ＝ TP/SL の組（離散候補＝決定木が選べる形）**。制約は2つのみ：① TP 下限＝往復手数料+slip を超える net が出る最低ライン以上（薄利禁止）② SL 常識範囲（上下限）。**R:R は事前固定せず学習で決まる**（方針0 固定最小化）。⛔ 全玉共通の単一組に固定しない＝玉ごと（場面ごと）に変わる（L-261）。
  - **TimeExit ＝ 固定480分（学習しない・安全弁）**。add が育つ保有を確保（E9 の add 破壊回避）。1回目は TP/SL のみ学習。
  - **教師ラベル** ＝ 各型バーから単独建玉を各 TP/SL 組で前向き sim（leak-safe・建玉時点から実価格を進めるだけ）→ 実 net 最大の組（net 基準）。
  - **モデル** ＝ LightGBM 多クラス分類（入口指標群 → どの組か・組の数=クラス数）。
  - **場面別性の監視（＝ML 価値の判定）** ＝ 予測組が建玉ごとに分かれるか（1組に張り付けば場面別でない＝ML 価値なしと早期判明）／ feature importance（指標が効くか）／ vol_share（ボラ逃げ・H15）。
  - **R:R 前提（P23 損小利大）** ＝ P23 は勝率 28-37%（トレンドフォロー）。損益分岐勝率 = SL/(TP+SL) より TP は SL の約1.7〜2.6倍以上が必要（候補は TP>SL 中心）。出典 trade_methods §6・WebSearch（R:R・損益分岐勝率）。
  - **具体値（CC 想定の初期グリッド・まこさん 2026-06-10「一旦 CC 想定で」）** ＝ TP ∈ {0.6, 0.9, 1.2, 1.5%}・SL ∈ {0.5, 1.0, 2.0%}（TP>SL 中心・TP 下限は手数料超・SL 0.5〜2% の常識範囲）。score.py の net で判定し回して直す。
  - **採点** ＝ 連続モードで各建玉に予測組の TP/SL を適用・cap0.12・score.py net vs 地面 $925.73（E0.2）。
  - **根拠** ＝ de Prado Triple Barrier（TP/SL セット・分類が業界標準）／ neuravest（場面別 Exit が固定グリッドより robust・fat-tail で改善）／ R:R・損益分岐勝率（P23 損小利大）。出血源＝伸びない玉が含み益失速・時間切れで死ぬ（E10 report C：含み益失速 −$10,166・時間切れ −$4,786）→ SL/TP の場面別で早く小さく切る余地。
  - **改悪させない仕組み** ＝ 学習期間 2021-04〜2024-12 で決め／採点 2025-04〜12 未使用（score.py）／地面 $925.73 超だけ残す（ratchet）／封印 2026Q1。
  - **leak（H2）** ＝ 教師の前向き sim は建玉時点から実価格を進めるだけ（未来先読みなし）。特徴量は entry 時点確定値。MFE/MAE 全保有ピークは特徴量に使わない。
- **章8-12（未着手）**: 持たせ方・決済（E0.3 機構）／モデル・学習（LightGBM・θ足切りなし・purged k-fold）／採点（score.py・$338比較・cap0.12）／自己検査・H1-H16 照合／禁止事項（1ポジ死守・θ足切り・net金額ラベル・ボラ主役・V9 閾値焼き込み）。

## §11 目標からの逆算（必達の 件数 × avg net）

**月次 NET ≥ $1,900 ＝ 日 $63.3（÷30）。** 全設計はこの逆算を判定軸に持つ（`score.py` net だけで満足しない）。
⚠️ **合否は monthly_avg（平均）でない**。score.py の平均は trade のある月だけで分母を取るため、下落集中の戦略を虚偽合格させる（類型E）。**合否＝全採点 9 ヶ月の個別 net ≥ $1,900 の AND**（欠損月=$0・§10.7）。下表は必要 avg の目安（参考）。

| 月間トレード数（日次） | 必要 avg net/件 |
|---|---|
| 30（日1） | $63.3 |
| 60（日2） | $31.7 |
| 90（日3） | $21.1 |
| 150（日5） | $12.7 |
| 300（日10） | $6.3 |

- **手数料下限（赤字回避の最低）**: size 0.024 BTC＝往復 maker fee $0.67 ／ 0.12 BTC＝$3.36。**avg net がこれ未満は論外**（OL-40）。
- **現状 V9手書き P23**: 採点9ヶ月 481件＝**月53件・avg $4.0**（月$216）。月$1,900には avg $36（9倍）or 件数9倍が必要。サイズ上限 0.12（5倍）でも avg $20・月$1,060＝**P23単独では未達**（industry §2.6「Entry単独不可・多レバー必須」）。
- **段階の位置づけ**: 今は P23 で **Entry × Exit セットの土台の天井**を測る段階。土台を最大化 → その後 多Priority / Exit / サイジング / 並立の多レバーで目標へ（industry §2.6 ケースB＝5レバー中央値で 5.57×）。
- **判定への組み込み**: 各実験の report に「月換算 件数 × avg net」を表示し、$1,900 ラインへの距離を毎回見る（**件数を削ると目標から遠ざかる**のを可視化）。逆算・手数料計算の詳細は [trade_analysis_methods_kb.md](../memory/trade_analysis_methods_kb.md)。
