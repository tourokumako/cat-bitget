## §1 方針（確定済）
- **V9踏襲**: 候補生成＝V9のセットアップ（`cat_v9_decider.py`）、Exit＝V9の12種（`run_once_v9._check_exits` / `replay_csv._check_exits_replay`）。**形と Exit の種類は残す**。V9本体は一切変更しない。
- **ML化する部分（人が手で決めたハードコード）**: ①Entry固定閾値 ②採用/見送り ③局面→Priority割当 ④Exitパラメータ。
- **足す（V9に無い新入力）**: MTF＝上位足 15m/30m/1h/4h（leak-safe・backward merge）。
- **Priority（スタイル）別にやる（混ぜない）**: V9はPriorityごとにスタイルが違う（`MAX_ADDS=1`＝スキャル小勝ち / `=5`＝平均建値ポジション大勝ち・[[v9_priority_styles]]）。E4はこれを混ぜて失敗した。
- **Entry/Exit をセットで net 最適化**: 入口だけ勝率で絞らない（E4の失敗）。入口選別×出口設定の組合せを net で判定。
- **予測対象＝net金額（勝率でない）**: 出口を同サイズに揃えれば勝率≈netにもできる。
- **判定＝`score.py` の net**（固定審判）。数字が上がった変更だけ残す（ratchet）。1周は小さく。封印2026Q1は触らない。
- **地面（超える対象）**: 採点期間 $172（365d）/ $149.50（5年暖機・同源比較用）。最終合格＝全月 net ≥ $1,900。

## §2 なぜこの設計か（E4の学びから）
- **E4（勝率二値メタ・全Priority混在・破棄）**: AUC 0.673 出たが net は θ↑で悪化。`corr(ml_prob, net)=−0.027`（無相関）。勝率を上げると大勝ち（P23＝下落を持つ）を切る＝edge逆行。
- **根本原因2つ**: ①ラベルが勝率（net金額でない）②スタイルの違うPriorityを1モデルに混ぜた。
- **直し**: Priority（スタイル）別 ＋ net目的 ＋ Entry/Exitセット。

## §3 構成（段構造）
1. **候補生成（V9・踏襲）**: V9のセットアップが各局面（regime割当）で発火 → 候補（side・priority・regime・5m指標）。
2. **Priority（スタイル）別ML**: 各Priorityの候補に対し、**net期待値**で採用＋閾値を学習。特徴量＝5m指標（pct化）＋MTF（15m/30m/1h/4h）＋regime＋side。Priorityごとに別モデル（or strict にPriority条件付け）。
3. **Exit（V9メニュー・パラメータをスタイルに最適化）**: Exitの種類はV9のまま、TP/SL/保有/MFEゲート等の**数値をそのPriorityのスタイルに合わせて最適化**（Entryとセットで）。
4. **net最適化**: 入口選別×出口設定の組合せを `score.py` の net（全体＆Priority別）で判定。

## §5 細かい選択（4つ・どうするか決定済み・わかりやすく）

> 難しい言葉は ( ) で意味を添える。CC の説明が難解だとまこさんがミスを見抜けず後で大きな巻き戻しになるため、ここは平易に書く（[[feedback_plain_language]]）。

**① ML に何を当てさせるか ＝「いくら儲かりそうか（金額）」を当てさせる**
- 「net回帰（ネットかいき）」＝「勝つ／負ける」の二択ではなく、「だいたい何ドル儲かる／損する」という**金額そのもの**を予測する学習。
- なぜ：E4 は「勝つか」で選んで、たまにある**大勝ちを捨てて**失敗した。金額で選べば大勝ちを残せる。
- 例え：「**当たりやすいクジ**」でなく「**もらえる額が大きいクジ**」を選ぶ。

**② どの手法から始めるか ＝ P23（下げ相場で売る・V9で一番稼いでいる手法）から**
- なぜ：一番稼いでいる所で ML が効くか先に確かめる（効けば他の手法にも広げる）。
- ※ ここだけ、別の手法から始めたい意向があれば上書きしてください。なければ P23 で進めます。

**③ 出口（利確・損切りの設定）の振り方 ＝ V9 の今の値の"すぐ近く"を少しだけ動かして一番儲かるのを選ぶ**
- 「出口の設定（Exitパラメータ）」＝「何%上がったら利確」「何分で時間切れ」などの数値。
- なぜ：大きく変えず、V9 の実績値の近くで net が最大のものを探す（冒険しない）。
- 例え：今のレシピの**塩加減を少しだけ振って**、一番おいしいのを選ぶ。

**④ 正解データの数え方 ＝ 1回の取引を単独で「儲かった／損した」と数える（買い増しは後回し）**
- 「正解データ（ラベル）」＝ ML に教える「答え」。ここでは各取引が儲かったか。
- 「買い増し（add・ナンピン）」＝ 同じ方向に追加で入れること。V9 はやるが、含めると複雑なので**最初は単発で測り**、次段階で対応。

→ **まとめ（1行）**：**P23（一番の稼ぎ手）に「いくら儲かりそうか」を当てる ML を足し、出口の数値を少し振って、一番 net が高い組合せを `score.py` で選ぶ。** 細部は CC が決めて進め、まこさんは **net の数字だけ**見る。

**狙いは「下降トレンドの戻りを売る＝戻り売り」**【まこさん確認済 2026-06-05】。

### 8.2 稼ぎ方 ＝ 戻り売りで取る（add/単発/出口幅は "手段"・固定意図ではない）

- **TimeExit幅を伸ばせばある程度稼げるかもしれないが、それも特に意図ではない**【まこさん 2026-06-05】。
- ＝add・単発・出口幅は **手段**。「addで大勝ちが正解」と焼き込まず、net が上がる方向を検証で選ぶ。
- **add方式**【事実＋まこさん 2026-06-05】: 現状は「同方向P23シグナルが再発火するたびに売り増し」（平均建値・`replay_csv.py` L1194-1210）。**ただし add は深く検証せず入れた暫定**。「**価格が○%下がったら売り増す**」ナンピン方式も効果が出そうなら検証したい。

### 8.3 出口 ＝ 伸びを待つ／伸びなければ小さく早く撤退【事実】
- **TP 1.2%**（指値maker）/ **TIME_EXIT 480分**（8h・伸びを待つ）。
- **MFE_STALE_CUT**: 益$4以下が30分続けば切る（失速カット）。
- **STOCH_REVERSE_EXIT**: stoch再上昇(ゴールデン)＋益$20＋150分以上で撤退。
- **PROFIT_LOCK V2**（add非依存・現状ENABLE）。
- 出典: `cat_params_v9.json` L33-150 / `replay_csv.py` L222-266・L304。

### 8.4 Entry と Exit のセット関係【意図・要確認】
- Entry「戻り天井で売る＝**再下落を取りに行く**」→ だから Exit は「**伸びを待つ**」（time480・TPを近すぎなくする）で**対になっている**。
- 賭けが当たれば（再下落）売り増して大勝ち、外れれば（横ばい/反発）失速カット・stoch反転・時間切れで**小さく早く撤退**。
- ＝入口の「伸びる前提」と出口の「伸びを待つ／外れたら早逃げ」がセット。**片方だけいじるとちぐはぐになる**（E4=入口だけ勝率で絞り大勝ちを切った／E7=入口サイズだけ振り儲け頭を薄くした）。

### 8.5 弱点と ML 化の的（次のPDCAの起点）【データ＋意図】
- **弱点**【事実・report】: 時間切れ −$2,367・失速 −$837 ＝ **再下落しなかった玉（賭け外れ）で出血**。伸びた玉(MFEピーク$15超)144件 +$3,182 / 伸びない玉336件 −$2,276。
- ＝V9は型が合えば一律に入るので、Entryが**「伸びる戻り売り」と「伸びない戻り売り」を入口で判別できていない**。
- **ML化の的**＝「この戻り売りが再下落につながって**伸びるか**」を入口で見分ける（MFE/payoff）。Entry: 伸びる場面に絞る/厚く ＋ Exit: 伸びない玉を早く切る・伸びる玉は伸ばす → **セットで net 最適化**（§5）。
- **検証順序（まこさん 2026-06-05・すべて score.py の net で判定）**: まず **【1】Entry（伸びる戻り売りの入口判別）× Exit（TP/SL/時間＝ラベルを決める Triple Barrier）をセットで最適化**して土台を固める（入口指標は trade_methods_study §6・MTFコンフルエンス中心）→ その後 **【2】add方式**（現状のシグナル再発火 vs 価格○%下落ナンピン）を検証。add は土台の上の増し玉なので順序が逆だと評価できない。
- add・出口の "型" はV9を起点とするが、まこさんの意図は **「戻り売りで稼ぐ」** であって型の固定ではない＝net が上がるなら手段は検証で選ぶ。

### 10.1 根拠データ（V9手書きP23 採点480件・地面$2,018 を再分析）
- **「伸びる/伸びない」で結果がくっきり割れる**: 伸びた(MFEピーク≥$15) 225件 **+$5,798** / 伸びない 255件 **−$3,780**。→ **伸びない255件を入口で外す価値＝$3,780**。
- **入口指標の伸び予測力（Spearman 指標vs MFE）**: ret_5 **−0.29**（直近が下がる戻り売りほど伸びる）/ RSI −0.23 / ATR% +0.21 / stoch_k・bb傾き・ADX 0.17〜0.18。**単独は弱いがコンフルエンス向き**。stoch_gap・rsi_slope は≈0。
- **Exit 取り逃し**: 含み益ピーク合計 **$11,143** vs 実net **$2,018**（差 $9,126）＝伸びた玉を取り切れていない。

### 10.2 設計（status: 草案・実装前にまこさん確認）
- **候補**: P23 型（typeonly で広げる or full）。**side=SHORT・add/出口の型はV9のまま**。
- **★ラベル**: 「**伸びるか**（MFEピーク ≥ 閾値 の二値、または net金額）」。**E6 の『勝つか(net>0)』とは違う**＝伸びた大勝ち玉は全部○になり **fat-tail を切らない**（E6の罠回避）。ラベルは Exit 設定で決まる（Triple Barrier）。
- **特徴量**: 入口5m指標（ret_5 / RSI / ATR% / stoch / bb傾き / ADX / bb_width・pct化=H6）＋ **MTF（15m/30m/1h/4h・leak-safe backward merge＝V9に無い・伸びしろ）**。
- **モデル**: LightGBM。伸びる玉を予測 → 伸びない255件を絞る。
- **Exit**: まず V9 のまま固定で入口判別の効果を測る → 次に Exit 数値（TP/time）を V9 近傍で振ってセット最適化（取り逃し$9,126回収）。
- **判定**: `score.py` の net（地面 V9手書き $1,943 超え）。
