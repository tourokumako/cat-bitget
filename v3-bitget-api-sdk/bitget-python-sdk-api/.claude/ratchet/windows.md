periods.py の1つだけにして、読む文書はそこから機械で作る形にしました。

## なぜこの期間なのか

**値決め窓と確認窓は「値動きの構造が採点窓に近い期間」で選んでいます。時間の近さでも、成績でも
選んでいません。**

構造とは、ボラ・レンジ滞在率・急騰性・方向など15項目のことです。採点窓の15項目と、
候補の期間の15項目との距離を測って、近い順に並べます。全順位と測り方の正本は
`.claude/ratchet/window_similarity_ranking.md` です。

**★距離の数字はこの文書に書きません。** 窓が変わるたびに書き換え忘れて腐るからです。実際に
2026-08-01 に腐っているのを見つけました。2026-07-30 に窓を統一したとき、この文書の生成元には
「いまの値決め窓は順位2位・距離 1.78」という文が固定で焼かれたまま残り、事実と食い違っていました。
距離を知りたいときは上の正本を開いてください。

**★成績で窓を選んではいけません。** 2026-08-01 の実測がその理由です。採用土台がいちばん稼ぐ
候補窓は、構造では採点窓から**いちばん遠い**窓でした。成績で選ぶと、いまの相場から一番遠い期間を
選ぶことになります。候補ごとの実測は `results/priority_rebuild/ratchet/judgement/` の
`window_material_` で始まるファイルにあります。出した道具は `tuner_window_diag.py` です。

**2025-10 の急落イベントについて。** 5分リターンの尖度がふだんの約8倍になる月です。2026-07-24 に、
この月を含む窓を**値決め窓**にすることは、まこさんが却下しました。急騰を切るツマミが、その1つの
イベントに合わせて過剰に調整される懸念があるためです。いまの確認窓 2025-09-01〜2026-02-28 はこの月を含みますが、
確認窓は値を**選ばない**窓なので同じ懸念は当たりません。荒れた月を含む方が確かめる力は強くなります。

## やってはいけないこと

- 採点窓で値を選ぶこと。その期間に一番合う値が選ばれ、本番で再現しません（L-267）。
- **成績で窓を選ぶこと。** 土台の net が一番大きい窓を選ぶのは、上と同じ過ちです（2026-08-01 実測）。
- 期間の数字を文書やコードに手で書くこと。periods.py から取ります（H8）。
- **距離や順位の数字をこの文書に焼くこと。** 窓が変わると腐ります（2026-08-01 に実際に腐っていた）。
- 道具ごとの期間を勝手に揃えること。診断は採点窓、値決めは値決め窓、と役割で分かれています。
- 値決め窓と確認窓を同じ日付にすること。確かめる力がゼロになり、B2 が必ず判定不能になります。
- 「古い期間だから駄目」と言うこと。基準は構造の近さです。時間の新しさではありません。
- 決着済みの窓の選定を蒸し返すこと。上の経緯の表と `decisions.md` を先に読みます。

## 期間を変えるときの手順

0. **採点窓を変えたときは、値決め窓を選び直します。**
   `cd scripts/priority_rebuild && python3 window_similarity.py` を走らせます。
   新しい採点窓と構造が近い窓を、全期間から順位づけて出します。数分かかります。
   出た順位を `.claude/ratchet/window_similarity_ranking.md` へ保存し、**どれにするかはまこさんが決めます**。
   ★この手順を書いていなかったため、道具の存在が忘れられていました（2026-07-27 まこさん指摘）。
1. periods.py の数値を直します。ここが唯一の出どころです。
2. `python3 scripts/priority_rebuild/gen_windows.py --write` を走らせます。本書と各文書の差し込みが更新されます。
3. 変更の理由と、まこさんの決定の日付を periods.py のコメントへ残します。
4. 過去の net は旧窓で測った値なので、直接比較できません。土台を新しい窓で測り直します。
