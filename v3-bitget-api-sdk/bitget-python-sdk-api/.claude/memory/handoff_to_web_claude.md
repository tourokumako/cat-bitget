## §2 最終目標（唯一の正本）

### 合格ライン（本番投入可判定）

**月次 NET ≥ $1,900/月**

- 本番投入の合否判定はこれのみ
- 「目標」ではなく「合格ライン」（超えたら本番投入可・上振れ歓迎）
- 365d Replay で **全 12 ヶ月**が月次 NET ≥ $1,900 を満たす必要あり（単月でも未達なら不合格）

### デイリー参考値

$60/day（≒ $1,900 ÷ 30日）。日次絶対下限ではない。月次が合否判定軸。

### 凍結ベースライン

- 旧 Priority (P1/P2/P4/P21/P23/P24) の 365d Replay 結果: **NET $4,506 / 月次平均 $370/月**
- 合格ラインまで **5.1 倍ギャップ**
- これらの旧 Priority は精度天井のため凍結・ゼロから再設計する方針

### 禁止する誤読

- ❌ 「日次 $60 を 1 日も下回らない」（変動相場で物理不可能）
- ❌ 「$60/day = 100 trade/日」（件数は目標値ではない）
- ❌ ジャスト合格設計（マージン厚く狙う）

## §5 このセッションで合意したこと（重要）

1. **目標は月次 NET ≥ $1,900/月**（日次絶対下限ではない・全 12 ヶ月クリアが必要）
2. **複数 Priority 並立で合算**して月次 $1,900 を狙う（1 Priority 単体での月次達成は不要）
3. **regime 判定研究は凍結**・新規 v15/v16 試作禁止
4. **既存 P1-P24 は改修ではなく解体・ゼロから再設計**
5. **指標の閾値はロング/ショートで分けるべき**（RSI のロングは < 30 上抜け、ショートは > 70 下抜け）
6. **同じ指標でも閾値で役割が変わる**（ADX > 25 はトレンド・ADX < 25 はレンジ等）
7. **A-2 では月次 $1,900 を直接判定しない**（Entry エッジの強さだけ測る・月次判定は段階 B/D）
8. **Entry/Exit は不可分**（Entry だけ最適化しても Exit と合わないと意味ない）
9. **段階間の役割分担**:
   - A-2: Entry 質の評価
   - 段階 B: Entry × Exit Replay
   - 段階 D: 月次合格判定

## §9 既定の制約・禁止事項

### 絶対禁止
- `ALLOW_LIVE_ORDERS = False` を True に変更しない
- `paper_trading` フラグをコードで変更しない
- 既存 P1-P24 の 1m 足回帰禁止（エッジゼロ確認済み・手数料負け）
- マルチシンボル化（ETH/SOL 追加）禁止
- ポジションサイズ 0.12 BTC/trade 上限を超える設計

### 凍結中（参照のみ可）
- regime 判定研究 v14/v15 等の新規試作
- 「regime → Priority 振り分け」アーキテクチャの復活

### 設計上の制約
- 5m足が現行標準（1m足は不可・他足は手数料計算とエッジ証明があれば許容）
- 時間帯フィルターは個別 Priority 最適化では禁止（統合調整フェーズで実施）
- ポジションサイズは上限内で Priority 別に自由配分可

### 評価上の制約
- 平均（mean）を主評価指標にしない（外れ値耐性なし・中央値使用）
- 上位 10% のみで評価しない（cherry-picking）
- 未来情報（MFE/MAE ラベル）を入力 X に含めない（リーク）
- 全 fold 共通中央値で二値化しない（stage 2 で発覚した leak）
