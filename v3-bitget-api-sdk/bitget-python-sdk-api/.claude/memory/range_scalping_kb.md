## §1 スキャルとは（定義・執行様式）

- **保有時間: 数秒〜数分が典型（1〜5分）。長くても数十分。**「保有4時間」はスキャルではない。
- **利幅: 小さい**。1回の狙いは小さく、その代わり回数で積む（small profits done many times）。
- **R:R（リスクリワード）: 1:1.5〜1:2 ＝勝ち側を大きく・損切りを浅く**。損切りが利確より深い形（E37 v9 の SL 2×ATR vs TP 0.5σ）はスキャルの逆。
- **頻度: 高品質なセットアップに限定して1日数件〜**。「大量」の意味は乱発ではなく「1件を小さく短く、確認の取れた場面だけで、毎日コンスタントに回す」こと。
- 常時監視前提の手法＝機械化（BOT）と相性が良い。ただし高コスト（手数料）がリターンを蝕むのが最大の敵（§6）。

## §2 レンジの正しい認識（何をもってレンジと言うか）

- **レンジ＝「価格がサポートとレジスタンスの間で繰り返し反応している状態」**。統計量（横ばい度・ADX 等）ではなく、**機能しているレベルの実績**で認識する。
- **レベルは1本の線でなくゾーン**（例: BTC $39,800〜$40,200 のような帯）。
- **機能実績の基準: 最低3回のタッチ**。タッチ（テスト）回数が多いほど強い。**近いピボット（スイング高値・安値）は1つのゾーンに束ねてタッチ回数を合算**する（孤立した1本ずつのピボット線を引かない）。
- **上位足で主要ゾーンを構築 → 下位足（5分）で執行**（多時間軸の黄金律）。ゾーンの信頼性は複数時間軸の整合と出来高で裏取りする。
- ⚠️ 「直近スイング高値・安値の間にいる」だけの判定（E35/E36 のフラクタル箱）は、タッチ実績の概念が無いためレンジ判定にならない＝上昇トレンド中でも常に直近高安の間にいる。

## §3 入口（レンジスキャルのエントリー）

- 手順: **①ゾーンに到達 → ②拒否（跳ね返し）の確認 → ③エントリー**。到達だけで入らない（確認なしの逆張りはダマシに轢かれる＝E37 v2 の型）。
- **拒否の確認材料**: 反転ローソク足パターン（ピンバー・エンガルフィング・ハンマー・シューティングスター）＋出来高＋モメンタム（レンジ相場の RSI は 70/30 が有効・5分足は RSI9）。
- **ショート＝レジスタンスゾーンで確認された拒否**。ロング＝サポートゾーンでの確認された反発（E37 はショートのみ＝上限ゾーンだけ使う）。
- 指値（maker）で入る場合もゾーン＋確認が前提（受け身の指値を全場面に置くのではない）。

## §4 出口

- **TP: レンジの反対側（ショートならサポート側）または中央**。手数料を超える幅が最低条件（§6）。
- **SL: ゾーンのすぐ外（浅い）**。「サポート/レジスタンスレベルの直下/直上」に置く＝レンジが破れたら即撤退する位置。スイングポイント超過に ATR 1〜2倍を目安にする流儀もあるが、核は「レベル基準で浅く」。
- **time-stop**: 勝ちセットアップが通常 X 分で最大収益に達するなら、それを大幅に超えて持たない（entry_exit_relationship_kb §time-stop と同旨・スキャルは分単位）。

## §5 レンジの終わり（破れの判定・いつ黙るか）

- 破れの判定3点: **①20期間平均を上回る出来高 ②境界を明確に超えた終値 ③複数時間軸での確認**。
- 破れたらレンジ戦略は**黙る**（トレンドの担当に譲る＝cat-bitget では下げトレンドは E32b の領分）。

## §6 失敗パターン（スキャルが負ける型）

- **高コスト**: 手数料・スプレッドがリターンを蝕む＝スキャル最大の敵。maker 前提・「幅 > 往復コスト」を建てる前に確認（TP 目標が往復手数料+滑りを超えない場面では建てない）。
- **リスク管理の欠如**: 損切りなし・深すぎる損切り（1発で数十回分の小勝ちを吐き出す）。
- **確認なしの逆張り**: 到達だけで入る・伸び切りを fade して継続に轢かれる。
- **レンジ判定なしの発火**: トレンド中の逆張り（上げ相場でのショート）＝そもそもレンジ戦略の前提外。
- **監視疲れ・乱発**: 高品質セットアップ以外に手を出す（BOT では「件数目標のための間口拡大」がこれに相当）。

## §6.5 グリッドトレード（頻度を"シグナル待ち"でなく"仕組み"から作る方法・2026-07-05 追記）

> ⚠️ **追記の経緯（恥・固定）**: 本KB初版（2026-07-04）はS/Rゾーン逆張り（1回の到達→1回の拒否確認→1回の入口→1回の出口、を繰り返す）の情報源しか調べておらず、**グリッドトレード（レンジ内に複数の指値を並べ、価格の往復自体が繰り返し約定を生む手法＝レンジ高頻度の代表的標準手法）を調べていなかった**。E37 v10 は `MAX_ADDS=1`（単発・追加なし）で実装され、頻度が0.97件/日に留まった（目標＝役割上「小刻みに大量」）。まこさん指摘（2026-07-05）「約定したら玉をどんどん追加するんじゃないの？」を受けて調査。

- **外部の標準的なグリッドトレードの仕組み**: 基準価格の上下に複数の指値を並べ、価格がその水準に触れるたびに約定（買い/売り）が発生し、ポジションが積み上がる。頻度は「良いシグナルを待つ」からでなく「注文を並べておく仕組み」から機械的に生まれる（出典 QuantPedia "A Primer on Grid Trading Strategy"）。
- ⚠️ **外部グリッドの弱点（文書化された事実）**: 「価格が持続的に一方向へトレンドすると簡単に赤字化する」（同上）。理由＝グリッドは価格がどちらに動いても律儀に約定し追加してしまう＝逆行方向にも機械的に積み増す（ナンピン型）。実装例（Hummingbot Grid Executor）も「activation bounds外で自動キャンセル」という防御を持つ＝トレンド検出が甘いと機能しない前提は外部グリッドも同じ。
- **★本プロジェクトでの正しい実装形（exchange_spec.md ★ポジションの持ち方・決済方法・L-255 と統合）**: Bitgetは同サイドの複数ポジションを**1つに統合**（平均建値）する仕様＝独立した複数ポジションを持つ「素のグリッド」はそもそも成立しない。だが**add（買い増し）で平均建値を積み上げ、複数のTP（最大20個）で段階的に部分決済**は可能＝これがこの取引所でのグリッドの精神の実装形。**V9（P23等・MAX_ADDS=5・add毎0.024BTC）で既に実装・実証済み**（exchange_spec.md L-255「大勝ち（addで伸ばす）も小勝ち（部分利確で刻む）も両取り・1日10件以上の取引所的な裏付け」）。
- **重要な違い（安全性の理由）**: V9のaddは**「順張りピラミッディング」＝ポジションが有利に動いている時に追加**する方式（価格逆行に買い増すナンピンではない）。外部グリッド（どちら向きにも律儀に約定・追加）とはリスク性質が違う＝**add-on-strength方式は、逆行トレンド時に機械的に含み損を積み増さない分、外部グリッドより安全**。E37はまさに「レンジ判定がトレンドを排除しきれていない」弱点を抱える（§7対応表・N11実測）ため、外部グリッド流（どちら向きでも積み増す）を採用すると、トレンド誤判定時の損失が単発方式より拡大するリスクが高い。add-on-strength＋部分決済（V9型）の方が本プロジェクトの現状に適合する。
- **E37への示唆**: 頻度不足（0.97件/日）の対策は「入口シグナルをさらに緩める」だけでなく、「1回の入口をadd＋部分決済で複数回の約定に展開する」（V9型・既にこのコードベースで実証済み）という選択肢がある。ただし①は依然として初回entryの方向精度（N11＝MFE≥MAE 11%）に依存する＝入口の質を上げずにadd/部分決済だけ足すと、悪い初回entryをより大きく育てるリスクがある（先に入口精度、次にadd/部分決済、の順が安全）。
- 出典: QuantPedia "A Primer on Grid Trading Strategy"（https://quantpedia.com/a-primer-on-grid-trading-strategy/）／ Hummingbot "Grid Executor"（https://hummingbot.org/strategies/v2-strategies/executors/gridexecutor/）／ exchange_spec.md ★ポジションの持ち方・決済方法（L-255・Bitget公式2026-06-09 WebFetch確認）。

## §6.6 反発の"方向"は予測できるのか（学術知見・2026-07-05 追記・E37の失敗型の根の疑い）

> 経緯: まこさん指摘「BTCのレンジスキャルで稼げる設計方法を本当にリサーチしたのか」を受け、より広く学術文献を検索した結果、E37 v2〜v10 が繰り返す失敗型（方向を当てるロジックが当たらない）の理論的根拠にあたる可能性のある知見を複数発見。

- **反発（bounce）の"方向"はランダムウォークと統計的に区別できない**：SPY等の分析で、反発の**大きさ**は高度に有意に予測可能（p<10⁻¹²）だが**方向**は有意でない（p=0.11）。さらに「平均回帰は株式・国債に限られ、**信用ETF・コモディティ・FX・crypto はランダムウォークと区別がつかない**」（出典: arxiv 2606.29591 "The Bounce Has No Direction"）。**本プロジェクトの既存知見（改訂111 base-up）とも一致**＝「短期反転の向きは予測不能・幅は予測可能」。
- **BTCは市場構造上ランダムウォークに近い**：専門ディーラー・在庫調整構造を欠く24/7市場のため、株式のような「在庫由来の自然な反転圧力」が薄い（出典: arxiv 2602.00776 暗号資産マイクロストラクチャー研究）。
- **予測力があるのはOHLCVでなく需給（オーダーフロー）情報**：同研究は「オーダーフロー不均衡・スプレッド動態・逆選択」が短期方向に対し実際の予測力を持つと報告（CatBoost+SHAPで複数銘柄横断的に再現）。板そのものの瞬時の不均衡は**L2板データ**（本プロジェクトの現行データ=Binance 5m OHLCVとは別物）を要するが、**5m集計の需給指標（taker_ls・L-S比）は本プロジェクトで取得済み・かつE28で実際に効いている（下記 §6.7 が正・「改訂109で不採用」は CC の記憶違いで誤り＝2026-07-05 ledger 照合で訂正）**。
- **E37の実測との整合**: v10のN10（`stoch_k_at_entry`相関−0.170＝過熱度高いほど負け）・N11（SL玉の89%が方向ミス）は、「ローソク足＋RSI反転確認で方向を当てる」設計が、学術的にランダムウォーク相当とされる対象を予測しようとしている結果である疑いが強い。v2（出来高climaxフェード）〜v9（型別検出器）まで手法を変えても同型の失敗（入口の方向が当たらない）が続いた根本原因の可能性。
- **示唆（設計への含意・要議論）**: 「確認バーをより厳格にする」等のチューニングでは解けない可能性が高い。有望な方向は① 板情報（オーダーフロー不均衡）の導入＝新規データソースが必要な大きな着手 ② 方向でなく**値幅の縮小（магnitude mean-reversion）**を狙う設計＝方向を当てずに済む構造 ③ ゾーン（S/R）自体が持つ情報（タッチ実績のある特定の価格帯）が汎用の「過熱→反転」より強い根拠を持つか＝現行のN10 box_W_pct_at_entry（弱いが両窓再現）はこの可能性を示唆。**E37の§1.2.1「ショートのみ」という方向固定の要求自体が、方向予測困難という学術知見と緊張関係にある**＝次の設計判断で要検討（まこさんと議論）。
- 出典: arxiv.org/abs/2606.29591（The Bounce Has No Direction）／ arxiv.org/abs/2602.00776（Explainable Patterns in Cryptocurrency Microstructure）／ arxiv.org/html/2212.06888v5（Fundamentals of Perpetual Futures・funding rate裁定＝範囲外だが別の高Sharpe戦略カテゴリとして参考）。

## §6.7 需給（オーダーフロー）フィルタ＝このプロジェクトで既に効いている確定エッジ（Gemini回答＋E28実測の統合・2026-07-05 追記）

> 経緯: まこさんが Gemini に広くリサーチさせた回答を受領。Gemini の学術骨格（方向は予測不能・板情報にエッジ・手数料負けが構造的・Makerリベートが本質）は本 KB §6.6 と一致。だが Gemini の「どうするか」提案（CVD 組み込み）を鵜呑みにする前に、まこさん指摘「設計通りに実装していなかった/実装方法が間違っていた、というオチでは」を受け ledger を照合。**結果＝オーダーフローは"失敗した道"ではなく、E28 で採用された確定エッジだった**（CC の「改訂109で不採用」は記憶違い＝§6.6 で訂正済み）。

- **Gemini 回答の事実部分（一次資料つき・本 KB の学術知見と一致・信頼できる）**:
  - ① 短期の「方向」は予測不能・「値幅」だけ予測可能（arxiv 2606.29591・§6.6 と同じ）。RSI 過熱でショートするとモメンタム継続に轢かれる確率が統計的に高い＝**E37 の N10（過熱度高いほど負け）・N11（方向ミス89%）の理論的裏付け**。
  - ② 方向を放棄したクオンツ戦略のエッジ＝「ボラティリティの平均回帰」「注文の需給不均衡」「流動性提供の手数料報酬（Maker リベート・スプレッド）」。出典 ResearchGate "Automated Trading in Cryptocurrency Markets"。
  - ③ グリッド＝レンジでは高頻度・安定だがトレンドで含み損が幾何級数的に拡大。実務対処＝ATR/BB幅の急拡大・流動性の急な片寄りで新規展開を停止する動的閾値（§6.5 と一致）。
  - ④ **L2板の需給不均衡（OBI）は数秒〜数分で高い予測力**を維持するが、5m OHLCV では板の厚み変化が消えて再現不可。L2データは Tardis.dev 等の購入 or Websocket のミリ秒処理インフラ（C++/Rust級）が必要＝**大きなハードル**。出典 arxiv 2602.00776・Charles University thesis 2025。
  - ⑤ 手数料込みで「方向を当てず黒字化」した実証例は、成行(Taker)でレンジ端を叩く型ではなく、**指値(Maker)で流動性提供しリベート/VIP優遇を取りつつボラの差を抜くマーケットメイキング**。一般アカウントの Taker 手数料（0.04-0.05%）で方向を当てないスキャルを成行で行うと手数料負けでほぼ確実にマイナス収束。

- **★ledger 照合で判明した最重要事実（Gemini は知らない・このプロジェクト固有）**:
  - **taker_ls（成行の買い/売り比＝5m集計の需給指標）は E28 で"効くエッジ"として採用済み**（ledger L495-509）。単独では効かない（L495 全敗）が、**「行き過ぎ1%ile ∩ taker_ls≤下側分位」のフィルタとして使うと +1.27/件・レース率41%（無エッジ基準33%超）**・逆方向は劣化＝偶然でない（L496-497）。E28 は「下げ相場 LONG の存在証明」として採用（Phase2 連続モード score.py 採点で正・月$3.96）。
  - **別の需給指標（L-S比＝口座の買い/売り比）でも同じ機構が再現**（E29・行き過ぎ×ls_global低ゾーンで +1.4/件・全年プラス）＝「行き過ぎ × 需給の歪み → 反発」は偶然でなく再現するエッジ（ただし連続モード採点では小N で有意性が出ず＝E29 Phase2 は破棄・存在証明は E28 で済）。
  - ⚠️ **注意＝これは全部 LONG 側（下げ相場での投げ売り過熱→反発 LONG）の話**。「行き過ぎて投げ売られた所を買う」は需給の歪みが方向を示す。E37 は SHORT のみ（上げ過熱→反落）＝**同じ需給フィルタが SHORT 側でも対称に効くかは未検証**（taker_ls≥上側分位＝買い過熱でショート、が対称に効くか）。

- **★E37 の設計上の抜け（まこさんの読み「設計通りに実装していない/やり方が間違い」に照らした結論）**:
  - E37（v2〜v10）は**5m の静的テクニカル（RSI・ピボット・ゾーン・ボラ）だけで方向を当てようとし、このプロジェクトで既に効くと実証済みの需給フィルタ（taker_ls・L-S比）を入口に一切使っていない**。検出器・θ・ゾーン判定を延々いじったが、E28 で確定した「効く材料」を組み込んでいない＝**"効かない材料で方向を当てる"のを繰り返していた**。
  - Gemini の①⑤（方向は当てられない・成行スキャルは手数料負け）と、E28 の実測（需給フィルタで初めて方向エッジが立った）は同じことを別角度から言っている＝**E37 に足りないのは「反転確認の厳格化」でなく「需給フィルタ（行き過ぎ×成行/建玉の偏り）による入口の作り直し」**の可能性が高い。
  - ただし未検証の緊張点: E28 は LONG・低頻度（3.7年で希少）。E37 は SHORT・高頻度が役割。**需給フィルタを SHORT 側かつ高頻度で成立させられるか**が次の設計判断の核心（まこさんと議論）。

- **Gemini 提案の扱い（保留・鵜呑みにしない）**: Gemini の結びの提案「CVD（Cumulative Volume Delta）を 5m に組み込め」は方向として taker_ls（E28 で効いた成行フロー）と同族＝有望だが、Gemini は E28 の実測も E29 Phase2 の小N破棄も知らない。**"新しい提案"として飛びつかず、E28/E29 の既存実装（taker_ls・ls_global の取得・フィルタ）を土台に E37-SHORT へ転用する形で検討する**（今日の教訓＝蓄積を先に読む）。

## §6.8 レンジ戦略の候補手法 ＝ 過去に試したものとの対応表（2026-07-05 追記・"新提案"に飛びつく前の照合）

> 経緯: まこさんが過去に調べたレンジBOT設計の知見（グリッド設計3条件・ボラ調整逆張り・現物/先物乖離・ボリュームプロファイル・FR収斂の各案）＋本番再現性順位表を提供。**大半が既にこのプロジェクトで試されている**（E33/E34）ことが ledger 照合で判明＝"新しい提案"として実装に飛びつくと、E33/E34 と同じ壁を再演する。以下は「候補手法 × このプロジェクトの過去実測」の対応表（今日の教訓＝蓄積を先に読む の実践）。

### レンジBOTの候補手法カタログ（知識として保持・出典＝まこさん提供の調査＋Gemini）

- **グリッド設計の3絶対条件（先物で破産を避ける）**: ① 最下限にハードストップSL（レンジ下抜け・一方向下落で無限ナンピン→強制ロスカットを防ぐ・全ポジ一括投げ）② 値幅を固定でなく**ATR比例**（例 ATR×0.2でエントリー幅・×0.15で利確幅＝ボラに合わせ網の目を自動調整）③ **メタラベリングでトレンド時はBOT停止**（1hBB のバンドウォーク・OI急増＋価格move を検知→二次モデルが「今はレンジBOT動かすな＝ラベル0」で新規稼働シャットダウン）。
- **ボラ調整逆張り（BB±2.5〜3σ ∩ バンド非拡大 ∩ 出来高減）**: バンドが開いている（エクスパンション＝トレンド）時は100%拒否・横ばいの極値のみ・TP=20期間MA（中央）。1回ごとにリスク限定（リピートのように多重に捕まえない）。
- **現物 vs 先物 乖離（プレミアム/ディスカウント）逆張り**: 同取引所の現物と先物の一瞬のズレ（99%ile 超）を高い方売り・安い方買い→乖離0で両決済。価格の上下と無関係＝「開いた口が閉じる」だけ＝レンジで最も安全な部類。⚠️ ただしBitgetで現物+先物の同時執行インフラが要る（現行の先物単独 pipeline に無い）。
- **ボリュームプロファイル（価格帯別出来高）S/R**: POC（最も出来高が集中した価格＝居心地の中心）と出来高が薄いエリアの境界を割り出し、薄いエリア突入＝壁で跳ね返る想定で逆張り→POC回帰で利確。テクニカルよりダマシが少ない（クジラの実注文の厚みが根拠）。
- **ファンディングレート（FR）収斂スイング**: レンジ長期化で上限=ロング過熱でFR上昇・下限=ショート過熱でFR低下。FRが数日で最高→ショート/最低→ロング、FR中立回帰＋価格中央回帰で決済。保有中FRを貰える側に回るとなお強い。

### ★この対応表から言える最重要点（E37 の設計判断への含意）

1. **「相対分位∩taker投げ売り（順位表1位・最有力）」は E34 として既に試され、E37 と同じ「5m の方向エッジが立たない」壁で止まっている**（ledger L631・N11 方向ミス）。E37 に taker_ls を足すのは有望な方向だが、E34 の実測を見る限り「足せば直る」保証は無い＝E34 が −$65 で止まった理由（方向エッジ不在の残り 8.5pt）を先に理解して設計する必要がある。
2. **固定閾値σ（ボリンジャーバンド素の逆張り）は E33 で死亡確認済み**＝Gemini案①をそのまま実装しない。効くとしたら「バンド非拡大∩出来高減」の追加フィルタ部分（未検証）。
3. **方向を当てない筋（現物/先物乖離・FR収斂・ボラの平均回帰）は §6.6/§6.7 の学術知見（方向予測困難）と整合し、かつ未検証＝最も"新しい情報"がある領域**。ただし乖離裁定は現物+先物の同時執行インフラが現行 pipeline に無い（大きな着手）。
