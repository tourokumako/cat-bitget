## §1 regime 判定ゴール（合格基準）

| 項目 | 基準 |
|------|------|
| 出力粒度 | 1 時間程度（5 分足ボット運用要件・WORKFLOW §A） |
| 切替頻度 | 1 日複数回〜数日に 1 回 |
| 持続時間 | 2-3 時間以上（取引平均保有 60-130 分より長い） |
| 視認一致 | 1h chart 上の局面切替と判定切替が目視で揃う |
| 補助一致 | 1826 日肉眼ラベルとの日単位一致率 |

不採用基準:
- ❌ 月単位/週単位で固定される判定
- ❌ 5 分や 1 分で頻繁切替する判定
- ❌ 人間ラベルそのものを入力に使う仕組み（look-ahead）
- ❌ 「月単位人間判定との一致率」だけで採否判定

## §11 判断軸の詳細（5 分足本番運用での機能要件・WORKFLOW から移送）

### A. 判定の出力粒度（試行対象）

| 粒度 | 妥当性 |
|------|-------|
| 5分ごと | ❌ 数分の振動で判定がパチパチ変わり、取引が殺される |
| 15分〜30分ごと | △ 試行候補（細かすぎないか視認で判断）|
| **1時間ごと** | ○ 第 1 候補 |
| **2-4時間ごと** | ○ 試行候補（過剰切替を抑える方向）|
| 1日ごと | △ 1 日中ずっと同じ判定になり intra-day phase を取り逃す |
| ❌ 月単位・週単位 | 月内・週内の局面変化を捉えられず、5 分足運用に意味を与えない |

**根拠**: 2026-03-17〜23 の1週間 1h chart 観察で、人間 1d ラベル「DT 5日連続」の内訳が DT 16h / range 70h / 移行帯 数時間。1d ラベル額面通りに SHORT 5日稼働すると 70h 横ばいで踏まれる損失（L-139 の根拠でもある）。

### B. 判定の持続条件（パチパチ切替防止）

- 同じ判定が **2-3時間続いてから** 次の判定に切り替える（ヒステリシス）
- 取引平均保有時間 60-130 分より長い間隔が必要

### C. 採否判定の優先順位

#### プロトタイプ段階

| 順位 | 評価軸 | 内容 |
|-----|-------|------|
| 第1（本丸）| 視認一致 | 1h or 4h chart 上の局面切替と判定切替が目視で揃う |
| 第2 | サンプル一致率（4h単位）| `data/regime_samples_4h.csv` 731バーとの一致率 |
| 第3 | 切替頻度・持続 | 1日複数回〜数日に1回・持続 2-3h 以上 |
| 第4（不採用判定）| 月/週単位固定でないか | 5年で数回しか切替が出ないのは §A 不採用パターン |

> **1d 一致率は L-139 により補助指標**（粒度ミスマッチで天井 39%）。Priority 純利益による評価はプロトタイプ段階では使わない。

#### 確定後の本評価（regime 採用後）

| 順位 | 評価軸 |
|-----|-------|
| 第1 | Priority 純利益改善（regime ON vs OFF・365日 Replay）|
| 第2 | 切替頻度・持続が運用整合（avgHold 60-130 分と整合）|

### D. 入力指標の選び方

| 指標時間軸 | 扱い |
|-----------|-----|
| **1時間足 / 4時間足** | 主軸（推奨）|
| 日足 | 副軸（俯瞰）|
| 5分足 | 不適（Priority 発火層と同層・ノイジー）|
| 月足/週足 | 粗すぎ・候補外 |
| 月支配人間ラベル | 入力禁止（look-ahead 問題）|

### E. 不採用パターン（明示）

- ❌ 月単位/週単位で固定される判定
- ❌ 5分・1分で頻繁切替する判定
- ❌ 人間ラベルそのものを入力に使う仕組み（look-ahead）
- ❌ 「月単位人間判定との一致率」だけで採否判定（2026-04-28 までで3日間迷走）

### F. 利用可能なデータ

- `data/BTCUSDT-5m-2021-04-01_03-31_1826d.csv` — 5年 5m OHLCV
- `data/regime_samples_4h.csv` — 2025年 4h サンプルラベル（**93区間 / 731バー**・教師データ）
- `data/regime_samples_4h_2024.csv` — 2024年 4h ラベル（N=42自動ラベル 2196バー・「あってない」で要修正）
- `data/regime_samples_4h_2023.csv` — 2023年 4h ラベル（N=42自動ラベル 2190バー・「あってない」で要修正）
- `data/regime_samples_4h_2022.csv` — 2022年 4h ラベル（N=42自動ラベル 2190バー・「あってない」で要修正）
- `data/regime_ground_truth_daily_human.csv` — 1826日 1d 人間肉眼ラベル（補助・粒度ミスマッチで天井あり）
- `data/funding_rate_BTCUSDT_5y.csv` — Funding Rate（必要時のみ）

### G. 実証で得た観察結果（2026-04-28）

### 重要仮説（段階2 判定ロジック設計の出発点）

> 段階1-A サンプリング肉眼確認（2026-05-06）で観察された構造。
> 段階2 で判定ロジックを組み立てるときの**出発点として明示的に保管する**。

#### 構造: 「前レジームの継続条件薄れ + 次レジームの兆候なし」

切替点では「次のレジームの典型的な兆候はまだ出ていない・前のレジームの継続条件が薄れている」状態だけが観察される。具体的には:

- **dn→up 切替点 (n=63)**:
  - bullish_streak 1d = **0** (まだ陽線が立っていない)
  - close_above_cloud 1h = **0** (まだ雲上に出ていない)
  - つまり「up の確定条件はまだ出ていない」

- **up→rg 切替点 (n=19)**:
  - bearish_streak 1d = **0** (まだ陰線が立っていない)
  - close_below_cloud 1d = **0** (まだ雲下抜けなし)
  - つまり「rg/dn の確定条件もまだ出ていない」

#### 含意

1. 「up 確定の指標」を待つと判定が遅すぎる
2. 「up が終わっている / dn が終わっている」を別の指標で先に検出する設計が効く可能性
3. ただし「兆候なし」だけで判定すると false positive 多発
4. → **「前レジームの継続条件が薄れ」を検出するシグナル + 「次レジームの兆候はまだない」を確認するシグナル**の組み合わせで判定ロジックを構築する仮説
5. **窓なし指標（streak / pivot_position / close_to_low_pct 等）は、t=0 の値だけでなく、過去 N バーからのドリフト方向を組み合わせて判定する必要がある**。「切替前から同じ値だった」事例を除外する設計が必須。

#### 段階1-A 補足（観察詳細）

[`no_window_drift_audit.md`](../../results/regime_label_analysis/no_window_drift_audit.md) のドリフト検証:
- `pivot_position_100b 1h` (up→dn / up→rg): t=0 値 0.87/0.91 だが t-5 からのドリフトはわずか +0.08-0.10 → 「数日前から高値圏停滞」型が混在
- `streak 系 1d` (bullish/bearish): 中央値レベルでは t-5 から 0 のまま静的だが、Q1=-1 / Q3=0/1 で個別事例ではドリフトあり → 「ずっと 0 だった」事例と「切替点で初めて 0 になった」事例が混在
- `close_to_low_pct 1d (rg→dn)`: t-5: 2.09% → t=0: 0.835% で 1.5% 縮小 = 切替点に向けて 1d 安値接近する明確なドリフト（判定材料として強い）
- `close_to_low_pct 1d (dn→rg)`: 中央値は静的だが |Δ|=1.32 で振れ幅大・事例次第

→ 含意 5 の根拠データ。

#### 段階2 への持ち越し

段階2（判定ロジック設計）に入ったら、まずこの仮説を起点として:

- 「up 継続条件」を定式化する（高値更新・ema 上方・MACD 正値 等）
- それらが「薄れた」状態を定義する（値の単純な反転ではなく、明示的な「条件離脱」）
- 一方で「次レジームの兆候はまだ出ていない」という除外条件も設ける（dn 確定指標がまだ立たない）
- 窓なし指標を採用する場合は **過去 N バーからのドリフト方向**を必ず併用する
- **指標の判定力は prev_run（前レジーム長）で分けると変わる可能性** がある:
  - 例: dn→up `close_vs_keltner_upper_pct 4h` で a 型（dn 最終局面の売り叩き → 底打ち）と c 型（短期 dn からの早期反発）の混在を確認
  - prev_run 短命/通常別に再分析することで判定の安全性が上がる可能性 → 段階2 で再評価
- **段階1-A と段階1-B で対象時間軸が異なる**:
  - 段階1-A: 1h/4h/1d (3軸)
  - 段階1-B: 15m/30m/1h/4h/1d (5軸・30m と 15m はメタ分析で形状特徴量の判定力が高いと判明)
  - 段階2 で判定ロジックを設計するときは **両者の時間軸を統合する設計** が必要。例: 段階1-A の 1h 指標と段階1-B の 30m 形状を同時に見るなど

#### 注意

この仮説検証は段階2 で行う。段階1-A の段階では仮説として保管するのみ。
段階1-B（値動きの形）・段階1-C（構造）の結果を見たうえで、仮説を更新する可能性あり。

### 段階1 各サブの詳細

#### メタ分析（段階1-A 着手前に必ず実施・先行）

**目的**: N（過去バー数）・対象時間軸・対象指標の選定基準をデータから決める。

3つの処理:
1. **自己相関分析**: 各指標 × 各時間軸で lag 1〜24 の Pearson 自己相関 → 「自己相関 < 閾値を初めて切る lag」を推奨 N とする
2. **ラベル分離度**: 教師ラベル全 4,745 バー（4h）の up/rg/dn 別 Q1〜Q3 IQR の重複度
3. **パターン特異性**: 切替点 t=0 値で 6遷移パターン間の Q1〜Q3 重複度

各処理で **0.3 / 0.5 / 0.7** の3閾値感度分析を併記する（先験排除）。

#### 段階1-A. 指標値 + 過去 N バー推移

**目的**: 切替点 t=0 と過去 N バーの指標分布を**全指標で網羅的に**出す。

入力:
- 教師ラベル 4h（`data/regime_samples_4h_*.csv`）
- 切替点 198 件（直接遷移・blank/同ラベル復帰除外）
- メタ分析で決まった N（カテゴリ別）・対象軸

集計内容（per-event → cohort）:
- t0_value: 切替バー（=後 run 冒頭）の指標値
- pre_window_median: t-N 〜 t-1 の中央値
- pre_window_min / pre_window_max: 過去窓の極値
- pre_window_slope: (窓末 - 窓初) / N
- pre_window_monotonic: 過去 N バーの単調度（連続増/減バーの割合・0〜1）

各セルにメタスコア（ラベル分離度・パターン特異性）を併記し、両方 < 0.3 の指標を **★** で示す（採否判定は段階2 で行う）。

⚠️ **post（未来）は使わない**: t=0 値と pre 窓のみ。
⚠️ **絞り込みはしない**: 全指標で出す。★ は優先順位の参考。

スクリプト: [`scripts/regime/analyze_stage1a_main.py`](../../scripts/regime/analyze_stage1a_main.py)
