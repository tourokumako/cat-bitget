## §1 regime 判定ゴール（合格基準）

| 項目 | 基準 |
|------|------|
| 出力粒度 | 1 時間程度（5 分足ボット運用要件・WORKFLOW §A） |
| 切替頻度 | 1 日複数回〜数日に 1 回 |
| 持続時間 | 2-3 時間以上（取引平均保有 60-130 分より長い） |
| 視認一致 | 1h chart 上の局面切替と判定切替が目視で揃う |
| 補助一致 | 1826 日肉眼ラベルとの日単位一致率 |

不採用基準:
- ❌ 月単位/週単位で固定される判定
- ❌ 5 分や 1 分で頻繁切替する判定
- ❌ 人間ラベルそのものを入力に使う仕組み（look-ahead）
- ❌ 「月単位人間判定との一致率」だけで採否判定

## §11 判断軸の詳細（5 分足本番運用での機能要件・WORKFLOW から移送）

### A. 判定の出力粒度（試行対象）

| 粒度 | 妥当性 |
|------|-------|
| 5分ごと | ❌ 数分の振動で判定がパチパチ変わり、取引が殺される |
| 15分〜30分ごと | △ 試行候補（細かすぎないか視認で判断）|
| **1時間ごと** | ○ 第 1 候補 |
| **2-4時間ごと** | ○ 試行候補（過剰切替を抑える方向）|
| 1日ごと | △ 1 日中ずっと同じ判定になり intra-day phase を取り逃す |
| ❌ 月単位・週単位 | 月内・週内の局面変化を捉えられず、5 分足運用に意味を与えない |

**根拠**: 2026-03-17〜23 の1週間 1h chart 観察で、人間 1d ラベル「DT 5日連続」の内訳が DT 16h / range 70h / 移行帯 数時間。1d ラベル額面通りに SHORT 5日稼働すると 70h 横ばいで踏まれる損失（L-139 の根拠でもある）。

### B. 判定の持続条件（パチパチ切替防止）

- 同じ判定が **2-3時間続いてから** 次の判定に切り替える（ヒステリシス）
- 取引平均保有時間 60-130 分より長い間隔が必要

### C. 採否判定の優先順位

#### プロトタイプ段階

| 順位 | 評価軸 | 内容 |
|-----|-------|------|
| 第1（本丸）| 視認一致 | 1h or 4h chart 上の局面切替と判定切替が目視で揃う |
| 第2 | サンプル一致率（4h単位）| `data/regime_samples_4h.csv` 731バーとの一致率 |
| 第3 | 切替頻度・持続 | 1日複数回〜数日に1回・持続 2-3h 以上 |
| 第4（不採用判定）| 月/週単位固定でないか | 5年で数回しか切替が出ないのは §A 不採用パターン |

> **1d 一致率は L-139 により補助指標**（粒度ミスマッチで天井 39%）。Priority 純利益による評価はプロトタイプ段階では使わない。

#### 確定後の本評価（regime 採用後）

| 順位 | 評価軸 |
|-----|-------|
| 第1 | Priority 純利益改善（regime ON vs OFF・365日 Replay）|
| 第2 | 切替頻度・持続が運用整合（avgHold 60-130 分と整合）|

### D. 入力指標の選び方

| 指標時間軸 | 扱い |
|-----------|-----|
| **1時間足 / 4時間足** | 主軸（推奨）|
| 日足 | 副軸（俯瞰）|
| 5分足 | 不適（Priority 発火層と同層・ノイジー）|
| 月足/週足 | 粗すぎ・候補外 |
| 月支配人間ラベル | 入力禁止（look-ahead 問題）|

### E. 不採用パターン（明示）

- ❌ 月単位/週単位で固定される判定
- ❌ 5分・1分で頻繁切替する判定
- ❌ 人間ラベルそのものを入力に使う仕組み（look-ahead）
- ❌ 「月単位人間判定との一致率」だけで採否判定（2026-04-28 までで3日間迷走）

### F. 利用可能なデータ

- `data/BTCUSDT-5m-2021-04-01_03-31_1826d.csv` — 5年 5m OHLCV
- `data/regime_samples_4h.csv` — 2025年 4h サンプルラベル（**93区間 / 731バー**・教師データ）
- `data/regime_ground_truth_daily_human.csv` — 1826日 1d 人間肉眼ラベル（補助・粒度ミスマッチで天井あり）
- `data/funding_rate_BTCUSDT_5y.csv` — Funding Rate（必要時のみ）

### G. 実証で得た観察結果（2026-04-28）

- 1h chart で局面切替が肉眼で識別可能（持続 4-72h が自然な単位）
- 5m chart は数分単位の振動が常時あり regime には不適
- 4h chart も局面切替が見やすく 1h と並ぶ主軸候補

## §12 判定器逆算フェーズ手順（次セッション開始位置・WORKFLOW から移送）

階層型 v1〜v4 の試行で粒度ミスマッチ天井（L-139）が判明 → 「全期間網羅ラベル一致率最大化」を廃止し（L-140）、**まこさん入力の 4h サンプル教師データを使った機械的逆算（学習）** に移行。

### 入力データ

- **教師**: `data/regime_samples_4h.csv`（2025年・731バー / 93区間）
  - uptrend 36区間 (320バー / 53.3日)
  - range 22区間 (191バー / 31.8日)
  - downtrend 35区間 (220バー / 36.7日)
- **特徴量元 OHLCV**: `data/BTCUSDT-5m-2021-04-01_03-31_1826d.csv`（5m → 1h/4h/15m 等にリサンプル）

### 設計手順（Claude の責務）

1. **特徴量設計**
   - 4h バーの各時点で計算可能な指標を特徴量化（4h MA50傾き / 1h MA20傾き / 15m DI± / 4h ADX / etc.）
   - L-134 に従い**方向系のみで開始**（異種特徴混合の罠を避ける）
   - 入力時間軸は §11.D に従う（1h/4h主軸・5m不適）
   - 人間ラベル直接参照は禁止（look-ahead）
2. **学習方式の選定**（Claude が推奨を断言・GO 待ち）
   - A: 決定木（RandomForest / XGBoost）→ 解釈性
   - B: ルール探索（5要素グリッドサーチで4h一致率最大化）→ 階層型試作の延長
   - C: ロジスティック回帰（多クラス）→ 線形性確認
3. **評価基準**
   - 第1: 4h サンプル 731バー一致率
   - 第2: 視認チェック（必要なら追加 UI）
   - 第3: 切替頻度・持続（持続 2-3h 以上）
   - 第4: 極端偏り（5%未満 or 80%超）に該当しない
4. **過学習対策**
   - 2025年データで学習 → 2021〜2024年で out-of-sample 検証
