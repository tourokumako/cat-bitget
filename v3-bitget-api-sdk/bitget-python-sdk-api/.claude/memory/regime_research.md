## §1 最終目的

**5分足ボットの Priority 発火前に、複数指標 × 複数時間軸の同時成立条件でレジームを高精度判定する状態を作る。**

例:
- 以下が同時成立 → Uptrend と判定
  - 1時間足の 200EMA が UP
  - 4時間足の DI差 が天井
  - 30分足で + ピボット成立

最終目的の階層:
```
$60/day 達成
  ↑
Priority 個別最適化（regime × 方向で別ロジック）
  ↑
高精度レジーム判定 ← いまここ
  ↑
全指標 × 全6軸（5m/15m/30m/1h/4h/1d）の網羅 → 最適組み合わせ発見
```

## §2 3原則 + 8原則（絶対不変）

### 3原則

1. **現バーで取得可能な情報のみを判定材料にする** — post（未来）使用禁止
2. **切替点が本丸** — 期間内分布は補助 lens

4. 「定番だから」「楽だから」「過去使ってたから」を根拠にしない
5. 段階1 で絞り込みをしない
6. post（未来）を判定材料に使わない
7. **集計表示・報告書出力で best 1 自動採用しない**（2026-05-08 追加）

## §3 §13 v3 検証フロー（本体）

### 段階1: 素材調達（網羅・絞り込まない）

**役割**: 段階2 の組み合わせ最適化に渡す素材を、欠落なく揃える。

**段階1 の構造**:

```
Step1 メタ分析
  自己相関分析     → N候補を決める
  ラベル分離度     → 対象時間軸を決める
  パターン特異性   → 対象指標を決める
  感度パラメータ範囲を決める
  → メタ分析結果提示 → STOP

Step2 本実装
  Step1 で選定された範囲を全並列で網羅
  集計表示は以下の次元を保持:
    カテゴリ × 時間軸 × N窓 × 感度パラメータ × パターン
  → 結果提示 → STOP
```

**段階1 で絶対やってはいけない 7 項目**（集計・表示・報告書出力時）:

1. 時間軸の絞り込み
2. N 窓の絞り込み
3. 感度パラメータの絞り込み
4. カテゴリの絞り込み
5. パターン跨ぎの集約
6. 軸跨ぎ・カテゴリ跨ぎのランキングを採用候補絞り込みに使う
   （並列出力の補助としてのソート表示・TOP N 表示は許容）
7. best 1 自動採用

段階1 の出力は **「個別指標の判別力マップ」**。組み合わせの判別力は段階1 では出さない（段階2 の仕事）。

### 段階2: 組み合わせ最適化（絞り込み）

**役割**: 段階1 が並べた素材から、複数指標 × 複数時間軸の同時成立条件を設計する。

**段階2 でやること**:

1. 段階1 結果から候補指標を抽出
2. 候補指標の組み合わせの判別力を測る
   - 同時成立時のレジーム的中率
   - 誤判定率
   - パターン別（6遷移）の組み合わせ最適化
3. 5分足タイミングで複数軸を同時参照する設計
   - 5分足発火時に各時間軸の最新確定値を引いてくる
   - 同期参照の設計
4. 過学習回避（訓練/検証分離）
5. 最終的な判定ロジック書き下し
   - 例: rg→up 用 = 1h 200EMA UP AND 4h DI差天井 AND 30m + ピボット成立

**段階2 着手前に組み合わせ探索手順を素描する**:

- 全探索 / 貪欲法 / 専門家設計 のどれを使うか
- 評価指標の定義
- 訓練/検証分離の設計

### 段階3: 検証・実装・採否判定

3-1 検証 → 3-2 実装（VERSION 上げ・diff GO） → 3-3 テスト（複数月肉眼） → 3-4 採否判定 → 3-5 ドキュメント・Git

## §6 重要仮説（段階2 着手時の出発点）

> 段階1-A サンプリング肉眼確認（2026-05-06）で観察された構造。
> 段階2 で判定ロジックを組み立てるときの**出発点として明示的に保管**。

### 構造: 「前レジームの継続条件薄れ + 次レジームの兆候なし」

切替点では「次のレジームの典型的な兆候はまだ出ていない・前のレジームの継続条件が薄れている」状態だけが観察される。具体的には:

- **dn→up 切替点 (n=63)**:
  - bullish_streak 1d = 0（まだ陽線が立っていない）
  - close_above_cloud 1h = 0（まだ雲上に出ていない）
  - つまり「up の確定条件はまだ出ていない」

- **up→rg 切替点 (n=19)**:
  - bearish_streak 1d = 0（まだ陰線が立っていない）
  - close_below_cloud 1d = 0（まだ雲下抜けなし）
  - つまり「rg/dn の確定条件もまだ出ていない」

### 含意

1. 「up 確定の指標」を待つと判定が遅すぎる
2. 「up が終わっている / dn が終わっている」を別の指標で先に検出する設計が効く可能性
3. ただし「兆候なし」だけで判定すると false positive 多発
4. → **「前レジームの継続条件が薄れ」を検出するシグナル + 「次レジームの兆候はまだない」を確認するシグナル**の組み合わせで判定ロジックを構築する仮説
5. **窓なし指標（streak / pivot_position / close_to_low_pct 等）は、t=0 の値だけでなく、過去 N バーからのドリフト方向を組み合わせて判定する必要がある**。「切替前から同じ値だった」事例を除外する設計が必須。

### 注意

この仮説検証は段階2 で行う。段階1 では仮説として保管するのみ。

## §7 regime 判定ゴール（合格基準）

| 項目 | 基準 |
|---|---|
| 出力粒度 | 1 時間程度（5 分足ボット運用要件） |
| 切替頻度 | 1 日複数回〜数日に 1 回 |
| 持続時間 | 2-3 時間以上（取引平均保有 60-130 分より長い） |
| 視認一致 | 1h chart 上の局面切替と判定切替が目視で揃う |
| 補助一致 | 1826 日肉眼ラベルとの日単位一致率 |

不採用基準: 月/週単位固定 / 5m・1m 頻繁切替 / 人間ラベル直接入力 / 月単位一致率のみで採否判定

## §8 試行禁止リスト

- ❌ 月単位/週単位で固定される判定
- ❌ 5 分や 1 分で頻繁切替する判定（**ただし指標時間軸として 5m を使うことは可・段階1 で除外しない**）

- ❌ 過去却下方針への退路提案（L-127）
