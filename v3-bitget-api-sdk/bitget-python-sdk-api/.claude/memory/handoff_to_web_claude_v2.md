### 1.2 過去原因分析（0-α + 0-β）完了

旧 P1-P24 が月次 $370 で頭打ちした原因を分析:

| 観察 | 数値 |
|---|---|
| Entry 質 | random より p=0.0032 で有意に良い（OK）|
| 完璧 Exit (理論上限) | 月次平均 $5,276.93 / worst $40.41 |
| 方向偏り | SHORT $4,197 / LONG $308 |
| regime偏り | downtrend $4,558 / 他 全部マイナスor微益 |
| 時間帯偏り | 夜間+ / 日中- |
| worst month (2025-09) | trade 4個・全P4-LONG・全range |
| best month (2025-11) | trade 240個・SHORT 193・全downtrend |
| LONG 完璧 K=96 Exit | 月次平均$1,715 < $1,900 |

**結論**: 構造的限界ではなく「**Entry規則の網羅性不足 + LONG Entry質低**」。
- 現Priorityがカバーしてない領域: range / uptrend / 日中時間帯 / LONG
- LONG TIME_EXIT で取りこぼし大（100trade / -$1,972 / 取りこぼし$16.77）

### 1.3 過去の新Priority作成試行と教訓（v1 で未記載・重要）

**過去経緯**:
- 旧Priority（P1/P2/P4/P21/P23 等）はまこさんが Web 検索したロジックを組合わせて作成
- これだけでは目標未達のため、CC に新Priority 作成を複数回依頼:
  - **P24**: CC作成・勝率高いが発火月1回・売上微々
  - **P3**: P23 反転（SHORT→LONG）で作成・機能せずマイナス
  - **全Priority CC お任せ**: 現状より悪化
- まこさんの結論: **「すべてお任せ」はダメ・CC への期待過剰だった**

**教訓**:
- CC は新Priority を「作れる」が、**お任せだと質が悪い**
- 「CC に判断させない・絶対避ける」ではなく「**お任せじゃない依頼方法**」を探るのが本筋
- 苦肉の策として全パターン総当り案（k=2 全探索）を出した経緯がある
- 総当り案は「現状の理解力での最善案」であって、「総当りが正解」ではない

**「お任せじゃない依頼方法」の候補（新チャットでブレスト対象）**:
- 制約を厳しく与える（発火頻度・regime・LONG/SHORT・既存相関）
- 検証ループを厳しくする（事前定義の採否基準・複数評価）
- 中間検証（実装前に Web Claude or まこさんがレビュー）
- CC の発想範囲を限定（既存組合せのみ等）
- 機械的探索 + CC 解釈（探索は機械・解釈は CC）
- ML を CC が実装係として回す

### 1.4 ML の位置付け（修正版）

- ML は「お任せじゃない依頼」の1つの形として valid
- ML 学習スクリプトを CC が実装・実行
- 学習結果は機械が出す（CC が発想しない）
- ハイパラ・採否判定は人間（Web Claude or まこさん）が握る
- ただし **ML を絶対視しない**: 「お任せじゃない依頼方法」は他にも複数あり、ML はその1つ
- 前チャットで「ML 主軸」を一度決めたが、§1.3 の経緯把握後に再整理が必要

→ A-2 大枠の核は「**CC を実装係に閉じ込める**」ではなく「**お任せじゃない設計で CC を使う**」
