## Q1. 1つの建玉に、利確の指値と損切りの逆指値を同時に置けるか

**答え**
- **置けるとは書いてない。** 決済注文の数量は「発注可能な数量」までに限られる。そのため、建玉の全量に指値（利確）と逆指値（損切り）を両方置くことは、エラー ERR-200 で断られる、と読める（**推測**。「建玉ごとの発注可能数量から有効な決済注文の数量が引かれる」とは明記されていない。ただし建玉一覧に `orderdSize`（発注中数量）がある）。
- 取引所（レバレッジ取引）には IFD・OCO・IFD-OCO が無い。注文タイプは「成行、指値、逆指値」だけ。
- 公式の代わりの手段は **ロスカットレート** です。ただし動かせる範囲に限りがある。
  - 買建玉のロスカットレートを動かせるのは、**自動で決まる値より下（遠い方）だけ**です（「設定上限」が自動の値と同じだから）。
  - そのため、損切りを建値に近づける（浅い損切りを置く）用途には使えない。
  - 自動の値が建値の何%下になるかは「1取引単位あたりの必要証拠金」の読み方しだいです。**推測**では、「建玉レート × 50%」の 50% なので、建値から 25% 離れた所になる（Q6 を参照）。

**逐語**
- [取引所] 注文タイプ：「成行、指値、逆指値」
- [取引所] 執行数量条件：「成行：FAK（ロスカット注文の場合は「成行FAS」）／指値：FAS/FOK/FAK/SOK（Post-Onlyの場合）／逆指値：FAK」
- [FX] 「また複合注文は3種類（IFD、OCO、IFD-OCO）ご用意しており」（暗号資産FX の話）
- [API] ERR-200：「すでに有効注文があり、注文数量が発注可能な数量を超えている場合に返ってきます。決済注文を行いたい場合は、注文数量を変更するか、有効注文を 取消 したうえで、再度 注文 をしてください。」
- [API] 建玉一覧の応答：「orderdSize string 発注中数量」「losscutPrice string ロスカットレート」
- [取引所] ※7①：「ロスカットレートは下記の計算方法で自動的に設定されます。買建：ロスカットレート = 建玉レート − (1取引単位あたりの必要証拠金 × 50%)　売建：ロスカットレート = 建玉レート + (1取引単位あたりの必要証拠金 × 50%)　なお、ロスカットレートは下記の設定上限〜設定下限の範囲内で変更可能です。買建玉ロスカットレートの設定上限：建玉レート − (1取引単位あたりの必要証拠金 × 50%)　売建玉ロスカットレートの設定下限：建玉レート + (1取引単位あたりの必要証拠金 × 50%)」
- [取引所] 同：「買建玉のロスカットレートを引き下げる場合、(変更前ロスカットレート − 変更後ロスカットレート) × 建玉数量 × 200%　売建玉のロスカットレートを引き上げる場合、(変更後ロスカットレート − 変更前ロスカットレート) × 建玉数量 × 200%　の金額が証拠金として追加で拘束され、取引余力から控除されますので、ご注意ください。」
- [API] 注文：「losscutPrice string Optional レバレッジ取引で、executionTypeが LIMIT または STOP の場合のみ設定可能。」
- [API] ERR-5118：「リクエストボディにlosscutPriceを指定できない場合に返ってきます。」

**書いてないこと**
- 同じ建玉に、決済の指値と決済の逆指値を合わせて建玉数量を超えて置けるかどうか。
- 片方が約定したときに、もう片方が自動で取り消されるかどうか。（WebSocket の取消区分に `CLOSED_ORDER` があるが、説明は無い。）

## Q2. closeOrder・closeBulkOrder・changeLosscutPrice の決まり

**答え**
- **closeOrder**：建玉を `settlePosition.positionId` と `settlePosition.size` で**1つだけ**指定する。数量を建玉より小さくすれば一部の決済になる（**推測**。「部分決済」の語は無い。ただし size を指定する作りで、決済可能保有数量を超えると ERR-189 になる）。
  - 注文タイプは MARKET・LIMIT・STOP。`timeInForce` は FAK・FAS・FOK・SOK（SOK は LIMIT だけ）。
  - `losscutPrice` の引数は無い。
- **closeBulkOrder**：建玉を指定しない。`symbol`・`side`・`size` で、その向きの建玉をまとめて決済する。
  - どの建玉から決済するかの順は書いてない。
- **changeLosscutPrice**：引数は `positionId` と `losscutPrice` の2つだけ。範囲の決まりは Q1 の通り。
  - プレ・オープンの間も使える。
- 1回の数量の上限は、新規も決済も 5 BTC。ロスカットのときは除く。決済の1日の上限は無い。

**逐語**
- [API] closeOrder：「決済注文をします。対象: レバレッジ取引」「POST /private/v1/closeOrder」「settlePosition.positionId number Required 建玉は1つのみ指定可能。」「settlePosition.size string Required 建玉は1つのみ指定可能。」「cancelBefore … ※executionType: MARKET ,timeInforce: FAK の場合に true を指定可能です。 ※複数の建玉に紐づいた注文については指定いただけません。」
- [API] closeBulkOrder：「一括決済注文をします。対象: レバレッジ取引」「POST /private/v1/closeBulkOrder」の引数は「symbol / side / executionType / timeInForce / price / size / clientOrderId」
- [API] changeLosscutPrice：「建玉のロスカットレート変更をします。対象: レバレッジ取引」「POST /private/v1/changeLosscutPrice」「positionId number Required」「losscutPrice string Required」
- [API] 3つとも timeInForce：「FAK FAS FOK ((Post-onlyの場合は SOK ) LIMIT の場合のみ設定可能 ) ※指定がない場合は成行と逆指値はFAK、指値はFASで注文されます。」
- [API] エラー
  - 「ERR-70 決済注文において、指定された建玉の売買区分が誤っている場合に返ってきます。」
  - 「ERR-189 決済注文において、決済可能保有数量を超えての数量の注文の場合に返ってきます。」
  - 「ERR-254 指定された建玉が存在しない場合に返ってきます。」
  - 「ERR-422 一括決済注文において、建玉が存在しない場合に返ってきます。銘柄または売買区分が誤っていないか確認してください。」
  - 「ERR-423 一括決済注文において、注文数量が決済可能な建玉の合計数量を超えている場合に返ってきます。」
  - 「ERR-5126 1回あたりの最大注文数量を超えている場合または最小注文数量を下回っている場合に返ってきます。」
  - 「ERR-5203 取引所プレオープン中に注文および注文変更した場合に返ってきます。」
  - 「ERR-635 有効注文の件数が上限に達している場合に返ってきます。」
- [取引所] 「最小注文数量（最小注文単位）新規・決済ともに 0.001 BTC / 回」「最大注文数量 新規・決済ともに 5 BTC / 回（ロスカット時を除く）」「最大取引数量 新規 3,000 BTC / 日（決済注文の場合、上限はありません）」「保有建玉上限 買建玉・売建玉各50 BTC」
- [取引所] ※5：「有効注文の数量と保有建玉数量の合計として計算しています。両建てをしている場合、買建玉・売建玉の数量は相殺されません。」
- [取引所] ※1：「定期メンテナンス終了後10分間は「プレ・オープン」の状態となり、注文の取消 建玉のロスカットレート変更 以外の機能がご利用いただけません。」

**積み増しの扱い**
- 新規の約定ごとに建玉が分かれるかどうか（同じ向きの建玉がまとまるかどうか）は書いてない。
- 建玉一覧は `positionId` ごとに並び、`closeOrder` は「建玉は1つのみ指定可能」。このことから、建玉が複数に分かれうる作りと読める（**推測**）。
- 有効注文の件数の上限（ERR-635）の数字は書いてない。

## Q3. 逆指値（STOP）の約定の決まり

**答え**
- 逆指値の執行数量条件は FAK だけ（指定しなければ FAK）。逆指値の価格に届いたあと、どの種類の注文として出るか（成行か指値か）は**書いてない**。
- BTC_JPY は、取引手数料が新規も決済も無料。
- 滑りの上限の数字は無い。ただし Taker 注文には価格の制限がある。想定の約定レートが「当社が指定する間隔における約定価格の平均値 ± 20%」の外なら失効する。
- 逆指値は、すぐ約定する価格では出せない（ERR-5129）。
- 逆指値は、価格に届くまで `WAITING` の状態になる。
- ロスカットの注文は「成行FAS」。

**逐語**
- [取引所] 「逆指値：FAK」「成行：FAK（ロスカット注文の場合は「成行FAS」）」
- [取引所] 「取引手数料 無料（新規・決済）」
- [取引所] その他の注意事項①：「以下の条件を満たす注文はご発注いただけません。 注文レートが、「発注時点での現在値 ± 50%」の範囲外である　以下の条件を満たすTaker注文は失効となります。 想定される約定レートが、「当社が指定する間隔における約定価格の平均値 ± 20%」の範囲外である（範囲内で約定可能なご注文は約定されます。また、相場急変時はこの限りではありません。）」
- [API] 「ERR-5129 逆指値注文で、即座に約定される価格が指定されている場合に返ってきます。（逆指値注文では、即座に約定される価格での注文はできません）」
- [API] 注文情報通知：「注文ステータス: WAITING ORDERED CANCELED EXPIRED ※逆指値注文の場合は WAITING が有効」
- [API] timeInForce：「FAK 注文が一部約定後に未執行数量が残った場合、その残数量を失効とする条件」

**書いてないこと**
- 逆指値が発動したあとの執行方法（成行になるのか、指値になるのか）。
- 逆指値が FAK で一部だけ約定して残りが失効したときに、残った建玉をどう扱うか。

## Q4. SOK（Post-only）が取り消される条件・指値の有効期限

**答え**
- SOK は、指値で Maker にならないとき、**全数量が失効**する。取引所（レバレッジ）の全銘柄で使える。
- 失効すると取消区分 `EXPIRED_SOK` になる。
- WebSocket の注文通知には、`ORDERED` のときにだけ返る取消区分 `SOK_TAKER` と `PRICE_LIMIT` がある。どういう意味かの説明は無い。
- **指値の有効期限の決まりは書いてない。** 注文の引数に期限は無い。ただし FAS の指値は残数量が「有効」のまま残る。
- 次の場合は、新規の有効注文が取り消される。
  - 取引余力が0を下回ったとき
  - 追加証拠金が発生したとき

**逐語**
- [API] 「SOK 指値注文においてMakerにならない場合、その全数量を失効とする条件(Post-only)」
- [API] 「timeInForceパラメータにSOK(Post-only)が指定可能な銘柄 … 取引所レバレッジ 全銘柄指定可能」
- [API] 注文情報取得：「取消区分: USER POSITION_LOSSCUT INSUFFICIENT_BALANCE INSUFFICIENT_MARGIN ACCOUNT_LOSSCUT MARGIN_CALL MARGIN_CALL_LOSSCUT EXPIRED_FAK EXPIRED_FOK EXPIRED_SOK EXPIRED_SELFTRADE COLLATERAL_LIQUIDATION」
- [API] 注文情報通知：「取消区分: SOK_TAKER PRICE_LIMIT ※orderStatusが ORDERED の場合のみ返ってきます。」
- [API] 「FAS 注文が一部約定後に未執行数量が残った場合、その残数量を有効とする条件」
- [取引所] 「Post-Only」とは、Takerとなる注文は取消となり、Makerとなる注文のみ発注されます。」
- [取引所] その他の注意事項②：「取引所（レバレッジ取引）において、取引余力が0を下回った場合、取引所（レバレッジ取引）における有効注文（新規のみ）が取消となります。」
- [取引所] ※8：「追加証拠金が発生したと判定された時点で、発注中の新規注文（暗号資産FX、取引所レバレッジ）は取り消され」

**書いてないこと**
- 指値の有効期限（日数、メンテナンスのときに取り消されるかどうか）。
- `SOK_TAKER` と `PRICE_LIMIT` の意味。
- `EXPIRED_SELFTRADE`（自分の注文どうしが当たったとき）の細かい決まり。

## Q5. レバレッジ手数料とロスカット手数料

**答え**
- **レバレッジ手数料**：毎営業日（祝日も含む）の **日本時間 6:00** をまたいで建玉を持っていると掛かる。額は、その取引日の**終値**で出した評価額 × 0.04%。建玉ごとに掛かる。式は「評価レート × 建玉数量 × 0.04% / 日」。
  - 6:00 より前に決済すれば、その日の分は掛からないと読める（**推測**。「6:00時点の建玉保有状況を基準に判定」から読んだ）。
- **ロスカット手数料**：ロスカットの注文が発動したときに掛かる。額は「建玉レート × 建玉数量 × 0.5%」（1回ごと）。
  - 自分で出した逆指値の決済には掛からない（**推測**。条件が「ロスカット注文が発動された場合」だから）。
- 追加証拠金を期限までに解消できず強制決済されたときも、「建玉レート × 建玉数量 × 0.5%」が掛かる。

**逐語**
- [取引所] ※10①：「毎営業日（祝日を含む）日本時間朝6:00時点での建玉保有状況を基準に判定します。日本時間朝6:00をまたいで建玉を保有した場合、当取引日の終値から計算した評価金額に対し、建玉ごとに0.04% / 日の手数料が発生します。」
- [取引所] 「レバレッジ手数料：評価レート × 建玉数量 × 0.04% / 日　ロスカット手数料：建玉レート × 建玉数量 × 0.5% / 回　追加証拠金が解消されないことに伴う強制決済手数料：建玉レート × 建玉数量 × 0.5%」
- [取引所] ※10②：「ロスカット注文が発動された場合、対象建玉の「建玉レート × 建玉数量 × 0.5%」を手数料が発生します。」
- [手数料] ※2：「ロスカット注文が発動された場合、「建玉レート × 建玉数量 × 0.5%」の手数料が発生します。」
- [手数料] ※3：「毎営業日（祝日を含む）日本時間朝6:00時点の建玉保有状況を基準に判定します。日本時間朝6:00をまたいで建玉を保有した場合、当取引日の終値から計算した評価額に対し、建玉ごとに0.04% / 日の手数料が発生します。」
- [API] 目次に「取引所のレバレッジ手数料・取引手数料返金履歴の取得」がある（2026-08-29 追加）。

**書いてないこと**
- 「当取引日の終値」が、どの時点のどの値か（6:00 の直前の約定値か、など）。
- 土日に掛かるかどうか。「祝日を含む」とはあるが、土日は明記されていない。ただし追加証拠金の決まりには「土日祝日を含む」とある。

## Q6. 証拠金・ロスカットの計算、0.12 BTC に要る証拠金

**答え**
- 必要証拠金は、建玉ごとに「建玉数量 × 建玉レート（約定時の価格）× 50%」。
- 拘束証拠金は、未約定の新規注文の分も足したもの。
- 証拠金維持率は「（口座残高 ＋ 取引所の建玉評価損益 ＋ 暗号資産FX の建玉評価損益）÷ 取引所の必要証拠金」。
- ロスカットは、次の**2本立て**です。
  1. **建玉ごと**：現在値が、その建玉のロスカットレートに届いたら発動する。
  2. **口座全体**：証拠金維持率が **30%** を下回ったら発動する（アラートは 50%）。
- **75% は取引所（レバレッジ）の値ではない**（暗号資産FX の値）。
- 追加証拠金は、毎日 6:30 の時点で維持率が 100% を下回っていると発生する。期限は、その営業日の 3:00 まで（判定の 20時間30分後）。

**合計 0.12 BTC に要る証拠金の式**

```
必要証拠金 = Σ（各建玉の数量 × 各建玉の約定価格）× 0.5
```

- 例：0.12 BTC を、すべて 12,115,000 円（2026-11-03 3:28 UTC の last）で建てた場合
  0.12 × 12,115,000 × 0.5 = **726,900 円**
- 両建ての場合：買と売は相殺されない（保有上限の計算でそう書いてある）。必要証拠金の式は「建玉数量 × 建玉レート × 50%」の建玉ごとの式なので、買と売の両方の分が積み上がると読める（**推測**。FX の頁のような「大きい方」という書き方は、取引所の頁には無い）。

**ロスカットレートの値（推測を含む）**
- 「1取引単位あたりの必要証拠金」を「建玉レート × 50%」と読むと、次のようになる。
  - 買建：ロスカットレート = 建玉レート × 0.75
  - 売建：ロスカットレート = 建玉レート × 1.25
- つまり、建値から ±25% 離れた所になる。「1取引単位」が 1 BTC か 0.001 BTC かで数字は変わらない（どちらでも1単位あたりの比率は同じ）。ただし、この読み方は計算例の記事（サポート）で確かめていない。

**逐語**
- [取引所] 「必要証拠金 建玉金額の50%に相当する額」
- [取引所] ※3：「必要証拠金 建玉数量 × 建玉レート (約定時価格) × 50%」「拘束証拠金 ① + ②　① : 取引所（レバレッジ取引）における拘束証拠金　買建 : (建玉数量 × 建玉レート + 新規注文数量 × 買い価格) × 50%　売建 : (建玉数量 × 建玉レート + 新規注文数量 × 売り価格) × 50%　※成行買の場合、「買い価格」の代わりに「最良売気配値 × 1.1」、成行売の場合、「売り価格」の代わりに「最良買気配値」を用います。」
- [取引所] 「証拠金維持率 （口座残高 + 取引所（レバレッジ取引）の建玉評価損益 + 暗号資産FXの建玉評価損益）/ 取引所レバレッジ必要証拠金　必要証拠金は、取引所（レバレッジ取引）の建玉のみを用いて計算します。」

- [取引所] ※7：「取引所（レバレッジ取引）では、建玉ごとにロスカットレートが設定される建玉単位のロスカット（①②）と、証拠金維持率に基づきロスカットが発動する口座単位のロスカット（③）を併用しています。」

## Q7. メンテナンス

**答え**
- **定期メンテナンスの曜日と時間は、読めた頁には書いてない。**
- 書いてあることは次の通り。
  - メンテナンス中は取引できない。
  - 定期メンテナンスの後 10 分間は「プレ・オープン」になる。その間は、注文の取消とロスカットレートの変更しかできない。
  - プレ・オープンの間に相場が大きく動くと、取引の再開のときにロスカットされることがある。
  - API は、メンテナンス中は ERR-5201（定期）か ERR-5202（緊急）を返す。プレ・オープン中の注文は ERR-5203。
  - `/public/v1/status` で `MAINTENANCE / PREOPEN / OPEN` が分かる（2026-11-03 3:25 UTC は `OPEN`）。
- メンテナンス中に、有効な注文や建玉がどうなるか（取り消されるか、残るか）は**書いてない**。

**逐語**
- [取引所] ※1：「メンテナンス中はお取引いただけません。また、定期メンテナンス終了後10分間は「プレ・オープン」の状態となり、注文の取消 建玉のロスカットレート変更 以外の機能がご利用いただけません。（定期メンテナンスの時間は変更になることがあります）プレ・オープン中に相場が急変した場合、取引再開時に建玉がロスカットされる可能性があります。事前に口座残高に余裕を持っていただいたうえでロスカットレートを変更していただくなど、建玉の管理には十分ご注意ください。」
- [取引所] 「取引時間 24時間 365日（メンテナンス時を除く）」
- [API] 「ERR-5201 定期メンテナンス時にPublic/Private APIを呼び出した場合に返ってきます。」「ERR-5202 緊急メンテナンス時にPublic/Private APIを呼び出した場合に返ってきます。」「ERR-5203 取引所プレオープン中に注文および注文変更した場合に返ってきます。」

## Q8. デモ・試しの環境、API のレート制限

**答え**
- **API のデモや試しの環境（テストネット）は、API の文書に書いてない。** API の接続先は本番の4つだけ。
- デモとして書いてあるのは、画面の道具「WebTrader」のデモ画面だけ（口座が無くても使える）。
- Private API の上限は、先週の取引高で決まる。
  - Tier1：GET・POST とも 1秒に20回
  - Tier2：先週の取引高が10億円以上20億円未満で、1秒に30回
  - Tier3：先週の取引高が20億円以上で、1秒に50回（2026-10-03 から）

- **Public API（REST）の回数の上限は書いてない。**

## Q9. 過去の約定データと KLine の取得

**答え**

  - 5分足は **20210415 から**取れる。実際に試すと、20210415 は 288 本（最初の足は 2021-04-14T21:00Z ＝ 日本時間 4/15 6:00）。20210414 は ERR-5207。
  - BTC_JPY の日足は 2018 年から取れる。最初の足は 2018-09-04T21:00Z（日本時間 2018-09-05 6:00）。2017 年は ERR-5207。

**逐語**
