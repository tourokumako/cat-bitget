# improvement_ideation_kb.md — 改善案・アイデアの発想法カタログ

作成: 2026-06-27（まこさん指示）。
位置付け: **「次の一手をどう発想するか」の引き出し集**。`trade_analysis_methods_kb.md`（結果データをどう読むか＝分析手法）とは別物＝こちらは「分析の後、改善案・アイデアをどう生み出すか」の思考法を並べる。
書くもの／書かないもの（cat_requirements §8.2 文書マップ準拠）: 書く＝発想法（複数の型・状況での選び方）。書かない＝実験結果（→ ledger）・設計の決定（→ strat_v9ml_design / acceptance）・分析手法（→ trade_analysis_methods_kb）。

---

## ⚠️ 大前提（これを外すと逆効果・まこさん 2026-06-27）

- **本書は強制でない＝引き出し（カタログ）**。hook で「この型でアイデアを出せ」と物理強制しない。**型を1本に固定するとアイデア出しがそのルートだけになり、思考の広がりが死ぬ**（まこさん指摘）。
- **唯一の正解ルートはない**。状況に応じて型を選ぶ・複数を併用する・**ここに無い新しい発想を妨げない**（むしろ歓迎し、効いたら追記する）。
- 本書の役割は「視野が狭くなった・消去法に陥った時に開いて、別の切り口を思い出す」こと。

## 型A：発散 → 過去の"勝ち"と接続 → 戦略整合 → 実装して両窓（2026-06-27 scene-size で実証）

**いつ使うと効くか**: 手元データの制約から「あれもダメ・これもダメ」と消去法（引き算）に陥っている時。視野が狭い時。

**手順**:
1. **発散**: 目標（この戦略で大きく稼ぐとは何か）から逆算し、業界の手法を**複数の異なる切り口で出典つきに机へ並べる**（WebSearch・KB）。いきなり手元データで収束しない。消去法でなく選択肢を広げる。
2. **過去の"勝ち"と接続**: 並べた候補のうち、**cat-bitget で過去に採用された勝ちレバー（ledger）と同型のもの**を優先候補にする＝「なぜこれが効くはず」の根拠になる。発散だけでは「どれを選ぶか」は決まらない。過去の成功との接続が選択を支える。
3. **戦略整合（⑩）**: その戦術が対象戦略の役割（局面・デイトレ/スキャル/トレンド型）に合うか（§1.2.1）。ミスマッチを外す。
4. **実装して両窓 score.py**: probe（近似）で割れても諦めず実装し、学習窓＋採点窓の両方で base 超えを確かめる（採否は probe/AUC でなく実エンジン両窓）。

**実証（2026-06-27）**: E36 改善で add の消去法に陥っていた → 発散4切り口（O-U閾値/ボラ連動サイジング/レジーム重み/動的グリッド）→ 「ボラ連動サイジング」が過去採用 E13（予測強度別サイジング）と同型と接続 → デイトレ型に整合（⑩）→ 実装し両窓改善（採点窓 $549→$1043・学習窓 $1275→$2079）で採用。**6連敗（損を削る系）を破った**。

**限界**: 発散は必要条件だが十分でない。「並べた中でどれが本当に良いか」の質判断は機械化できない＝最後は非同型レビュー or まこさんの目（cc_role §2.9）。

## 型B 以降（今後 効いた発想法を追記する場所）

> 1つの型に固定しないため、別の発想で改善できたら型として書き足す。候補の切り口（まだ実証前・参考）:
> - **逆算型**: 目標 net から必要件数×期待値を割り、どのレバーで埋めるかを設計から決める。
> - **制約破り型**: 「当然」と思っている前提（全玉同サイズ・反対端まで取る 等）を1つ疑う。
> - **第一原理型**: 取引所の仕組み（merge・部分決済・maker/taker）から、何が物理的に可能かを積み上げる。
> - **業界横展開型**: 他資産・他戦略で確立した手法を cat-bitget の制約に翻訳する。

（効いた型は、型A と同じ「いつ効くか／手順／実証 ledger E番号／限界」の形で追記。効かなかった型も "この状況では効かない" と残すと次に役立つ。）
