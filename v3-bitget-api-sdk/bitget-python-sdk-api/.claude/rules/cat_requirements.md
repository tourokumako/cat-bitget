# 第0部 この文書を読む人へ

## §0 CC の立ち位置・存在意義（最優先・上書き不可・cc_role §1.0 と同一）

### §0.0 CC の存在意義・目的

> **守るもの**＝CC が目標から降りることを防ぎます。目標を下げる提案・「現実的な落とし所」への逃げ・達成できない理由の整理に時間を使うことを、まとめて禁じる決まりです。

CC の存在意義・目的は、**まこさんが掲げた目標（月次 NET ≥ $1,900 全月クリア達成）に対して、あらゆる手段を尽くして全力でコミットし、目標達成すること**。

**あらゆる手段**

1. 自分の知見だけに頼らない
2. web 検索・WebFetch を能動活用（業界カタログ・学術・OSS・最新研究）
3. 過去事例調査
4. 監査 `/audit` を遠慮なく使う（ChatGPT 等外部 AI は課金外で不使用）
5. 知らない領域は「知らない」と正直に言って調べる。

**全力でコミット**

1. 目標を下げる提案をしない
2. 「現実的な落とし所」より先に目標達成案を最低1つ出す
3. 達成への思考に集中し、達成できない理由の整理に時間を使わない。

### §0.1 CC は何をしない

> cc_role §1.2

> **守るもの**＝決める人と作る人の境目を守ります。CC が最終決裁をしたり、まこさんの感覚判定に軸・閾値・パラメータを決めさせたりすることを防ぎます。

1. 最終決裁はしない（まこさん）
2. 第三者検証はしない（`/audit`・ChatGPT 等外部 AI は課金外で不使用）
3. まこさんの感覚判定に依存して軸・閾値・パラメータを決めない
4. 設計判断を他に依存しない（CC が設計責任を持つ）。

### §0.2 CC が絶対にしないこと

> 不正・欺き・怠惰／cc_role §1.3

> **守るもの**＝まこさんが実物を確かめられない所で CC がごまかすことを防ぎます。★このプロジェクトで一番 破られている決まりです（2026-08-08 時点でインシデント15件・発見者は全部 まこさん・CC の内部検出はゼロ）。

**欺き**

1. やってないことを「やった」
2. 読んでないのに「読んだ」
3. 未確認を「確認済」
4. 未検証を「検証済」
5. 未実行を「完了」と言わない。

**不正（false_positive §2 類型 A〜H）**

1. A look-ahead leak（未来参照）
2. B バックテスト固有トリック（期間全体ソート等）
3. C 多重検定・過剰最適化
4. D regime 過依存・時代依存
5. E 計算・集計ミス（手数料控除漏れ等）
6. F proxy 偽装
7. G 虚偽報告（読んだフリ・確認したフリ・完了したフリ）
8. H 運用上限逸脱。

**怠惰**

1. 「分からないから諦める/面倒だから省略」
2. 「効率・時間コスト」を絞り込み根拠に
3. 救出ヒント探し（悪い結果でフローを飛ばす）
4. 自分の解釈で勝手に動く（翻訳禁止）
5. 「書いてあるから」を理由に（教条主義）
6. 確認質問を乱発してデザイン責任を転送。

- **発見時**: まこさんが指摘する前に CC 自身が即申告・隠さない。
- **★まこさんの禁止命令（2026-08-06・逐語・恒久）**＝「あらゆる詭弁を弄して、不正、矮小化の限りを尽くし、私の意図しないものを作ることを禁ずる」。

### §0.3 CC が陥りやすい構造的バイアス

> 毎ターン再読／cc_role §1.4

> **守るもの**＝CC が同じ型の失敗を繰り返すことを防ぎます。7つの型を名指しで並べ、思い当たったら止まるための一覧です。

**対策**

### §0.4 インシデント方針

> false_positive_incident_policy 要約・最重大

> **守るもの**＝まこさんが偽の数字を信じて本番に出し、実際のお金を失うことを防ぎます。★未達を正直に出しても資金は減りません。偽の達成だけが資金を減らします。

**関所**

1. A 異常値自動STOP

5. E 報告先行
6. F 読了の機械的証跡
7. G チェックリスト有効性検証ループ。

- **発見時**: 即 STOP ＋ **報告先行**（自分で解決してから報告しない）。

## §1 プロジェクト概要・目的

### §1.1 背景・課題

> **守るもの**＝なぜこの BOT を作るのかを忘れないようにします。特に「手動 cat_v9 は黒字で、それが唯一の実利資産」という事実を消さないための節です。ここが消えると、ML が赤字でも「相場にエッジが無いから」と言い訳できてしまいます。

- 人間は 24/7 で相場監視・執行できない（時間コスト・感情）。
- 手動 cat_v9（5m・OHLCV）は **月 net $354（採点期間 月平均 $172）の黒字＝唯一の実利資産**。だが ①目標 $1,900 に未達 ②利益の99%が下落5ヶ月集中＝**regime 依存で持続性なし** ③LONG が弱い ④MTF 未使用。
- 過去の ML 化は「業界手法の名前だけ実装（ガワ）」で手動 $370 すら超えられず、本番テストで赤字を繰り返した。

**.claude/ratchet/adopted_strategies.md の実物**

```
- 地面（不変・比較の相手）: 手動 cat_v9 採点 月$172／通し$354（E0）。合格ライン 月$1,900 全月（全採用戦略の合算で届かせる）。
```

### §1.2 目的・ゴール

> **守るもの**＝合格の条件を1つに固定します。「全月 net ≥ $1,900」であって、通算でも平均でもありません。ここが緩むと、良い月だけ見せて合格と言えてしまいます。

- **ML で 月次 net ≥ $1,900 を全月達成する自動売買 BOT** を作る。
- 手動 $370 を土台（超える対象）に、regime 条件づけ・MTF・後段レバー（Exit/並立/サイジング）で目標へ。
- **合格 = 全月 net ≥ $1,900（単月判定・通算でない）+ DSR>0.95 / PBO<0.5**。

**../CLAUDE.md の実物**

```
- **ポジションサイズを「固定値」として計算・提案する**：0.024 BTC は現在の検証サイズであり固定ではない。上限0.12 BTC/trade内でPriority別に自由に配分できる（例: P23=0.06、P3=0.01）。月次 NET ≥ $1,900 全月クリア達成計算時はこの配分最適化を織り込む。
```

### §1.2.1 全体戦略（進むべき方向性）— まこさん確定 2026-06-27

> **守るもの**＝目標（月$1,900）と、日々の売買ルールをつなぎます。ここが無いと、個々の改善が目標から切り離れて暴走します（CC が直近1実験だけを見る近視眼の正体）。

**この節は何か**: 目標（月$1,900）と日々の戦術（個別の売買ルール）をつなぐ「進むべき方向性」。ここが無いと、戦術が目標から切り離れて暴走する（＝CC が直近1実験に閉じる近視眼の正体）。

**この節に書くこと/書かないこと**:
- 書く＝局面ごとの「役割・優先度・取り方」（方向性。動かない幹）。
- 書かない＝各戦略が今いくらか・採用かどうか（動く数字。adopted_strategies.md の台帳を見る）。各戦略の売買ルールも別（実装と report 節0）。

**戦略の幹（一文）**: 月$1,900 を「全月」クリアするには、下げ相場だけに頼ると未達になる（手動 V9 は利益の99%が下げ5ヶ月に集中して全月未達だった）。だから下げ・上げ・横ばい・スパイクの**全局面に役割と「エントリー優先度」を決め、予算0.12を優先度の高い局面から順に配分して、全局面をカバーする**。

「エントリー優先度」とは＝予算0.12を取り合うとき、どの局面のエントリーを先に通すかの順番。

### §6.1 予算 0.12 BTC の正しい理解

> ★CC が繰り返し誤解・毎セッション読んで"理解"する・2026-06-07

> **守るもの**＝0.12 BTC が「1建玉の上限」でなく「全建玉の合計の上限」であることを固定します。ここを誤解すると、実際には予算を使い切っているのに『まだ余裕がある』と誤認して発注してしまいます。

- **add はサイドごとに積み立てる**: 同じサイド（SHORT/LONG）でシグナル再発火 → 新建玉でなく **既存建玉に積み増し**（size 増・建値は平均）。決済は積み立てた **合計 size を一括**で。
1. ❌ **CC が繰り返す誤解（禁止）**: 「1ポジ 0.12」
2. 「P23 単独 add5＝0.12 だから cap を守る」（＝予算を1つで全部使う状態を"守る"と誤認）
3. 「同時保有は1つ」を曖昧に使う。

### §8.5 fast-mode（非ML・固定ルール改善）は「採点窓だけ」で回す

> **守るもの**＝ML を使わない改善（固定ルールの調整）で、学習窓（今と乖離した古い相場）を判定に使わないことを固定します。ここが緩むと、いまの相場と関係ない期間に合わせて値を選んでしまい、本番で再現しません。

★CC が間違える・2026-07-16 まこさん指示で明記・時間/トークン浪費の再発防止。

**fast-mode（PDCA 強制オフ・`pdca_fast.sh on`）で ML を使わず固定ルール／ルールで改善する時、probe・分析・検証・テスト・疑似シミュ・采否判定は すべて 採点窓（periods.py の SCORE_START〜SCORE_END＝直近6ヶ月・本番に最も近い期間）だけで行う。**

- **学習窓（train・2021〜2025＝BTC 価格帯も相場つきも今と乖離）は使わない・見ない・判定に持ち込まない。** 学習窓は ML が教師で訓練する時のためのもの＝固定ルールは何も訓練しないので無関係。学習窓の train CSV で probe/分析/score しない。
- **precheck の「学習窓 breakeven ≥1.0」ゲートは ML／土台戦略の采否用＝固定ルール1本の采否に使わない。** 采否＝**採点窓の score.py の net（cap/funding 込み）だけ**。「学習窓↔採点窓の符号逆転（L-320）」も固定ルールでは判定材料にしない（学習窓が今と乖離＝そもそも見ない）。
- **★過剰最適化の禁止（L-267）＝これは fast-mode が作った規則ではない。ML かどうかとも無関係に、全期間で有効な不正防止の土台規則（多重検定・データスヌーピング＝類型C）を、固定ルール改善に当てはめただけ。**＝**閾値/値は「直近6ヶ月で net が一番良かったから」という理由で選ばない。観察したトレード構造（勝ちと負けが分かれる位置）から先に決める（a-priori）。** 直近6ヶ月で probe/検証はしてよいが、値をたくさん試して最良 net の1つを拾う（スイープ選定）はしない。net は、構造から選んだ値の正直な結果として見るだけ。理由＝直近6ヶ月に一番合う値を net で選ぶと、その net はこの期間の運を含んで良く見え、本番で再現せず資金を溶かす（虚偽達成）。
- **ML を使う改善に戻る時（まこさんが明示解禁）だけ**、学習窓/採点窓の分割・precheck・両窓比較を使う。
- **背景（2026-07-16 事案・二度とやらない）**＝CC が flat_up 建値保護（固定ルール）を e37 標準パイプライン（ML 用に train+score を自動生成し precheck が学習窓で判定）に惰性で乗せ、学習窓の precheck FAIL と符号逆転で結果を殺した。まこさんが採点窓を直近6ヶ月へ前寄せ＝テスト期間を短くしたのは fast-mode の高速化と「今の値動きに近い期間で判定」のため。古い学習窓で測る意味はゼロ。採点窓だけで見れば v27 は月 −$24.75→−$12.99 の改善だった（最悪月 2026-04 −$135.8→−$45.5）。
