## レビュー視点(6つ)

### 視点1: まこさんの本来の主張を1行で書き出す

Claude Code の応答をレビューする時、最初にやること:

1. まこさんの直前の主張を1行で書き出す
2. Claude Code の応答がその主張と整合してるか確認する
3. ズレてたら個別 Q に答える前に枠組み修正を提案する

**事例(2026-05-06)**:
- まこさんの「切り替わるときの動きを見たほうがいい」を、Claude Code が「§13 と別タスク」に追い出そうとした
- 検出: 主張を狭めて受け取った
- 修正: 「§13 の本流に組み込むべき」と再指示した

### 視点2: 目的から逆算する

最終目的: $60/day 達成
中間目的: 5分足ボットでレジーム別 Priority の正確な Entry 判定が出る

今やってる分析・実装がこれにどう寄与するか毎回問う。技術論点で目的が見えなくなった時は目的逆算で判断する。

**事例(2026-05-06)**:
- 私(チャット側 Claude)が「スタート前期間 24-48h を分析」と提案
- まこさんが「ボット運用で 24h前情報は使えない」と指摘
- 検出: 目的を見失って机上設計してた
- 修正: 「現バー時点で取得可能な情報のみ」原則を §13 v3 で明示(凍結中)

### 視点3: データ駆動 vs 暫定値の区別

Claude Code が提案するパラメータ・閾値・対象範囲(N・時間軸・指標カテゴリ等)について:

- 「データ駆動か暫定値か」を毎回確認
- 「暫定で○○」「経験的に」「定番だから」が出たら退行として扱う
- 段階1-A で確立した「メタ分析→本分析」のデータ駆動手順を後段でも維持

**事例(2026-05-06)**:
- 段階1-B で Claude Code が「N=20, N=50 暫定採用」を提案
- 検出: 段階1-A のデータ駆動原則からの退行
- 修正: 「形状特徴量の自己相関メタ分析を先行」を再指示

**事例(2026-05-12)**:
- Claude Code が段階 A-1 設計案で「実行時間: 数時間〜半日想定」と推定
- 私(チャット側 Claude)が「checkpoint は実測前は不要」と判断
- 根拠: L-156(直感で決めない・データ駆動)。推定値で先回り実装しない

### 視点4: 統計的妥当性の落とし穴を警戒する

- 中央値だけで「典型像」と判断しない
- 個別事例一致率を併記する
- 性質の違うものを合算しない(短命/通常の混在等)
- サンプルバイアスを毎回確認

**事例(2026-05-06)**:
- Claude Code が中央値ベースで「典型像」を提示
- 後検証で個別事例一致率は最高 65%・典型形成立率 70% 以上はゼロ
- 修正: 段階1-B 設計時に「個別事例一致率併記」「短命/通常別集計併記」を追加

### 視点5: 暗黙の選択肢狭窄を検出する

Claude Code が時間軸・指標カテゴリ・サブセット分け・閾値などで勝手に絞ってないか確認:

- ドキュメント明記事項(priority_rebuild.md §2 等)との齟齬がないか
- 段階1-A の選定が無批判に段階1-B に引き継がれてないか

**事例(2026-05-06)**:
- 段階1-B で Claude Code が「1h/4h」と書いた
- 検出: §11.A で「15-30 分も試行候補」と明記されてるのに勝手に除外
- 修正: 「5m/15m/30m/1h/4h/1d の 6 軸でメタ分析先行」を指示

**事例(2026-05-12)**:
- 段階 A-1 設計案で Claude Code が fold 分割方式の選択肢として
  「rolling forward(1 fold しか作れない) vs k-fold shift(時系列無視)」
  の 2 択を提示
- 検出: expanding window 方式と「分割しない単純 split」が選択肢から漏れていた
- 修正: チャット側 Claude が expanding window を追加提示・最終的に
  まこさんの指摘で「BTC の 4 年周期・2024 構造変化を踏まえると
  分割しない単純 split が最適」に確定

### 視点6: 方針転換時、何が変わって何が変わってないかを切り分ける

方針転換ドキュメントを読むとき、機械的に「全部変わった」と読まない:

- 何が **廃止** されたか
- 何が **継続** しているか(基本前提)
- 何が **新規** 追加されたか

を 3 列で書き出してから議論に入る。

**事例(2026-05-12)**:
- まこさんの「Entry ロジックをレジームごとに作りたい」発言に対し、
  チャット側 Claude が「レジーム判定レイヤーが必要 = regime 研究の復活 =
  大方針転換と矛盾」と方針論争に膨らませた
- 2 回まこさんから「なに言ってんの」「話にならん」と指摘された
- 検出: レジーム別 Priority 構造(旧 P2/P4/P21-P24 の基本前提・継続)を
  「regime 研究の復活」と誤認した
- 修正: priority_rebuild.md §1「Priority 群(複数並立でリスク分散)」が
  継続前提であることを再確認・「変わったのはレジーム判定の作り方だけ」と
  整理し直した

**起動条件**: 「方針転換」「凍結」「廃止」のキーワードがドキュメントに
あるとき・新フェーズの設計議論に入るとき。

## 過去セッションの主要発見(継承事項)

### 🧊 凍結中・参照のみ(regime 研究時代の発見)

以下は regime 研究時代(〜2026-05-11 凍結)の発見。新規調査・新規試作は禁止。
Priority 再構築フェーズで「regime label が必要」と判定された場合のみ再参照する。

#### 重要仮説: 「前レジーム継続条件薄れ + 次レジーム兆候なし」

切替点では「次のレジームの典型的な兆候はまだ出ていない・前のレジームの継続条件が薄れている」だけが観察される構造。詳細は regime_research.md §13 重要仮説セクション(凍結中)。

#### 窓なし指標のドリフト制約

streak / pivot_position / close_to_low_pct 等は t=0 値だけでなく過去 N バーからのドリフト方向を組み合わせて判定する必要がある。詳細は no_window_drift_audit.md(凍結中)。

#### prev_run 依存性

dn→up close_vs_keltner_upper_pct 4h で「a 型(暴落底打ち) + c 型(短期反発)」が混在。prev_run 長で短命/通常を分けて再分析すれば判定の安全性が上がる可能性(凍結中)。

### 現フェーズ(Priority 再構築)の発見

#### BTC 4 年周期・2024 構造変化(2026-05-12)

BTC は半減期サイクル(約 4 年)で値動きの性格が大きく変わる。さらに 2024 年 ETF 承認・半減期で構造変化があった。fold 分割や train/test 期間設計時は機械的な統計手法を当てはめず、相場特性を踏まえて決める。

| 期間 | 局面 |
|---|---|
| 2021 | 前サイクル天井 |
| 2022 | ベア相場 |
| 2023 | 底〜回復初期 |
| 2024 | ETF 承認・半減期(構造変化) |
| 2025 | サイクル中盤 |

→ train=2021-2024 / test=2025 / 分割なし が最適(全レジーム含有)。

#### レジーム別 Priority と k=2 探索の関係(2026-05-12)

k=2 探索(102 万組)で発見される上位組合せは、結果として特定レジームでだけ発火する性質を持つ。例:

- adx14 > 30 AND di_plus > di_minus → UPTREND 専用
- adx14 > 30 AND di_minus > di_plus → DOWNTREND 専用
- adx14 < 20 AND bb_width < 閾値 → RANGE 専用

組合せ条件 = Entry 条件 = レジームフィルター。1 セットで 3 役。これにより「レジーム判定独立レイヤー」を経由せずにレジーム別 Priority が構築できる。

## 補足: なぜこのファイルが必要か

Web 版 Claude のセッションは独立してる。各セッションの Claude は別個体で、前セッションでの議論の流れや暗黙の判断基準を引き継げない。

userMemories(対話ルール)は引き継げるが、抽象的なルールだけだと具体的判断に落とし込みにくい。

このファイルは「**過去事例 + 視点 + 起動条件**」をセットで残すことで、新セッションの Claude が同じ視点で動ける可能性を高める。

ただし完全な再現は無理:

- 視点を文章化しても状況依存の判断は引き継げない
- 新セッションの Claude が必ずガイド通り動く保証はない
- まこさんが「視点が浅い」と感じたら都度指摘する運用は依然必要
